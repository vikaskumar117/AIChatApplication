APPLY THE IDEA

Worked example

An identity service applies short account-aware throttles, network reputation signals, MFA for risky sign-ins, and monitored recovery instead of exposing whether an email address exists.

  1. Detect repeated or anomalous sign-in attempts
  2. Apply layered throttling and risk checks
  3. Require stronger proof when risk is elevated
  4. Alert and protect account recovery

CODE OR QUERY

Try it

services.Configure<IdentityOptions>(options =>
{
    options.Lockout.MaxFailedAccessAttempts = 5;
    options.Lockout.DefaultLockoutTimeSpan = TimeSpan.FromMinutes(5);
    options.Lockout.AllowedForNewUsers = true;
});

// Also configure gateway limits, MFA/risk controls, and safe recovery.
// Avoid exposing account existence in login or reset responses.

TRADE-OFFS

Benefits and limitations

Benefits

  • Layered friction reduces automated account takeover
  • Risk-based responses can be less disruptive to legitimate users

Limitations

  • Strict thresholds can lock out real users or be abused for denial of service
  • Detection and recovery require careful privacy and support operations

DECISION GUIDE

When to use it

Use: Protect login, MFA, and recovery endpoints with adaptive controls and monitor attack patterns across accounts and networks.

Avoid: Avoid relying only on CAPTCHA, IP blocks, a single hard lockout threshold, or password complexity rules.

COMMON MISTAKES

Watch out

  • Using only IP throttling against distributed traffic.
  • Permanently locking accounts after a small number of failures.
  • Leaking account existence through different login and reset responses.

BEST PRACTICES

In practice

  • Use MFA/passkeys, breached-password checks, adaptive throttling, and secure password hashing.
  • Apply controls to login, MFA verification, registration, and recovery.
  • Alert on distributed failure patterns and provide a safe account recovery path.

INTERVIEW PRACTICE

Common questions

  1. How does credential stuffing differ from brute force?
  2. Why can account lockout become a denial-of-service vector?
  3. Which controls should protect password reset as well as login?

SENIOR-LEVEL SCENARIO

Production thinking

A credential-stuffing wave causes many failed logins and support calls. Add adaptive rate limits and MFA challenges, use generic user-facing errors, monitor distributed patterns, protect recovery endpoints, and communicate account remediation without disclosing sensitive details.

SUMMARY

In one minute

Credential stuffing reuses leaked username/password pairs, while brute-force attacks repeatedly guess credentials; layered controls limit account takeover and abuse.
