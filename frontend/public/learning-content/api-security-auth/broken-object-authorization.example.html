APPLY THE IDEA

Worked example

A customer can read only orders in their own tenant, even if they guess or receive another order ID.

  1. Authenticate caller
  2. Resolve resource within authorized scope
  3. Authorize operation
  4. Return only permitted data

CODE OR QUERY

Try it

var tenantId = currentUser.GetRequiredTenantId();
var order = await db.Orders
    .SingleOrDefaultAsync(
        x => x.Id == orderId && x.TenantId == tenantId,
        cancellationToken);

if (order is null)
    return NotFound();

TRADE-OFFS

Benefits and limitations

Benefits

  • Enforces least privilege at the resource boundary
  • Tenant-scoped queries reduce accidental data exposure

Limitations

  • Rules must be consistently applied across every access path
  • Incorrect tenant or ownership claims can still invalidate the boundary

DECISION GUIDE

When to use it

Use: Authorize every object access using server-trusted identity and ownership data, including nested and asynchronous operations.

Avoid: Avoid relying on opaque IDs, UI filtering, route-level authentication, or client-supplied tenant IDs as authorization.

COMMON MISTAKES

Watch out

  • Checking only that a user has the Customer role.
  • Trusting tenantId in the request body or query string.
  • Protecting GET while leaving update, delete, export, or background paths unscoped.

BEST PRACTICES

In practice

  • Centralize resource access policies and scope data queries.
  • Use negative authorization tests with two distinct tenants.
  • Audit logs should identify actor and resource without recording sensitive payloads.

INTERVIEW PRACTICE

Common questions

  1. Why is authentication insufficient to prevent BOLA?
  2. Where should tenant scoping be enforced?
  3. How do you test cross-tenant access?

SENIOR-LEVEL SCENARIO

Production thinking

A penetration test discovers that changing an order ID returns another tenant’s record. Add tenant-scoped repository queries, audit all read/write/export paths, invalidate exposed credentials if needed, and add cross-tenant regression tests.

SUMMARY

In one minute

BOLA occurs when an API checks who the caller is but fails to check whether they may access the specific record they requested.
