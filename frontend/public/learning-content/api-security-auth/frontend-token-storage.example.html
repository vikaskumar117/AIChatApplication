APPLY THE IDEA

Worked example

A BFF stores OAuth tokens server-side and returns an HttpOnly Secure session cookie; unsafe browser requests also carry a validated antiforgery token.

  1. Choose browser credential architecture
  2. Protect token from script or ambient abuse
  3. Attach credential to intended requests

CODE OR QUERY

Try it

// Cookie-based BFF session: tune for deployment and browser requirements.
options.Cookie.HttpOnly = true;
options.Cookie.SecurePolicy = CookieSecurePolicy.Always;
options.Cookie.SameSite = SameSiteMode.Lax;
// Add antiforgery protection to state-changing requests.

TRADE-OFFS

Benefits and limitations

Benefits

  • HttpOnly/BFF designs keep long-lived provider tokens out of JavaScript
  • In-memory access tokens reduce persistent exposure compared with localStorage

Limitations

  • Cookie sessions create CSRF considerations
  • BFF adds server state, proxying, and operational complexity

DECISION GUIDE

When to use it

Use: Choose storage based on the client architecture, threat model, and provider guidance; for sensitive browser apps strongly consider a BFF.

Avoid: Avoid putting refresh tokens or privileged credentials in localStorage, URLs, source bundles, or telemetry.

COMMON MISTAKES

Watch out

  • Calling localStorage secure because it is not a cookie.
  • Assuming HttpOnly prevents CSRF or prevents malicious same-origin actions.

BEST PRACTICES

In practice

  • Use short-lived, least-privilege tokens and avoid persistent browser secrets.
  • Apply CSP, safe rendering, cookie flags, antiforgery validation, and session revocation.

INTERVIEW PRACTICE

Common questions

  1. Why does HttpOnly reduce but not eliminate browser risk?
  2. How does a cookie-based design affect CSRF?
  3. What does a BFF change about token exposure?

SENIOR-LEVEL SCENARIO

Production thinking

A security review finds long-lived refresh tokens in localStorage; revoke active tokens, migrate to a BFF or supported safer browser pattern, add XSS and CSRF controls, and plan session reauthentication.

SUMMARY

In one minute

Browser token storage is a threat-model trade-off: script-readable storage exposes tokens to XSS, while cookie-based sessions require CSRF protections.
