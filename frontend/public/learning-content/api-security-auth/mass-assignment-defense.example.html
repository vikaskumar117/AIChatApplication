APPLY THE IDEA

Worked example

A profile update accepts display name and phone number but never accepts IsAdmin, TenantId, or approval status.

  1. Receive a narrow request DTO
  2. Validate allowed fields
  3. Authorize the requested change
  4. Map explicitly to domain state

CODE OR QUERY

Try it

public sealed record UpdateProfileRequest(
    string DisplayName,
    string? PhoneNumber);

var profile = await profiles.GetForUserAsync(userId, cancellationToken);
if (profile is null) return NotFound();

TRADE-OFFS

Benefits and limitations

Benefits

  • Makes the writable API surface explicit
  • Prevents new internal entity properties from being implicitly exposed

Limitations

  • Requires deliberate mapping and DTO maintenance
  • A DTO does not replace authorization or domain validation

DECISION GUIDE

When to use it

Use: Create separate input contracts for create, update, and privileged operations; map only authorized fields.

Avoid: Avoid binding HTTP request bodies directly to EF entities or using broad reflection-based property copying for sensitive updates.

COMMON MISTAKES

Watch out

  • Using one entity as both persistence model and public API contract.
  • Copying every matching property from request to entity.
  • Assuming client-side forms prevent crafted requests.

BEST PRACTICES

In practice

  • Use separate DTOs and commands for privileged state changes.
  • Reject or ignore unexpected fields consistently and test the behavior.
  • Add domain and database constraints for critical invariants.

INTERVIEW PRACTICE

Common questions

  1. Why is an EF entity a risky request model?
  2. How does a DTO reduce over-posting?
  3. What other checks are still required after using a DTO?

SENIOR-LEVEL SCENARIO

Production thinking

A user can change an approval flag through an update endpoint. Remove entity binding, constrain the request DTO, add an authorized approval command, review audit logs, and test that privileged fields in extra JSON properties are ignored or rejected.

SUMMARY

In one minute

Mass assignment occurs when an API binds untrusted request fields directly to a domain or persistence object, allowing callers to set fields they should not control.
