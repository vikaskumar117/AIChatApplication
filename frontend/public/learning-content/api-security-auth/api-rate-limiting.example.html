APPLY THE IDEA

Worked example

Partition expensive search requests by authenticated customer and also apply a global concurrency cap on the database-intensive operation.

  1. Identify caller and operation cost
  2. Apply partitioned limit or queue policy
  3. Allow request or reject with 429

CODE OR QUERY

Try it

builder.Services.AddRateLimiter(options =>
{
    options.AddTokenBucketLimiter("search", limiter =>
    {
        limiter.TokenLimit = 30;
        limiter.TokensPerPeriod = 10;
        limiter.ReplenishmentPeriod = TimeSpan.FromMinutes(1);
        limiter.QueueLimit = 0;
    });
});
app.UseRateLimiter();

TRADE-OFFS

Benefits and limitations

Benefits

  • Protects capacity from bursts and noisy clients
  • Can enforce fairness and service tiers

Limitations

  • Poor limits reject legitimate bursts or enable identity evasion
  • Per-instance memory limits are not automatically globally coordinated

DECISION GUIDE

When to use it

Use: Limit expensive and abuse-prone operations with identity-aware partitions, global capacity bounds, and observable policy.

Avoid: Avoid relying exclusively on source IP, which may be shared or rotated, or treating rate limiting as permission control.

COMMON MISTAKES

Watch out

  • Trusting a client-supplied identity header for rate-limit partitioning.
  • Assuming fixed per-instance thresholds create a global quota.

BEST PRACTICES

In practice

  • Set explicit burst, queue, fairness, and retry behavior.
  • Load-test limits and monitor false positives and downstream health.

INTERVIEW PRACTICE

Common questions

  1. How do fixed-window and token-bucket limits differ?
  2. Why may an in-memory limiter be insufficient across replicas?
  3. What response should a limit rejection use?

SENIOR-LEVEL SCENARIO

Production thinking

A public search API is distributed across ten replicas and IP-based limits are bypassed; add gateway/global protection and authenticated customer partitions, then measure legitimate rejection rates.

SUMMARY

In one minute

Rate limiting bounds request consumption to protect service capacity and fairness, but it does not replace authorization or broader abuse defenses.
