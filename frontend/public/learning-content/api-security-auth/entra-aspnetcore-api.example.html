APPLY THE IDEA

Worked example

A controller requires the Orders.Read scope and then verifies that the current organization may access the specific order.

  1. Client requests token for API resource
  2. API validates token and creates principal
  3. Policy and resource checks authorize request

CODE OR QUERY

Try it

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = $"https://login.microsoftonline.com/{tenantId}/v2.0";
        options.Audience = "api://orders-api";
    });
builder.Services.AddAuthorization(options =>
    options.AddPolicy("Orders.Read", p => p.RequireClaim("scp", "Orders.Read")));
app.UseAuthentication();
app.UseAuthorization();

TRADE-OFFS

Benefits and limitations

Benefits

  • Standard issuer metadata and key rollover
  • Centralized user and workload identity with API permission models

Limitations

  • Claim names and issuer behavior vary by token version and flow
  • Misconfigured tenant or audience can either block legitimate callers or trust the wrong tokens

DECISION GUIDE

When to use it

Use: Use a supported Microsoft identity integration package or carefully configured bearer middleware with explicit tenant and audience policy.

Avoid: Avoid writing custom JWT parsing or accepting any tenant/token based only on a valid signature.

COMMON MISTAKES

Watch out

  • Validating only the signature and accepting a token for another API.
  • Assuming a scope claim and an app-role claim are interchangeable.

BEST PRACTICES

In practice

  • Use platform libraries, explicit audience and tenant constraints, and authorization policies.
  • Test anonymous, wrong-audience, wrong-tenant, insufficient-scope, app-only, and user-delegated cases.

INTERVIEW PRACTICE

Common questions

  1. What does the API audience identify?
  2. How do delegated scopes differ from application roles?
  3. Why is UseAuthentication ordered before UseAuthorization?

SENIOR-LEVEL SCENARIO

Production thinking

A service token has an app role but no delegated scope; design separate policies for delegated user calls and application-only calls, then test both principal types and tenant boundaries.

SUMMARY

In one minute

An ASP.NET Core API integrates with Entra as a resource server: validate bearer access tokens for the API, then apply application authorization.
