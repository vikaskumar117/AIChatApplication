APPLY THE IDEA

Worked example

A report API accepts a partner ID and resolves it to a preconfigured partner endpoint instead of accepting an arbitrary fetch URL.

  1. Caller supplies or influences destination
  2. Server validates destination and request purpose
  3. Egress policy restricts reachable networks
  4. Bound response and record safe telemetry

CODE OR QUERY

Try it

// Map an approved business key to configuration; do not fetch a caller URL.
if (!partnerEndpoints.TryGetValue(partnerId, out Uri? endpoint))
    return BadRequest("Unknown partner.");

using var request = new HttpRequestMessage(HttpMethod.Get, endpoint);
using var response = await httpClient.SendAsync(
    request, HttpCompletionOption.ResponseHeadersRead, cancellationToken);
response.EnsureSuccessStatusCode();

TRADE-OFFS

Benefits and limitations

Benefits

  • Fixed destinations sharply reduce the reachable attack surface
  • Network egress restrictions add defense if application validation fails

Limitations

  • Legitimate dynamic-fetch use cases need careful destination governance
  • DNS, redirect, proxy, and IPv6 behavior require operational testing

DECISION GUIDE

When to use it

Use: Use fixed integrations where possible; otherwise combine strict allowlisting with network-level egress enforcement and bounded requests.

Avoid: Avoid accepting arbitrary URLs for server-side fetching or assuming a hostname string check is sufficient.

COMMON MISTAKES

Watch out

  • Blocking only a few literal IP strings.
  • Following redirects without revalidating the destination.
  • Returning raw internal response bodies or forwarding caller credentials.

BEST PRACTICES

In practice

  • Use dedicated outbound clients with short timeouts and response-size limits.
  • Disable redirects or validate every redirect target and resolved address.
  • Restrict workload egress and test DNS, IPv4/IPv6, proxies, and metadata protections.

INTERVIEW PRACTICE

Common questions

  1. Why can a backend reach destinations unavailable to a browser?
  2. How can redirects undermine a host allowlist?
  3. Why are egress controls important in addition to URL validation?

SENIOR-LEVEL SCENARIO

Production thinking

A document-preview service fetches arbitrary URLs. Disable arbitrary fetching, rotate any credentials that may have been exposed, review egress logs, replace URLs with approved document IDs, and restrict outbound access at the network layer.

SUMMARY

In one minute

SSRF abuses a server feature that fetches a caller-influenced destination, potentially crossing network trust boundaries.
