APPLY THE IDEA

Worked example

The Orders API rejects an otherwise well-signed token whose aud is the Billing API and returns 401 rather than trusting its decoded orders.read claim.

  1. Receive bearer access token
  2. Validate trust, signature, audience, and time
  3. Authorize permission and target resource

CODE OR QUERY

Try it

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.Authority = configuration["Identity:Authority"];
        options.Audience = "api://orders";
        options.TokenValidationParameters.ValidateIssuer = true;
        options.TokenValidationParameters.ValidateAudience = true;
        options.TokenValidationParameters.ValidateLifetime = true;
    });
app.UseAuthentication();
app.UseAuthorization();

TRADE-OFFS

Benefits and limitations

Benefits

  • Signature-validated claims can be checked locally at scale
  • Standard authority metadata supports interoperable key rollover

Limitations

  • Revocation before expiry may require provider checks or application state
  • Configuration errors can accept wrong issuers or reject valid key rotations

DECISION GUIDE

When to use it

Use: Use maintained bearer authentication middleware and configure exact issuer, API audience, lifetime, and authorization requirements.

Avoid: Never trust a decoded token, accept arbitrary algorithms/issuers, log bearer credentials, or send an ID token as an API access token.

COMMON MISTAKES

Watch out

  • Base64URL-decoding a payload and treating its claims as trusted.
  • Checking signature but omitting audience or issuer validation.

BEST PRACTICES

In practice

  • Use provider discovery/JWKS and tested key rollover rather than hard-coded static assumptions.
  • Test wrong issuer, wrong audience, expired tokens, key rotation, insufficient scope, and resource ownership.

INTERVIEW PRACTICE

Common questions

  1. What does a JWT signature prove and not prove?
  2. Why validate audience as well as issuer?
  3. What is the difference between 401 and 403 after token processing?

SENIOR-LEVEL SCENARIO

Production thinking

A signing key rotates and some API instances reject new tokens; use trusted metadata and overlapping key rollover, test old and new key windows, and keep issuer/audience restrictions intact.

SUMMARY

In one minute

An API must validate a bearer access token’s cryptographic and protocol constraints before it trusts claims or authorizes a request.
