APPLY THE IDEA

Worked example

ASP.NET Core Identity manages salted password hashes and format/version metadata, allowing work-factor upgrades without storing recoverable passwords.

  1. Registration receives password securely
  2. Password hasher salts and derives verifier
  3. Login recomputes and compares safely

CODE OR QUERY

Try it

// Prefer ASP.NET Core Identity's IPasswordHasher<TUser>.
var hash = passwordHasher.HashPassword(user, password);
var result = passwordHasher.VerifyHashedPassword(user, hash, suppliedPassword);
// Never store password or a fast unsalted SHA-256 digest.

TRADE-OFFS

Benefits and limitations

Benefits

  • Limits damage from database disclosure
  • Parameterized work factors support migration over time

Limitations

  • Expensive verification consumes CPU and needs abuse controls
  • Legacy hashes require careful migration and reset policy

DECISION GUIDE

When to use it

Use: Use a maintained identity framework and an approved adaptive password-hashing algorithm with current parameters.

Avoid: Never store plaintext, reversible-encrypted passwords, or fast general hashes such as bare SHA-256.

COMMON MISTAKES

Watch out

  • Using a fast hash or reversible encryption for password storage.
  • Logging passwords or sending them to analytics/error telemetry.

BEST PRACTICES

In practice

  • Delegate hashing and verification to ASP.NET Core Identity or a vetted library.
  • Add login throttling, MFA options, breach response, and secure secret handling.

INTERVIEW PRACTICE

Common questions

  1. Why must each password have a unique salt?
  2. Why are password hashes deliberately slow?
  3. How should an application upgrade hashing parameters?

SENIOR-LEVEL SCENARIO

Production thinking

A credential database is exfiltrated; preserve forensic evidence, force risk-based resets, invalidate sessions, assess hash parameters, and upgrade the verifier strategy without exposing passwords to operators.

SUMMARY

In one minute

Passwords should be stored as salted, deliberately expensive one-way password hashes, never as plaintext or reversibly encrypted values.
