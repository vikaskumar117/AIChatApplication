APPLY THE IDEA

Worked example

An order API has an availability SLO and a defined recovery point. Application Insights traces a request through the API and database, alerts on error-budget burn, while scheduled restore exercises verify backups and Azure Cost Management highlights cost per successful order.

  1. Set user-facing latency/availability objectives and RPO/RTO.
  2. Instrument APIs and dependencies with correlated telemetry.
  3. Alert on SLO burn, queue age, dependency saturation, and backup failures.
  4. Run restore/failover exercises and compare actual recovery to objectives.
  5. Review cost per successful workload and adjust bounded scaling.

CODE OR QUERY

Try it

// Example Kusto query: failed requests by operation over the last hour
requests
| where timestamp > ago(1h)
| summarize total=count(),
            failures=countif(success == false)
  by operation_Name
| extend failureRate = todouble(failures) / total
| order by failureRate desc

TRADE-OFFS

Benefits and limitations

Benefits

  • Correlated telemetry shortens detection and diagnosis
  • Explicit RPO/RTO and budgets make trade-offs measurable

Limitations

  • Telemetry retention, replicas, backups, and cross-region traffic cost money
  • Alerts without ownership or tested runbooks create noise rather than resilience

DECISION GUIDE

When to use it

Use: Use SLO-driven monitoring, owned alerts, tested recovery, and cost guardrails for production workloads.

Avoid: Avoid equating a green health probe with end-to-end availability or assuming backups are recoverable without restore tests.

COMMON MISTAKES

Watch out

  • Alerting on every metric threshold without user-impact context or ownership.
  • Assuming multi-region deployment automatically provides safe failover.
  • Scaling without maximums, budget alerts, or downstream capacity checks.

BEST PRACTICES

In practice

  • Correlate traces, metrics, and structured logs with safe redaction.
  • Attach runbooks and owners to actionable alerts; review noisy alerts.
  • Test restore/failover regularly and track cost per meaningful business transaction.

SENIOR-LEVEL SCENARIO

Production thinking

A regional outage causes the application to fail over, but stale data and unexpectedly high egress costs follow. Revisit consistency and RPO, test failback, alert on replication lag and spend, and document who owns recovery decisions.

SUMMARY

In one minute

Measure user outcomes, exercise recovery, and include cost guardrails so Azure reliability claims are operationally verifiable.
