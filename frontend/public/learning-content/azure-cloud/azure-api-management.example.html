APPLY THE IDEA

Worked example

APIM validates caller tokens, applies a per-product quota, and routes requests to an internal Orders API. The Orders API independently verifies order ownership and tenant boundaries.

  1. Publish an API version with a clear contract and product.
  2. Apply token validation and route-level rate limits at APIM.
  3. Keep the backend private where appropriate and authenticate gateway-to-backend traffic.
  4. Enforce tenant and resource permissions in the backend; correlate gateway and service telemetry.

CODE OR QUERY

Try it

<!-- Illustrative APIM policy fragment; configure values and scope per environment. -->
<inbound>
  <base />
  <rate-limit-by-key calls="60" renewal-period="60"
      counter-key="@(context.Subscription?.Id ?? context.Request.IpAddress)" />
  <set-header name="X-Request-Id" exists-action="override">
    <value>@(context.RequestId.ToString())</value>
  </set-header>
</inbound>

TRADE-OFFS

Benefits and limitations

Benefits

  • Consistent gateway policies and API publication controls
  • Can protect or hide backend endpoints behind a managed boundary

Limitations

  • Gateway policies and tier/network features have limits and cost
  • Misconfigured transformations can create divergent API behavior or false authorization confidence

DECISION GUIDE

When to use it

Use: Use APIM for governed external APIs, shared gateway policies, consumer onboarding, and controlled routing.

Avoid: Avoid putting all domain authorization in gateway policies or assuming an API key alone proves end-user identity.

COMMON MISTAKES

Watch out

  • Assuming a subscription key is user authentication.
  • Removing backend authorization after moving checks to a gateway.
  • Ignoring policy inheritance, rate-limit scope, private DNS, and backend connectivity.

BEST PRACTICES

In practice

  • Use OAuth/OIDC tokens for user or service identity and keep backend authorization authoritative.
  • Version contracts deliberately and test policies at each scope.
  • Monitor rejected requests, throttles, latency, backend errors, and gateway capacity.

INTERVIEW PRACTICE

Common questions

  1. What belongs at a gateway versus in the backend?
  2. Why does APIM not replace object-level authorization?
  3. How do quota/rate policies differ from backend capacity protection?
  4. What must be considered when APIM reaches a private backend?

SENIOR-LEVEL SCENARIO

Production thinking

A new gateway policy accidentally trusts a client-supplied tenant header. Remove that trust, derive identity from validated credentials, keep object authorization in the backend, test policy inheritance, and verify private backend reachability and quota behavior.

SUMMARY

In one minute

APIM centralizes API-edge governance; preserve independent backend authorization and validate the full network and policy path.
