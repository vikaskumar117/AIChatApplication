THE IDEA

What is it?

Entity Framework Core (EF Core) is a .NET object-relational mapper (ORM): it maps .NET entity types and LINQ queries to relational schema and SQL through a database provider. DbContext is a unit-of-work and identity map that coordinates querying, change tracking, and saving.

WHY IT MATTERS

What problem does it solve?

EF Core reduces repetitive data-access code while preserving access to relational capabilities, but the abstraction does not remove SQL, transaction, schema, or provider behavior.

UNDER THE HOOD

How does it work?

Model entities and relationships, configure mappings and constraints, compose LINQ expressions, inspect translated SQL, and call SaveChangesAsync to persist tracked changes. Use migrations or a separately managed schema workflow and keep DbContext scoped to a unit of work.

KEY TAKEAWAYS

Remember

  • DbContext is a short-lived unit of work and identity map.
  • LINQ query translation is provider- and version-dependent.
  • EF Core does not eliminate SQL, database constraints, or transaction semantics.
  • Review generated SQL and measure critical paths.
