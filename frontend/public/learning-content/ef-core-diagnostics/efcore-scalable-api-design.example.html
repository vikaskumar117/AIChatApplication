APPLY THE IDEA

Worked example

A catalog endpoint caps page size, uses keyset pagination, projects DTOs, and returns a continuation token instead of loading the whole table.

  1. Set request, pagination, payload, and dependency budgets.
  2. Design query projection and stable keyset or bounded offset paging.
  3. Use async cancellation, short transaction scope, and idempotent writes.
  4. Load-test end-to-end while monitoring database, connection pools, and tail latency.

TRADE-OFFS

Benefits and limitations

Benefits

  • Bounded requests protect database and service capacity.
  • Stateless APIs, idempotency, and observable budgets support horizontal scaling.

Limitations

  • Pagination, caching, and asynchronous workflows add contract and consistency complexity.
  • Capacity limits and rate limits can reject work that previously queued implicitly.

DECISION GUIDE

When to use it

Use: Use bounded resource consumption and explicit consistency contracts for public or high-volume APIs.

Avoid: Avoid unbounded collection endpoints, per-request unbounded fan-out, and relying on in-memory state for cross-instance coordination.

COMMON MISTAKES

Watch out

  • Returning all matching rows or allowing unbounded page sizes.
  • Assuming adding API replicas automatically increases database capacity.
  • Using distributed retries without idempotency or a total deadline.

BEST PRACTICES

In practice

  • Use capped pagination, DTO projection, cancellation, and async I/O.
  • Keep application instances stateless and DbContext scoped.
  • Apply rate limits, backpressure, and idempotency to protect dependencies.
  • Load-test realistic traffic mixes and monitor saturation and tail percentiles.

SENIOR-LEVEL SCENARIO

Production thinking

A product endpoint causes database CPU spikes as traffic grows. Cap page size, use keyset pagination and a covering access path if measured, apply request budgets and rate limiting, and monitor latency/DB saturation while scaling out.

SUMMARY

In one minute

A scalable API bounds work per request, isolates failures, manages concurrency and resources, and supports horizontal growth without relying on process-local state. Unbounded queries, payloads, synchronous I/O, shared mutable state, and retry amplification make traffic growth translate directly into database saturation and tail latency.
