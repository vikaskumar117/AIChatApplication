THE IDEA

What is it?

Slow API diagnosis separates time spent in application code, database execution, network/dependency waits, queueing, serialization, and client transfer, then correlates a slow request with trace and resource evidence.

WHY IT MATTERS

What problem does it solve?

Endpoint duration alone cannot reveal whether the cause is an N+1 query, blocking, pool exhaustion, downstream latency, CPU saturation, or oversized response.

UNDER THE HOOD

How does it work?

Compare p50/p95/p99 by route and deployment version, inspect distributed traces and dependency spans, correlate EF command count/duration and Query Store, check connection/thread pools and waits, and reproduce with representative inputs. Change one hypothesis and watch tail latency.

KEY TAKEAWAYS

Remember

  • API latency spans application, data, dependencies, and transfer.
  • Percentiles expose tail degradation hidden by mean duration.
  • Query count, SQL duration, and host saturation are complementary evidence.
  • Protect telemetry from high-cardinality and sensitive payloads.
