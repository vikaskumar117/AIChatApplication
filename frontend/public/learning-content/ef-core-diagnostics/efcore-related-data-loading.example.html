APPLY THE IDEA

Worked example

Return order summaries and line counts in a projection; load a full order aggregate with Include only for a bounded command.

  1. Define the response/entity graph and whether each relation is always required.
  2. Prefer a projection for API output or Include for a bounded entity graph.
  3. Use explicit loading for conditional secondary data.
  4. Inspect generated SQL, number of commands, and result volume.

CODE OR QUERY

Try it

// Projection for a read model:
var summaries = await db.Orders
    .Select(o => new OrderSummaryDto(
        o.Id, o.Number, o.Lines.Count))
    .ToListAsync(ct);

// Explicit loading for a conditional detail path:
var order = await db.Orders.SingleAsync(o => o.Id == id, ct);
if (needLines)
    await db.Entry(order).Collection(o => o.Lines).LoadAsync(ct);

TRADE-OFFS

Benefits and limitations

Benefits

  • Eager loading makes graph shape visible at the query site.
  • Projection returns only required data; explicit loading is deliberate and conditional.

Limitations

  • Eager collection joins can duplicate parent columns and inflate results.
  • Lazy loading hides additional queries; explicit loading can increase round trips.

DECISION GUIDE

When to use it

Use: Use projection for APIs, eager loading for bounded required graphs, and explicit loading for intentionally conditional access.

Avoid: Avoid uncontrolled lazy loading in serialization, loops, or code where hidden I/O violates latency expectations.

COMMON MISTAKES

Watch out

  • Enabling lazy loading without accounting for serializers and loops.
  • Adding several collection Includes without checking cartesian multiplication.
  • Assuming Include is needed when a DTO projection can express the result.

BEST PRACTICES

In practice

  • Make query shape explicit at the service boundary.
  • Count database commands in tests and diagnostics.
  • Use split-query behavior intentionally and verify transactional consistency.
  • Avoid serializing tracked entities directly from an API.

INTERVIEW PRACTICE

Common questions

  1. How do the three loading strategies differ?
  2. When can Include create a large joined result?
  3. How can split queries affect consistency and round trips?

SENIOR-LEVEL SCENARIO

Production thinking

An API serializer touches navigation properties after the service returns. Disable or constrain lazy loading, define the response graph in a projection, and verify SQL command count and result size.

SUMMARY

In one minute

Eager loading fetches related data as part of the original query using Include/ThenInclude or projection. Lazy loading loads a navigation on access, commonly through proxies. Explicit loading deliberately issues a later query through the entry API. Loading strategy controls round trips, row multiplication, memory, and when data access occurs. A navigation access can otherwise hide database I/O.
