THE IDEA

What is it?

N+1 is a query pattern where one query loads N parent records and subsequent navigation access issues roughly one additional query per parent.

WHY IT MATTERS

What problem does it solve?

Round-trip latency and database work can dominate endpoint time and grow linearly with page size, even when each individual SQL statement is quick.

UNDER THE HOOD

How does it work?

Count commands and inspect EF Core database logs/traces. Replace repeated navigation access with a projection, an appropriate Include, or an intentional grouped query. Compare generated SQL, rows transferred, and latency; an overly broad join can also be inefficient.

KEY TAKEAWAYS

Remember

  • N+1 means one parent query plus per-parent relationship queries.
  • Count commands; one slow query is not the only performance problem.
  • Projection often avoids both N+1 and over-fetching.
  • Validate that the fix reduces total work, not just command count.
