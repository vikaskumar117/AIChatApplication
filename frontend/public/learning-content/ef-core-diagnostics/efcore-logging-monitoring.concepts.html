THE IDEA

What is it?

Logs record discrete events, metrics aggregate numerical time series, and traces connect spans across a request and its dependencies. Together they describe what happened, how often, and where latency accumulated.

WHY IT MATTERS

What problem does it solve?

Logs alone are difficult to aggregate; metrics lack per-request context; traces show causal timing but may be sampled. Correlation across all three improves diagnosis.

UNDER THE HOOD

How does it work?

Use structured logs with stable event IDs and trace IDs, low-cardinality metrics for latency/error/saturation, and distributed tracing for request/dependency spans. Redact secrets and personal data; avoid SQL parameter logging unless explicitly approved and protected.

KEY TAKEAWAYS

Remember

  • Metrics detect and quantify; traces localize latency; logs explain events.
  • Trace correlation connects EF/database activity to API requests.
  • High-cardinality labels increase cost and harm aggregation.
  • Never log secrets or unrestricted production SQL parameter values.
