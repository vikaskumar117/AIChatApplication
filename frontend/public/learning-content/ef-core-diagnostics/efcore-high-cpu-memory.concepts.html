THE IDEA

What is it?

High CPU can result from application hot loops, excessive serialization, query translation/materialization, contention, or garbage collection. High memory can be allocation pressure, large caches, unbounded buffers, or retained object graphs.

WHY IT MATTERS

What problem does it solve?

CPU and memory symptoms require different evidence: a high allocation rate can cause GC/CPU without a leak, while retained memory can grow with stable allocation rate.

UNDER THE HOOD

How does it work?

Start with bounded runtime counters and process/container metrics. Use dotnet-counters for live trends, dotnet-trace for sampled CPU/GC stacks, and dotnet-dump for heap/root analysis when authorized. Correlate with request volume and deployment; production dumps may contain sensitive data.

KEY TAKEAWAYS

Remember

  • High allocation can cause CPU/GC without a retained-memory leak.
  • Counters show trends; traces reveal stacks; dumps reveal retained objects/roots.
  • Production diagnostic artifacts may contain sensitive data.
  • Verify the fix under comparable traffic and resource limits.
