THE IDEA

What is it?

An integration test exercises multiple real components across a boundary, such as HTTP routing, dependency injection, serialization, EF Core translation, and a relational database.

WHY IT MATTERS

What problem does it solve?

Integration tests catch configuration, mapping, provider, constraint, and middleware failures that isolated unit tests cannot observe.

UNDER THE HOOD

How does it work?

Use WebApplicationFactory for an in-process ASP.NET Core test host and a disposable relational database such as SQL Server in a container or SQLite when its semantics are sufficient. Isolate test data, apply schema deliberately, and clean up reliably.

KEY TAKEAWAYS

Remember

  • Integration tests validate wiring and real boundary behavior.
  • EF InMemory is not a relational database substitute.
  • Use production-compatible provider testing for SQL-specific behavior.
  • Isolation and cleanup are essential for repeatable parallel runs.
