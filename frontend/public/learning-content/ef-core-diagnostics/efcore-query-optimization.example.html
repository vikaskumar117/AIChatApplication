APPLY THE IDEA

Worked example

A paged endpoint applies a stable server-side order and projection before ToListAsync.

  1. Keep filters, ordering, projection, and paging in IQueryable before materialization.
  2. Use deterministic ordering and page-size limits.
  3. Inspect generated SQL and actual database plan.
  4. Measure allocations, logical reads, result size, and p95/p99 latency.

CODE OR QUERY

Try it

var page = await db.Products
    .AsNoTracking()
    .Where(p => p.IsActive && p.Name.StartsWith(prefix))
    .OrderBy(p => p.Name).ThenBy(p => p.Id)
    .Skip(offset).Take(pageSize)
    .Select(p => new ProductDto(p.Id, p.Name, p.Price))
    .ToListAsync(ct);

TRADE-OFFS

Benefits and limitations

Benefits

  • Projection and server-side filtering reduce transferred rows and allocations.
  • Generated SQL and plans allow optimization at the actual database boundary.

Limitations

  • Some LINQ expressions do not translate or translate differently by provider/version.
  • Offset paging cost can rise at deep pages; specialized SQL or keyset paging may be needed.

DECISION GUIDE

When to use it

Use: Use explicit query shapes and measurements for high-volume or latency-sensitive endpoints.

Avoid: Avoid materializing early, loading full graphs by default, or introducing compiled/raw SQL complexity before measurement.

COMMON MISTAKES

Watch out

  • Calling ToList before Where/Select and processing the full table in memory.
  • Using Skip/Take without deterministic order.
  • Assuming compiled queries fix a database bottleneck.

BEST PRACTICES

In practice

  • Set a maximum page size and stable unique ordering.
  • Use cancellation-aware async terminal operators.
  • Inspect SQL and plan for critical queries.
  • Benchmark representative data distributions and concurrency.

SENIOR-LEVEL SCENARIO

Production thinking

A catalog API allocates heavily and returns slow deep pages. Project DTOs, filter on the server, add a stable ordering, inspect the SQL plan and logical reads, then evaluate keyset pagination and index design.

SUMMARY

In one minute

EF Core query optimization aligns the LINQ expression, generated SQL, indexes, result shape, and database plan with the workload. Deferred IQueryable composition runs at the database only when materialized or enumerated. ORM abstractions can hide over-fetching, client-side work, repeated queries, tracking allocations, and provider translation costs. Database-side execution still follows database planning and resource constraints.
