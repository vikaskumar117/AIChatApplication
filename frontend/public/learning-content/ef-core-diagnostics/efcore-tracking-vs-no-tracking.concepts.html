THE IDEA

What is it?

A tracking query registers materialized entities in DbContext’s change tracker, which records state and original values for SaveChanges. A no-tracking query materializes results without registering them for normal updates; identity resolution controls whether repeated keys share an instance.

WHY IT MATTERS

What problem does it solve?

Tracking supports convenient updates and identity consistency but consumes CPU and memory. Read-only endpoints often benefit from projection or no-tracking materialization.

UNDER THE HOOD

How does it work?

Use tracked entities for update workflows. Use Select projections for read models, or AsNoTracking for read-only entity results. AsNoTrackingWithIdentityResolution deduplicates entity instances within one result without retaining them in the context tracker.

KEY TAKEAWAYS

Remember

  • Tracking stores entity state for change detection and unit-of-work persistence.
  • No-tracking is appropriate for many read-only paths.
  • Projection avoids materializing unused columns and entity state.
  • Identity resolution and tracking are related but distinct choices.
