THE IDEA

What is it?

Eager loading fetches related data as part of the original query using Include/ThenInclude or projection. Lazy loading loads a navigation on access, commonly through proxies. Explicit loading deliberately issues a later query through the entry API.

WHY IT MATTERS

What problem does it solve?

Loading strategy controls round trips, row multiplication, memory, and when data access occurs. A navigation access can otherwise hide database I/O.

UNDER THE HOOD

How does it work?

Prefer projection for read-model shapes, Include when a bounded entity graph is needed, explicit loading when a conditional follow-up is intentional, and lazy loading only when its hidden-query behavior is controlled and measured. Consider split queries for large collection graphs.

KEY TAKEAWAYS

Remember

  • Eager, lazy, and explicit describe when/how navigation data is fetched.
  • Projection often gives the most precise read shape.
  • Lazy loading can make database access invisible to callers.
  • Split queries trade row multiplication for extra commands and consistency considerations.
