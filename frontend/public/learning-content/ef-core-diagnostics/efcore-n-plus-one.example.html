APPLY THE IDEA

Worked example

Return order number and line count with a single aggregate projection instead of enumerating each order’s Lines.

  1. Record database command count per request and correlate with parent count.
  2. Identify navigation accesses that issue SQL.
  3. Express the response as projection or a bounded graph.
  4. Test SQL command count and compare rows transferred and p95 latency.

CODE OR QUERY

Try it

var summaries = await db.Orders
    .Where(o => o.CreatedAt >= start)
    .Select(o => new OrderSummaryDto(
        o.Id, o.Number, o.Lines.Count))
    .ToListAsync(ct);

TRADE-OFFS

Benefits and limitations

Benefits

  • Projection/grouping can reduce round trips and avoid loading unused entity graphs.
  • Command-count instrumentation makes the issue measurable.

Limitations

  • A large Include can replace many round trips with a huge duplicated join result.
  • Provider translation and split-query choices need verification.

DECISION GUIDE

When to use it

Use: Use projection for read models and bounded Includes when entity relationships are required.

Avoid: Avoid navigation access inside loops and lazy-loading during serialization.

COMMON MISTAKES

Watch out

  • Relying on endpoint duration without observing database command count.
  • Replacing N+1 with a massive multi-collection join.
  • Allowing JSON serialization to trigger lazy loads.

BEST PRACTICES

In practice

  • Instrument EF command counts and durations.
  • Write list endpoints as explicit DTO projections.
  • Add regression tests for query count on representative data.
  • Use Include only when the entity graph is truly required.

INTERVIEW PRACTICE

Common questions

  1. How does query count grow in an N+1 pattern?
  2. How can projection avoid over-fetching?
  3. Why is Include not automatically the best fix?

SENIOR-LEVEL SCENARIO

Production thinking

An orders endpoint is fast for one record and slow for a full page. Trace shows one orders query and 50 line queries. Replace with aggregate projection, assert command count in an integration test, and compare rows and response latency.

SUMMARY

In one minute

N+1 is a query pattern where one query loads N parent records and subsequent navigation access issues roughly one additional query per parent. Round-trip latency and database work can dominate endpoint time and grow linearly with page size, even when each individual SQL statement is quick.
