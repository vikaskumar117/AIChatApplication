APPLY THE IDEA

Worked example

An API trace has an EF database span linked to a request ID, while route-level histograms show the p99 regression.

  1. Define service SLOs and the metrics that signal user impact.
  2. Instrument route and dependency spans with propagated trace context.
  3. Emit structured event logs linked by trace/correlation ID.
  4. Review labels, redaction, sampling, access, and retention policies.

TRADE-OFFS

Benefits and limitations

Benefits

  • Three telemetry signals answer complementary diagnostic questions.
  • Correlation IDs connect API activity to dependencies and logs.

Limitations

  • Telemetry volume, cardinality, retention, and sampling require governance.
  • Sensitive data can leak through log scopes, SQL, headers, or exception messages.

DECISION GUIDE

When to use it

Use: Use structured, correlated telemetry aligned with SLOs and incident questions.

Avoid: Avoid high-cardinality metric labels, unredacted secrets, and unbounded verbose production logging.

COMMON MISTAKES

Watch out

  • Using logs as the only source for fleet-wide latency trends.
  • Adding user IDs or arbitrary strings as metric dimensions.
  • Enabling sensitive EF logging in production without strict controls.

BEST PRACTICES

In practice

  • Use OpenTelemetry-compatible instrumentation and context propagation.
  • Keep metric dimensions bounded and stable.
  • Redact personal data, credentials, and sensitive query values.
  • Define retention and access controls for telemetry.

INTERVIEW PRACTICE

Common questions

  1. When do you use logs versus metrics versus traces?
  2. Why are user IDs bad metric labels?
  3. How does trace context improve SQL/API diagnosis?

SENIOR-LEVEL SCENARIO

Production thinking

A latency alert cannot identify which dependency is slow. Add trace propagation and bounded dependency spans, correlate EF command metrics by route/build, and use redaction and low-cardinality tags.

SUMMARY

In one minute

Logs record discrete events, metrics aggregate numerical time series, and traces connect spans across a request and its dependencies. Together they describe what happened, how often, and where latency accumulated. Logs alone are difficult to aggregate; metrics lack per-request context; traces show causal timing but may be sampled. Correlation across all three improves diagnosis.
