APPLY THE IDEA

Worked example

The expression count++ is a read-modify-write sequence; two threads can read the same old value and overwrite one increment.

  1. Run concurrent increments against shared state.
  2. Replace non-atomic read/modify/write with Interlocked.Increment.
  3. Verify the final count under repeated concurrent execution.

CODE OR QUERY

Try it

int count = 0;
Parallel.For(0, 1000, _ => Interlocked.Increment(ref count));
Console.WriteLine(count); // 1000

TRADE-OFFS

Benefits and limitations

Benefits

  • Correct shared invariants
  • Atomic and immutable designs reduce coordination

Limitations

  • Locks can limit throughput
  • Incorrect lock scope can deadlock

DECISION GUIDE

When to use it

Use: Identify shared mutable state and protect the entire invariant-preserving operation.

Avoid: Avoid assuming async code is single-threaded or that one statement is automatically atomic.

COMMON MISTAKES

Watch out

  • Using a lock around only part of a compound invariant.
  • Assuming ConcurrentDictionary makes mutable values thread-safe.

BEST PRACTICES

In practice

  • Prefer immutability or atomic APIs where suitable.
  • Use one consistent synchronization strategy per state.
  • Stress-test and analyze lock contention.

INTERVIEW PRACTICE

Common questions

  1. What is a race condition?
  2. Why can count++ lose updates?
  3. Can async code race without multiple simultaneous instructions?

SENIOR-LEVEL SCENARIO

Production thinking

A singleton cache has occasional corrupted entries under load. Define the entry invariant, use ConcurrentDictionary atomic APIs or a narrow lock, and add stress tests.

SUMMARY

In one minute

Thread safety means preserving invariants under concurrent access; identify races and make updates atomic or synchronized.
