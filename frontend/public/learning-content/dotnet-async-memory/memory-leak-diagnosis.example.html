APPLY THE IDEA

Worked example

A singleton event publisher holds a delegate to a transient subscriber, keeping the subscriber and its object graph reachable until it unsubscribes.

  1. Run the same workload several times and record counters.
  2. Compare heap snapshots and inspect retaining paths.
  3. Unsubscribe or bound the identified owner, then repeat the workload.

CODE OR QUERY

Try it

public sealed class Feed
{
    public event Action? Changed;
    public void Publish() => Changed?.Invoke();
}

public sealed class ViewModel : IDisposable
{
    private readonly Feed feed;
    public ViewModel(Feed feed) => this.feed = feed;
    public void Attach() => feed.Changed += OnChanged;
    private void OnChanged() { }
    public void Dispose() => feed.Changed -= OnChanged;
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Root paths identify retention owners
  • Repeatable snapshots confirm trends

Limitations

  • Snapshots can perturb runtime state
  • Native leaks may not appear in managed heap

DECISION GUIDE

When to use it

Use: Compare snapshots after equivalent workloads and inspect retaining paths.

Avoid: Avoid concluding “leak” from one heap-size sample or allocation count.

COMMON MISTAKES

Watch out

  • Forcing GC before understanding roots.
  • Treating one memory sample as proof of a leak.
  • Pooling objects before determining whether retention is the issue.

BEST PRACTICES

In practice

  • Use repeatable workloads and comparable snapshots.
  • Inspect roots and dominators, including event subscriptions.
  • Validate the fix over repeated lifecycle cycles.

INTERVIEW PRACTICE

Common questions

  1. What is a root path?
  2. How can an event subscription retain an object?
  3. How do allocation and retained heap differ?

SENIOR-LEVEL SCENARIO

Production thinking

A worker process grows after each batch. Compare snapshots and handle counters, locate the retained owner, unsubscribe or bound its cache, then repeat the same workload to verify stabilization.

SUMMARY

In one minute

Diagnose leaks by tracing unintended reachability or undisposed native resources, then confirm stabilization under repeatable load.
