APPLY THE IDEA

Worked example

Load independent profile and permissions concurrently with WhenAll; use WhenAny only when whichever endpoint responds first is acceptable and the loser is canceled or drained.

  1. Start profile and flags tasks before awaiting either.
  2. Use WhenAll when both results are required.
  3. Alternatively await WhenAny and then await the returned task for its result.

CODE OR QUERY

Try it

Task<string> profile = LoadProfileAsync(token);
Task<string> flags = LoadFlagsAsync(token);
string[] results = await Task.WhenAll(profile, flags);

Task<string> first = await Task.WhenAny(profile, flags);
string firstResult = await first;

TRADE-OFFS

Benefits and limitations

Benefits

  • Concurrent independent work can reduce wait time
  • WhenAny supports race and fallback patterns

Limitations

  • Failures and cancellation require explicit policy
  • Losing tasks may continue consuming resources

DECISION GUIDE

When to use it

Use: Use WhenAll for independent work that must all succeed or be accounted for.

Avoid: Avoid unbounded fan-out and abandoning WhenAny losers.

COMMON MISTAKES

Watch out

  • Starting one task, awaiting it, then starting the next and expecting overlap.
  • Discarding tasks that lost a WhenAny race without observing errors.

BEST PRACTICES

In practice

  • Propagate cancellation tokens.
  • Bound concurrent operations.
  • Define partial failure and timeout behavior.

INTERVIEW PRACTICE

Common questions

  1. Does WhenAny return the result?
  2. How are WhenAll results ordered?
  3. What should happen to losing tasks after a race?

SENIOR-LEVEL SCENARIO

Production thinking

A dashboard loads independent data sources. Use bounded concurrency and WhenAll if all sections are mandatory; otherwise define timeout, fallback, and loser cancellation policy.

SUMMARY

In one minute

WhenAll joins all operations; WhenAny selects a completed task, while the caller remains responsible for all outcomes and cleanup.
