APPLY THE IDEA

Worked example

A local value used after an HTTP await must be available to the continuation, so generated state captures what is needed.

  1. Set multiplier before the await.
  2. If the HTTP Task is incomplete, preserve multiplier and continuation state.
  3. Resume, obtain body, then calculate the result.

CODE OR QUERY

Try it

static async Task<int> ReadLengthAsync(HttpClient client, CancellationToken token)
{
    int multiplier = 2;
    string body = await client.GetStringAsync("/data", token);
    return body.Length * multiplier;
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Readable sequential control flow
  • No blocked worker during incomplete await

Limitations

  • State and continuation have overhead
  • Captured locals can extend object lifetimes

DECISION GUIDE

When to use it

Use: Await returned asynchronous operations and keep state lifetimes short.

Avoid: Avoid unnecessary async state machines when a method only returns an existing Task and needs no transformation.

COMMON MISTAKES

Watch out

  • Assuming one thread remains parked with the local stack.
  • Capturing large object graphs across long waits unnecessarily.

BEST PRACTICES

In practice

  • Keep async methods composable and cancellation-aware.
  • Minimize long-lived references across awaits.
  • Profile before removing async/await for micro-optimization.

INTERVIEW PRACTICE

Common questions

  1. What is stored in the generated state machine?
  2. What does the awaiter do?
  3. When can await continue synchronously?

SENIOR-LEVEL SCENARIO

Production thinking

A high-volume parser’s allocation profile shows many tiny completed async operations. Preserve async where needed for composition; optimize measured hot paths without losing exception or cancellation semantics.

SUMMARY

In one minute

The compiler-generated state machine saves the necessary state at incomplete awaits and resumes through an awaiter continuation.
