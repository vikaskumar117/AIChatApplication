APPLY THE IDEA

Worked example

A method that only returns repository.LoadAsync can return that Task directly; retaining async/await adds no behavior.

  1. Inspect whether the body has any await or transformation.
  2. Return the repository Task directly if forwarding only.
  3. Retain async if local catch/finally or exception semantics are required.

CODE OR QUERY

Try it

// Redundant wrapper:
async Task<Customer?> FindAsync(Guid id) => await repository.FindAsync(id);

// Direct forwarding:
Task<Customer?> FindAsync(Guid id) => repository.FindAsync(id);

TRADE-OFFS

Benefits and limitations

Benefits

  • Direct forwarding avoids needless state-machine work
  • Consistent async contract may be valuable

Limitations

  • Synchronous exceptions may escape differently
  • Removing async can change stack traces and exception timing

DECISION GUIDE

When to use it

Use: Return a Task directly when truly forwarding without transformation.

Avoid: Keep async when adding await-specific cleanup, exception conversion, or multiple sequential asynchronous steps.

COMMON MISTAKES

Watch out

  • Removing async without checking exception behavior.
  • Using Task.Run merely to make a synchronous body appear asynchronous.

BEST PRACTICES

In practice

  • Keep method semantics consistent with its contract.
  • Use Task.FromResult for truly synchronous results when useful.
  • Test both successful and failing paths after refactoring.

INTERVIEW PRACTICE

Common questions

  1. What happens to code in async without await?
  2. How does direct forwarding affect synchronous exceptions?
  3. When is retaining async intentional?

SENIOR-LEVEL SCENARIO

Production thinking

A repository wrapper merely forwards a Task. Remove the redundant async modifier only after verifying callers and tests accept exception timing and stack-trace behavior.

SUMMARY

In one minute

Without await an async method runs synchronously; direct Task forwarding is simpler unless async exception or cleanup semantics are needed.
