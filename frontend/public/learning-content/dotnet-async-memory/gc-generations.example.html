APPLY THE IDEA

Worked example

Request-scoped temporary objects often die in Gen 0; a global cache may retain objects long enough to promote, increasing Gen 2 footprint.

  1. Observe an object’s current generation with GC.GetGeneration.
  2. Track collection counts around representative work.
  3. Use heap snapshots to identify why objects survive and promote.

CODE OR QUERY

Try it

int gen = GC.GetGeneration(someObject);
int gen0Collections = GC.CollectionCount(0);
ProcessRequests();
Console.WriteLine($"Generation={gen}, Gen0 collections={GC.CollectionCount(0) - gen0Collections}");

TRADE-OFFS

Benefits and limitations

Benefits

  • Young collections reclaim many short-lived objects cheaply
  • Survival history guides collection work

Limitations

  • Promoted retention increases long-lived heap
  • Large/pinned objects have specialized costs

DECISION GUIDE

When to use it

Use: Use generation counters as clues, not a standalone diagnosis.

Avoid: Avoid forcing promotion or collections to “manage” generations.

COMMON MISTAKES

Watch out

  • Assuming every object starts in Gen 0 regardless of allocation category.
  • Treating LOH as simply a regular generation.
  • Calling Collect to force desired promotion behavior.

BEST PRACTICES

In practice

  • Correlate collection counts with allocation and heap snapshots.
  • Review cache and static roots.
  • Avoid large transient allocations where measurements justify it.

INTERVIEW PRACTICE

Common questions

  1. What causes promotion?
  2. Why are Gen 0 collections common?
  3. How does long-lived cache retention affect Gen 2?

SENIOR-LEVEL SCENARIO

Production thinking

A service’s Gen 2 size grows over hours. Compare heap snapshots and cache roots for unintended long-lived objects and check LOH allocation separately.

SUMMARY

In one minute

Generational GC collects young objects frequently and promotes survivors; use generation data alongside retention and allocation profiles.
