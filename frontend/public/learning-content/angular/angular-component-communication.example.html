APPLY THE IDEA

Worked example

A reusable date picker receives the selected date and emits a selection; unrelated pages do not couple themselves to its internal state.

  1. Keep reusable components controlled by explicit inputs and outputs.
  2. Choose provider scope to match state lifetime.
  3. Use readonly state interfaces and intentional update methods in shared services.

CODE OR QUERY

Try it

@Component({ selector: 'app-date-picker', template: '' })
export class DatePicker {
  readonly value = input<Date | null>(null);
  readonly valueChange = output<Date>();

  select(date: Date): void {
    this.valueChange.emit(date);
  }
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Inputs/outputs make local contracts visible
  • Scoped services support sibling or cross-route coordination

Limitations

  • Global buses obscure causality
  • Shared mutable objects make ownership and updates unclear

DECISION GUIDE

When to use it

Use: Prefer input-down/event-up for direct relationships and a scoped service/store for shared lifetimes.

Avoid: Avoid reaching into child internals or using a global event bus for routine parent-child state.

COMMON MISTAKES

Watch out

  • Mutating an input object inside a child without an emitted intent.
  • Creating a root singleton event bus for unrelated features.
  • Using view queries as a substitute for a stable component API.

BEST PRACTICES

In practice

  • Keep state local until a real sharing requirement appears.
  • Document event meaning and payload semantics.
  • Test component contracts independently from the store implementation.

INTERVIEW PRACTICE

Common questions

  1. Who owns the authoritative state in a parent-child interaction?
  2. When is a service better than outputs?
  3. Why should child outputs express intent rather than hidden mutation?

SENIOR-LEVEL SCENARIO

Production thinking

Two distant workflow steps need the same draft for the duration of one route. Provide a route-scoped state service and clear it with the workflow lifetime instead of creating permanent root-level mutable state.

SUMMARY

In one minute

A parent supplies state through inputs and receives child intent through outputs; this keeps ownership explicit. Content/view queries and model inputs have narrower purposes, while sibling or cross-route coordination often requires a shared service/store. Signals, Observable streams, and immutable input values can carry state; outputs should express events or intent rather than let a child mutate parent-owned objects invisibly. Avoid using a global event bus for tightly related components.
