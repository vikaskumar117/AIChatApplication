APPLY THE IDEA

Worked example

A route-level account selector needs a current account for a component that subscribes after initialization; a toast event should not replay to a later page.

  1. Expose account$ as read-only observable.
  2. Use null or an explicit state union when “no account” is meaningful.
  3. Use async pipe or takeUntilDestroyed for component-owned subscriptions.

CODE OR QUERY

Try it

private readonly accountSubject = new BehaviorSubject<Account | null>(null);
readonly account$ = this.accountSubject.asObservable();

selectAccount(account: Account): void {
  this.accountSubject.next(account);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • BehaviorSubject provides immediate current state to late subscribers
  • Subject is a lightweight event broadcast

Limitations

  • A writable subject can create hidden shared mutation
  • BehaviorSubject seed and stale values can misrepresent loading or logout state

DECISION GUIDE

When to use it

Use: Use BehaviorSubject when consumers need the latest value and a stream API is intentional; use Subject for non-replay events.

Avoid: Avoid exposing either subject as a public writable API or treating completion as automatic component cleanup.

COMMON MISTAKES

Watch out

  • A Subject is not a cache; late subscribers miss prior events.
  • Do not seed BehaviorSubject with a fake domain object merely to avoid nullable state.
  • Do not use a BehaviorSubject as a generic global store without defining ownership.

BEST PRACTICES

In practice

  • Keep the subject private and expose asObservable().
  • Represent loading, success, and failure explicitly when consumers need more than a nullable value.
  • Choose replay intentionally for commands versus durable state.

SENIOR-LEVEL SCENARIO

Production thinking

A page opened after account selection must show the selected account immediately, but a newly mounted notification panel must not replay old toasts. Give the two needs separate stream contracts and test late subscriptions.

SUMMARY

In one minute

A Subject is both an Observer and an Observable: calling next broadcasts to current subscribers, but it does not retain a current value. A BehaviorSubject additionally requires a seed and synchronously emits its latest value to each new subscriber. Replay determines whether a consumer starting late can render immediately. This matters for current state such as the selected account, while replaying transient events can incorrectly repeat commands or notifications.
