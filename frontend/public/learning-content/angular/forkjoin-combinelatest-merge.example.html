APPLY THE IDEA

Worked example

Load initial settings with forkJoin, derive a filtered view from filters and live data with combineLatest, and merge independent refresh events when only event order matters.

  1. Seed state streams when a latest-value output is required immediately.
  2. Use named object properties for forkJoin aggregates when supported by the project RxJS version.
  3. Test error and completion behavior, not only happy-path values.

CODE OR QUERY

Try it

const initial$ = forkJoin([user$, settings$]);
const view$ = combineLatest([filters$, rows$]);
const events$ = merge(refreshClick$, reconnect$);

TRADE-OFFS

Benefits and limitations

Benefits

  • Each operator expresses a distinct timing contract
  • Correct choice makes UI update behavior predictable

Limitations

  • Wrong operator can never emit or emit too often
  • combineLatest retains latest values and may recompute frequently

DECISION GUIDE

When to use it

Use: Use forkJoin for completed finite inputs, combineLatest for latest-state recomputation, and merge for interleaved events.

Avoid: Avoid combineLatest when any source may never emit without providing a deliberate initial value.

COMMON MISTAKES

Watch out

  • Expecting merge to synchronize inputs into a tuple.
  • Expecting combineLatest to emit before each source has emitted once.
  • Using forkJoin with a long-lived stream that never completes.

BEST PRACTICES

In practice

  • Write down each source’s cardinality and completion behavior before choosing.
  • Use map after combination to derive a view model.
  • Place error recovery at the level where partial versus total failure is decided.

INTERVIEW PRACTICE

Common questions

  1. Which operator emits only once after completion?
  2. Why does combineLatest wait before its first emission?
  3. Does merge produce a tuple?

SENIOR-LEVEL SCENARIO

Production thinking

A route combines an HTTP-loaded catalog with a live filter form. forkJoin loads finite initial resources; combineLatest drives the filtered view as either filters or rows change.

SUMMARY

In one minute

forkJoin waits for every source to complete, then emits their last values once. combineLatest waits until every source has emitted, then emits a new tuple whenever any source emits, using each source’s latest value. merge forwards each source emission independently as it arrives; it does not create a tuple or wait for all sources. Each operator preserves Observable completion/error rules, and a source error normally errors the result.
