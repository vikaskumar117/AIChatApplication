APPLY THE IDEA

Worked example

A correlation interceptor tags requests and measures latency without embedding telemetry code in each feature service.

  1. Prefer functional interceptors for explicit dependency injection and predictable configuration.
  2. Use HttpContextToken for opt-out or per-request policy flags.
  3. Test both outgoing request mutations and response/error behavior.

CODE OR QUERY

Try it

export const correlationInterceptor: HttpInterceptorFn = (req, next) => {
  const id = inject(CorrelationIds).create();
  return next(req.clone({ setHeaders: { 'X-Correlation-ID': id } }));
};

provideHttpClient(withInterceptors([correlationInterceptor]));

TRADE-OFFS

Benefits and limitations

Benefits

  • One policy across feature services
  • Composable request and response instrumentation

Limitations

  • Ordering and retries can be difficult to reason about
  • Global logic can hide feature-specific behavior

DECISION GUIDE

When to use it

Use: Use functional interceptors for transport-wide behavior and register their order intentionally.

Avoid: Avoid unbounded retries, business-specific decisions, and logging sensitive headers.

COMMON MISTAKES

Watch out

  • Mutating a request object instead of cloning it.
  • Retrying every request indefinitely or refreshing on the refresh endpoint itself.
  • Logging full headers or bodies containing credentials and personal data.

BEST PRACTICES

In practice

  • Keep the chain narrow and ordered.
  • Protect recursive flows with explicit request context or endpoint policy.
  • Separate transport concerns from domain decisions.

INTERVIEW PRACTICE

Common questions

  1. Why are HttpRequest objects cloned?
  2. How does interceptor order affect request/response flow?
  3. What prevents refresh requests from recursively invoking refresh logic?

SENIOR-LEVEL SCENARIO

Production thinking

Several APIs need correlation IDs and common telemetry. Add a functional interceptor, verify ordering with a test backend, and ensure the telemetry output redacts authorization and personal data.

SUMMARY

In one minute

An HttpInterceptorFn receives an immutable HttpRequest and a next handler, then returns an Observable<HttpEvent<unknown>>. Clone requests to change headers or parameters; responses and errors flow back through the chain. Interceptors centralize concerns such as correlation IDs, trusted-origin credentials, timing, and consistent transport error mapping. Ordering matters: each interceptor wraps downstream processing and can observe the transformed result.
