APPLY THE IDEA

Worked example

For live search, a newer query supersedes the older query; for a submitted payment, cancellation cannot establish whether the payment committed.

  1. Debounce and deduplicate user input before issuing requests.
  2. Use switchMap only when newer intent supersedes earlier work.
  3. Use idempotency keys and server-side status checks for critical writes.

CODE OR QUERY

Try it

readonly results$ = this.query$.pipe(
  debounceTime(250),
  distinctUntilChanged(),
  switchMap(query => this.http.get<Result[]>('/api/search', {
    params: { query }
  }))
);

TRADE-OFFS

Benefits and limitations

Benefits

  • Prevents stale read results from winning races
  • Reduces unnecessary client/network work

Limitations

  • Server may still process an aborted request
  • switchMap is wrong when every write must be observed

DECISION GUIDE

When to use it

Use: Use switchMap for replaceable reads, and async pipe or takeUntilDestroyed for owner-bound subscriptions.

Avoid: Avoid interpreting unsubscribe as rollback or using switchMap for non-idempotent commands that must all complete.

COMMON MISTAKES

Watch out

  • Starting a request inside an unmanaged nested subscribe.
  • Using switchMap for every POST/PUT even when all operations must finish.
  • Assuming unsubscribe proves a mutation was not applied.

BEST PRACTICES

In practice

  • Prefer stream composition over manual subscription replacement.
  • Tie component-owned streams to the component lifetime.
  • Design mutation APIs for retries, idempotency, and ambiguous client disconnects.

INTERVIEW PRACTICE

Common questions

SENIOR-LEVEL SCENARIO

Production thinking

A slow prior search finishes after a fast newer one. switchMap removes the old subscription, and the UI renders only the newest response; verify server behavior separately for any mutation endpoints.

SUMMARY

In one minute

Angular HttpClient returns cold Observables. Unsubscribing before completion aborts the in-progress browser request where the backend supports it; it does not guarantee that the server did not receive or finish processing the request. switchMap unsubscribes the previous inner Observable when a newer source value arrives, making it appropriate for replaceable reads such as search. takeUntilDestroyed ends work when its Angular owner is destroyed.
