APPLY THE IDEA

Worked example

A parent replaces a list reference and an OnPush child updates; mutating an existing row object without a new binding reference can leave the child stale.

  1. Keep input objects immutable or use observable/signal inputs with clear ownership.
  2. Use markForCheck when a legitimate external boundary needs a future Angular check.
  3. Measure subtree cost and binding work independently.

CODE OR QUERY

Try it

@Component({ changeDetection: ChangeDetectionStrategy.OnPush })
export class UserList {
  @Input({ required: true }) users: readonly User[] = [];
}

TRADE-OFFS

Benefits and limitations

Benefits

  • OnPush reduces avoidable subtree work
  • Explicit reference flow is easier to reason about

Limitations

  • In-place mutation may not mark input changes
  • Manual marking can add complexity at integration boundaries

DECISION GUIDE

When to use it

Use: Prefer OnPush with immutable inputs and signal/async-pipe state.

Avoid: Avoid assuming OnPush means no checks or using detectChanges for ordinary data flow.

COMMON MISTAKES

Watch out

  • Mutating an input object in place and expecting an input-change trigger.
  • Thinking a click inside an OnPush component is ignored.
  • Calling detectChanges repeatedly to paper over stale references.

BEST PRACTICES

In practice

  • Design component inputs as explicit state boundaries.
  • Prefer async pipe/signals to manual subscriptions.
  • Use local detection only for deliberate low-level integration cases.

INTERVIEW PRACTICE

Common questions

  1. Name four common OnPush triggers.

SENIOR-LEVEL SCENARIO

Production thinking

A table’s child row appears stale after an in-place update. Replace the changed row and enclosing array references, or expose the row as signal/observable state; test event and async-pipe triggers separately.

SUMMARY

In one minute

Default strategy makes a view broadly eligible during Angular change-detection passes. OnPush allows Angular to skip a subtree until a recognized trigger marks it, such as a changed input binding, an event in the subtree, a signal update read by the view, or an async pipe emission. OnPush encourages explicit data flow and can reduce unnecessary checks in large trees, but it does not eliminate checks or require every internal property to be immutable. In-place mutation of an input object can evade reference-based input change detection.
