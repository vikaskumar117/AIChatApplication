APPLY THE IDEA

Worked example

A callback from a non-Angular widget updates a signal read by the template, so the state change has an explicit rendering notification.

  1. Keep template expressions cheap and move nontrivial derivation into computed values or memoized selectors.
  2. Use track/trackBy identity to preserve repeated-view instances.
  3. Use Angular DevTools and production-like profiling to validate improvements.

CODE OR QUERY

Try it

readonly count = signal(0);

increment(): void {
  this.count.update(value => value + 1);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Understanding eligibility makes rendering predictable
  • Signals and async pipe provide explicit notifications

Limitations

  • Broad checks can cost time in large trees
  • Manual detection can mask broken state boundaries

DECISION GUIDE

When to use it

Use: Use Angular-observed events, signals, and async pipe; profile before optimizing.

Avoid: Avoid repeated detectChanges calls and direct DOM writes that diverge from template state.

COMMON MISTAKES

Watch out

  • Assuming every object mutation triggers every view.
  • Calling detectChanges as a general-purpose fix for stale state.
  • Measuring only development mode or synthetic microbenchmarks.

BEST PRACTICES

In practice

  • Use immutable updates at component boundaries when reference identity matters.
  • Adopt signals/async pipe for explicit reactive rendering.
  • Optimize measured bottlenecks rather than applying blanket manual detection.

INTERVIEW PRACTICE

Common questions

SENIOR-LEVEL SCENARIO

Production thinking

A legacy chart fires a callback outside the usual Angular event path. Update a template-read signal or bridge into Angular’s scheduling model, then verify the affected view with profiling rather than adding global forced checks.

SUMMARY

In one minute

Angular evaluates template expressions for views considered eligible for checking and applies changed binding values to the DOM. A state mutation alone is not universally a notification; Angular must know that relevant work may have occurred. Events, input updates, async pipe emissions, and signal writes read by a template provide notification paths. OnPush narrows eligibility but does not mean “never check”; Angular traverses marked paths and checks the relevant view.
