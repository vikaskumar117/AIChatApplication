APPLY THE IDEA

Worked example

An admin console used by a small subset of users is loaded as a separate route chunk rather than included in every visitor’s initial bundle.

  1. Inspect emitted chunk sizes and route waterfalls.
  2. Use route-level loading/error UX for slow or failed chunk loads.
  3. Consider selective preloading for likely next routes.

CODE OR QUERY

Try it

export const routes: Routes = [
  {
    path: 'admin',
    loadChildren: () => import('./admin/admin.routes')
      .then(module => module.ADMIN_ROUTES)
  }
];

TRADE-OFFS

Benefits and limitations

Benefits

  • Shrinks startup code for deferred features
  • Creates clear route-level ownership boundaries

Limitations

  • First navigation can be slower
  • Excessive fragmentation and preloading can waste resources

DECISION GUIDE

When to use it

Use: Lazy-load substantial, noncritical route features and measure initial and navigation costs.

Avoid: Avoid assuming lazy loading protects code or data from unauthorized users.

COMMON MISTAKES

Watch out

  • Lazy-loading tiny modules with high overhead and no meaningful startup benefit.
  • Preloading every route on constrained connections.
  • Relying on hidden route code as access control.

BEST PRACTICES

In practice

  • Keep feature boundaries cohesive and avoid duplicate shared chunks.
  • Measure initial and deferred navigation separately.
  • Enforce permissions on the server regardless of route configuration.

INTERVIEW PRACTICE

Common questions

  1. What work moves to the first feature navigation?
  2. How does preloading change the trade-off?
  3. Why is lazy loading not authorization?

SENIOR-LEVEL SCENARIO

Production thinking

A rarely used reporting feature inflates the main bundle. Split it at the route boundary, measure both startup and first-navigation latency, and secure all report data at the API.

SUMMARY

In one minute

A lazy route loads a component or route configuration through dynamic import when Angular activates that route. This creates a separate code chunk that can be downloaded and evaluated on demand. Lazy loading can reduce initial JavaScript, but does not reduce total application code and may add route-entry latency. Preloading strategies trade network/bandwidth and memory for faster subsequent navigation.
