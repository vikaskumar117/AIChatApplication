APPLY THE IDEA

Worked example

An authenticated user without an admin role is redirected from the admin route, while the API still checks the role on every administrative request.

  1. Prefer functional guards and injectable policy services.
  2. Handle an authentication state that is still loading without racing the router.
  3. Use CanDeactivate for unsaved work and provide accessible confirmation.

CODE OR QUERY

Try it

export const signedInGuard: CanActivateFn = () => {
  const auth = inject(AuthSession);
  const router = inject(Router);
  return auth.isSignedIn()
    ? true
    : router.createUrlTree(['/sign-in']);
};

TRADE-OFFS

Benefits and limitations

Benefits

  • Keeps navigation aligned with application state
  • UrlTree redirects are declarative and race-resistant

Limitations

  • Client checks are bypassable
  • Slow guard dependencies delay route activation

DECISION GUIDE

When to use it

Use: Use guards for client navigation UX and return UrlTree for redirects.

Avoid: Avoid treating a route guard as authorization or duplicating complex business policy in the router.

COMMON MISTAKES

Watch out

  • Using a guard as the sole protection for sensitive API data.
  • Calling router.navigate and returning false, causing competing transitions.
  • Putting long or side-effect-heavy workflows inside a guard.

BEST PRACTICES

In practice

  • Return explicit typed decisions and keep checks fast.
  • Test direct URL entry, reload, delayed auth resolution, and rejected access.
  • Enforce authorization at the API and data layer.

SENIOR-LEVEL SCENARIO

Production thinking

A user can alter client state or call APIs directly. The guard hides inaccessible navigation, while each protected API independently validates the identity and permission.

SUMMARY

In one minute

CanActivate, CanActivateChild, CanMatch, and CanDeactivate guard different router decisions. A guard may synchronously return a boolean or return a Promise/Observable that resolves to a decision or UrlTree/RedirectCommand. Returning a UrlTree communicates redirect intent to the router; imperatively navigating and returning false can create races. CanMatch can prevent a route from matching, while CanDeactivate is suited to unsaved-change confirmation.
