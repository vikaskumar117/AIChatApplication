APPLY THE IDEA

Worked example

A typeahead benefits from Observable cancellation and debounce; a one-off browser API wrapper may be easier to consume as a Promise.

  1. Subscribe once or share deliberately when multiple consumers must not duplicate a cold request.
  2. Use firstValueFrom only for a guaranteed first emission and lastValueFrom only for a stream that completes.
  3. Keep errors in the same model as the chosen abstraction.

CODE OR QUERY

Try it

const user$ = this.http.get<User>('/api/users/42');
const user = await firstValueFrom(user$);

TRADE-OFFS

Benefits and limitations

Benefits

  • Observable operators model time, retries, and cancellation
  • Promise syntax is concise for one eventual result

Limitations

  • Promises have no standard cancellation
  • Unsubscribing an Observable does not undo server work already performed

DECISION GUIDE

When to use it

Use: Use Observable when the source can emit repeatedly, must be cancelled, or composes with Angular streams; use Promise for a true one-shot boundary.

Avoid: Avoid converting a long-lived stream with firstValueFrom or lastValueFrom unless its emission and completion semantics are guaranteed.

COMMON MISTAKES

Watch out

  • Assuming every Observable is infinite or every HTTP observable is shared.
  • Using lastValueFrom on a stream that never completes.
  • Assuming Promise.race cancels the losing operation.

BEST PRACTICES

In practice

  • Treat emission count, completion, and cancellation as explicit API contracts.
  • Prefer async pipe for template consumption and compose streams before subscribing.
  • Use an AbortSignal-aware API when Promise-based work must support cancellation.

SENIOR-LEVEL SCENARIO

Production thinking

A search box issues a new request for every keystroke. Keep it as an Observable so switchMap can replace stale client work; use a Promise for a single confirmation dialog result that settles exactly once.

SUMMARY

In one minute

A Promise settles once with a value or error; an Observable can emit zero, one, or many values and then complete or error. Angular HttpClient observables normally emit one response and complete, but share the Observable contract. Observables are lazy by default: subscribing starts execution, and separate subscriptions can start separate executions. Promises represent work already started when created and cannot be cancelled through the standard Promise API.
