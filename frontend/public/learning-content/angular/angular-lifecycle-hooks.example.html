APPLY THE IDEA

Worked example

A chart needs a rendered host element, while data derived from an input must respond to every relevant input change.

  1. Prefer input-driven derivations over copying input values once in ngOnInit.
  2. Use afterNextRender for DOM work that must follow rendering.
  3. Tie subscriptions and imperative resources to DestroyRef.

CODE OR QUERY

Try it

private readonly destroyRef = inject(DestroyRef);

ngOnInit(): void {
  this.feed.events$
    .pipe(takeUntilDestroyed(this.destroyRef))
    .subscribe(event => this.apply(event));
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Hooks clarify readiness and ownership
  • DestroyRef offers concise lifecycle-bound cleanup

Limitations

  • Misplaced work causes stale inputs or DOM timing bugs
  • Heavy checked hooks can dominate render cost

DECISION GUIDE

When to use it

Use: Use the narrowest hook matching input, view, or destruction readiness.

Avoid: Avoid subscriptions and expensive computation in ngDoCheck or repeated after-check hooks.

COMMON MISTAKES

Watch out

  • Reading a view query before it is initialized.
  • Assuming ngOnInit runs again whenever an input changes.
  • Doing network or expensive computation in ngDoCheck.

BEST PRACTICES

In practice

  • Keep constructors free of work that depends on inputs or rendered DOM.
  • Make cleanup ownership explicit.
  • Use lifecycle hooks sparingly when declarative signals or template bindings suffice.

SENIOR-LEVEL SCENARIO

Production thinking

A reusable chart receives changing data and owns a live stream. Recompute from input changes, initialize chart integration only when its host exists, and dispose observers/third-party instances with DestroyRef.

SUMMARY

In one minute

Angular constructs a component, assigns inputs, checks the view, and eventually destroys it. Hooks such as ngOnChanges, ngOnInit, ngAfterViewInit, and ngOnDestroy are callbacks for those phases, not arbitrary scheduling utilities. Choose a hook according to dependency readiness: input-dependent work belongs in ngOnChanges or an input transform/signal; one-time setup belongs in ngOnInit; DOM/view-dependent work belongs after view initialization; owned cleanup belongs at destruction.
