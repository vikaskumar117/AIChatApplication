APPLY THE IDEA

Worked example

A SPA calls its own API and a third-party image service; the bearer token is attached only to the API origin.

  1. Use HTTPS everywhere and short-lived, least-privilege access tokens.
  2. Keep token acquisition behind an injectable auth abstraction.
  3. Have the server validate claims and permissions; client decoding is not trust.

CODE OR QUERY

Try it

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const trusted = new URL(req.url, location.origin).origin === 'https://api.example.com';
  const token = inject(AuthSession).accessToken();
  return next(trusted && token
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })
    : req);
};

TRADE-OFFS

Benefits and limitations

Benefits

  • Centralized attachment prevents per-service omissions
  • Origin checks reduce accidental credential disclosure

Limitations

  • XSS can steal JavaScript-readable tokens
  • Bearer tokens remain usable if leaked until policy expires them

DECISION GUIDE

When to use it

Use: Use an explicit trusted-origin allowlist and a narrowly scoped token provider.

Avoid: Avoid storing long-lived tokens in browser storage or attaching credentials to arbitrary URLs.

COMMON MISTAKES

Watch out

  • Sending the token to every host because an interceptor sees every HttpClient request.
  • Assuming JWT payload encryption or trusting decoded claims client-side.
  • Logging or persisting bearer credentials unnecessarily.

BEST PRACTICES

In practice

  • Prefer secure server-managed session patterns where feasible.
  • If using cookies, design CSRF defenses and SameSite policy deliberately.
  • Redact authorization headers from logs, traces, and error reports.

SENIOR-LEVEL SCENARIO

Production thinking

A feature introduces a third-party upload endpoint. Test that its origin never receives Authorization, and ensure decoded client claims only influence UX while the server enforces permissions.

SUMMARY

In one minute

A JWT is a signed claims container, not encrypted by default; its claims can be read by anyone holding it. A bearer token grants authority to whoever possesses it until expiry or revocation policy takes effect. A functional interceptor can read an access token from an injected authentication abstraction and clone a request with an Authorization: Bearer header. Restrict attachment by trusted origin and exclude token/refresh endpoints as appropriate.
