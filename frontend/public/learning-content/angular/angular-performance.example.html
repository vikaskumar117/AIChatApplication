APPLY THE IDEA

Worked example

A slow table is profiled first: the trace shows thousands of DOM rows and repeated formatting, so virtualization and precomputed view models are tested before changing unrelated HTTP code.

  1. Set bundle and interaction budgets in CI where feasible.
  2. Use stable keys for repeated views and avoid expensive template calls.
  3. Load noncritical features lazily and virtualize only when DOM volume is the bottleneck.

TRADE-OFFS

Benefits and limitations

Benefits

  • Profiling directs effort to actual bottlenecks
  • Layered improvements can reduce payload and rendering cost

Limitations

  • Premature optimization adds complexity
  • Caching and virtualization can increase memory or correctness risks

DECISION GUIDE

When to use it

Use: Profile representative production-like flows and optimize the limiting resource.

Avoid: Avoid broad rewrites based on assumptions or adding memoization without measuring invalidation and memory cost.

COMMON MISTAKES

Watch out

  • Optimizing development-mode traces as if they were production.
  • Adding caching that serves stale or cross-user data.
  • Assuming OnPush alone fixes a long task or oversized bundle.

BEST PRACTICES

In practice

  • Measure cold and warm paths, network conditions, and realistic data sizes.
  • Recheck accessibility and keyboard behavior after virtualization.
  • Prefer small, reversible changes with recorded before/after metrics.

INTERVIEW PRACTICE

Common questions

  1. Which measurements distinguish bundle cost from rendering cost?

SENIOR-LEVEL SCENARIO

Production thinking

A large analytics route is slow on midrange devices. Compare cold-start, route-entry, and scroll traces; reduce its lazy chunk, virtualize the proven DOM bottleneck, and add a repeatable performance budget.

SUMMARY

In one minute

Performance includes startup and route loading, interaction latency, rendering/scroll smoothness, network waterfalls, and memory retention. A change that improves one dimension can worsen another. Angular tools such as DevTools, browser performance traces, and bundle analysis identify expensive components, template work, long tasks, and oversized dependencies. OnPush/signals, lazy routes, stable list identity, and code splitting address different bottleneck classes.
