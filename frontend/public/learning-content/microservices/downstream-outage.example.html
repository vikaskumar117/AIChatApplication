APPLY THE IDEA

Worked example

If Recommendations is down, the product page still returns core product details and omits the optional recommendation panel.

  1. Determine whether the dependency is essential to this use case.
  2. Set a caller budget and concurrency limit.
  3. Map failure to valid fallback, pending status, or explicit error.
  4. Alert on degradation and test recovery under load.

TRADE-OFFS

Benefits and limitations

Benefits

  • Explicit degradation preserves critical paths when an optional dependency fails.
  • Load shedding protects healthy dependencies and local capacity.

Limitations

  • Fallbacks can mislead users if stale or semantically invalid.
  • A failed dependency can still cause cascading overload through queued or blocked calls.

DECISION GUIDE

When to use it

Use: Classify dependencies as critical or optional and define outage behavior per operation.

Avoid: Avoid swallowing failures or presenting defaults that look authoritative.

COMMON MISTAKES

Watch out

  • Avoid swallowing failures or presenting defaults that look authoritative.
  • Assuming responding to a downstream outage guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Keep critical and optional dependencies distinct.
  • Expose degraded behavior in telemetry and, where appropriate, the response.

SENIOR-LEVEL SCENARIO

Production thinking

Catalog is healthy but its image service is stalled. Deadline-bound image calls and a placeholder protect product requests; dashboards distinguish degraded images from catalog errors.

SUMMARY

In one minute

Outage handling limits resource damage and preserves truthful business behavior; it does not make the dependency available.
