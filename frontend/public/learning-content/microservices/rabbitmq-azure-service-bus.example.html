TRADE-OFFS

Benefits and limitations

Benefits

  • Buffers bursts and permits consumers to scale independently.
  • Topics enable multiple subscribers without producer knowledge of each consumer.

Limitations

  • Brokers can fill, redeliver, reorder, or reject work under quota and outage conditions.
  • Broker semantics differ; “exactly once” claims do not remove application-level duplicate effects.

DECISION GUIDE

When to use it

Use: Use broker primitives to match competing work versus independent subscriptions.

Avoid: Avoid assuming broker configuration alone guarantees end-to-end processing exactly once.

COMMON MISTAKES

Watch out

  • Avoid assuming broker configuration alone guarantees end-to-end processing exactly once.
  • Assuming rabbitmq and azure service bus concepts guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Design consumers for duplicate delivery.
  • Document broker-specific limits, lock/visibility timeout, and replay operations.

SENIOR-LEVEL SCENARIO

Production thinking

A consumer crashes after charging a card but before acknowledging. The broker redelivers; a stable message ID and idempotent payment operation prevent a second charge.

SUMMARY

In one minute

A broker transports and stores work; application correctness still depends on consumer behavior and explicit delivery semantics.
