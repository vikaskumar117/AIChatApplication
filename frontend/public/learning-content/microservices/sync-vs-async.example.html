APPLY THE IDEA

Worked example

A checkout synchronously checks an authorization decision, but asynchronously requests a shipping label after the order is accepted.

  1. Ask whether the caller needs the answer to complete its operation.
  2. For sync, propagate a bounded deadline.
  3. For async, persist intent and define how consumers report failure.
  4. Communicate pending and eventual status to clients when needed.

Try it

var decision = await risk.CheckAsync(order, deadlineToken);
if (!decision.Allowed) return Results.Conflict();
await bus.PublishAsync(new OrderAccepted(order.Id), deadlineToken);

TRADE-OFFS

Benefits and limitations

Benefits

  • Sync is straightforward when the response is required immediately.
  • Async can absorb bursts and decouple producer availability from consumer availability.

Limitations

  • Sync dependency chains add latency and amplify outages.
  • Async adds queues, delayed results, duplicate delivery, ordering concerns, and harder tracing.

DECISION GUIDE

When to use it

Use: Use synchronous communication for bounded immediate decisions and async for deferrable work.

Avoid: Avoid async solely to hide slow work when the caller still needs the result before responding.

COMMON MISTAKES

Watch out

  • Avoid async solely to hide slow work when the caller still needs the result before responding.
  • Assuming synchronous vs asynchronous communication guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Use async for durable, independently processable work.
  • Set queue limits, consumer capacity, and client-visible completion semantics.

SENIOR-LEVEL SCENARIO

Production thinking

A user’s order endpoint times out while a background email eventually sends. Separate order acceptance from email completion and expose status only where business semantics require it.

SUMMARY

In one minute

Sync couples availability in time; async loosens timing but requires explicit delivery and completion semantics.
