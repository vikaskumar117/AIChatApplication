APPLY THE IDEA

Worked example

The order is authoritative for order status; a reporting projection may lag by seconds, while payment authorization remains owned by Payments.

  1. Name authoritative data and tolerated staleness per field.
  2. Expose pending or freshness semantics when they matter.
  3. Use reconciliation and projection rebuilds as designed recovery paths.

CODE OR QUERY

Try it

public sealed record OrderView(Guid Id, string Status, long Version, DateTimeOffset UpdatedAt);
// Client can display "updating" while the projection version catches up.

TRADE-OFFS

Benefits and limitations

Benefits

  • Allows service autonomy and query-optimized local views.
  • Can keep noncritical reads available while consumers catch up.

Limitations

  • Stale views can confuse users or violate hidden assumptions.
  • Reconciliation, replay, and freshness monitoring add operational work.

DECISION GUIDE

When to use it

Use: Use eventual consistency where the business accepts bounded delay and clear intermediate states.

Avoid: Avoid duplicating authoritative writes across services or promising a global read-your-writes guarantee without implementing it.

COMMON MISTAKES

Watch out

  • Avoid duplicating authoritative writes across services or promising a global read-your-writes guarantee without implementing it.
  • Assuming cross-service consistency guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Make write ownership explicit.
  • Measure lag and test replay/rebuild behavior.

INTERVIEW PRACTICE

Common questions

  1. What is an authoritative source of truth?
  2. How do you communicate eventual consistency to clients?
  3. What does reconciliation detect that message delivery metrics may not?

SENIOR-LEVEL SCENARIO

Production thinking

A user confirms an order but the account page still shows the old status. Return the committed order version and let the view report freshness; investigate projection lag without accepting a second order.

SUMMARY

In one minute

Cross-service consistency is an explicit business contract about ownership, stale observations, convergence, and repair.
