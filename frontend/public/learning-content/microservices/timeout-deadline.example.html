APPLY THE IDEA

Worked example

A 900 ms API budget allocates 250 ms to pricing, 400 ms to inventory, and leaves time for validation and response rather than granting each hop 900 ms.

  1. Propagate cancellation and remaining time, not the original full budget.
  2. Leave budget for validation, persistence, and response.
  3. Record timeout location and elapsed duration.

CODE OR QUERY

Try it

using var cts = CancellationTokenSource.CreateLinkedTokenSource(requestAborted);
cts.CancelAfter(remainingBudget);
var result = await client.GetAsync(uri, cts.Token);

TRADE-OFFS

Benefits and limitations

Benefits

  • Bounds latency and resource occupancy.
  • A propagated budget discourages work that cannot affect the response in time.

Limitations

  • Too-short budgets create avoidable failures; too-long budgets tie up capacity.
  • Cancellation may not stop remote work already accepted by a downstream service.

DECISION GUIDE

When to use it

Use: Set budgets from user-facing SLOs and dependency latency distributions.

Avoid: Avoid treating every OperationCanceledException as a dependency timeout.

COMMON MISTAKES

Watch out

  • Avoid treating every OperationCanceledException as a dependency timeout.
  • Assuming timeouts and deadlines guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Use deadlines with bounded retries and idempotent mutations.
  • Reconcile uncertain outcomes for commands with side effects.

INTERVIEW PRACTICE

Common questions

  1. How does a deadline differ from a per-hop timeout?

SENIOR-LEVEL SCENARIO

Production thinking

A mobile client disconnects while a report service is querying downstream systems. Propagate cancellation to safe reads and ensure accepted durable jobs are not accidentally discarded.

SUMMARY

In one minute

Deadlines bound the entire operation; per-hop timeouts and cancellation implement that budget at specific boundaries.
