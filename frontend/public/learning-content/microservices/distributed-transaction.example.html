APPLY THE IDEA

Worked example

Two databases under one tightly controlled application may use a supported transaction coordinator; independent microservices instead commit locally and coordinate with an outbox/saga.

  1. Verify participant and platform support before design approval.
  2. Understand coordinator recovery and in-doubt operations.
  3. Prefer local atomicity with outbox when spanning database and broker.

Try it

await using var tx = await db.Database.BeginTransactionAsync(ct);

db.Outbox.Add(OutboxMessage.For("OrderCreated", order.Id));
await db.SaveChangesAsync(ct);
await tx.CommitAsync(ct);

TRADE-OFFS

Benefits and limitations

Benefits

  • Can provide atomic commit across compatible participants.
  • Simplifies invariants when a genuinely shared transaction boundary is feasible.

Limitations

  • Coordinator and participant support constrain deployment and technology.
  • Coordination can block or reduce availability during failures and lengthen resource locks.

DECISION GUIDE

When to use it

Use: Use only when all participants and infrastructure support the required protocol and failure model.

Avoid: Avoid assuming HTTP calls or a broker publication automatically join a database transaction.

COMMON MISTAKES

Watch out

  • Avoid assuming HTTP calls or a broker publication automatically join a database transaction.
  • Assuming distributed transactions guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Choose the narrowest transaction boundary that protects the invariant.
  • Document operational recovery for prepared or in-doubt transactions.

INTERVIEW PRACTICE

Common questions

SENIOR-LEVEL SCENARIO

Production thinking

An order service wants atomic database update plus broker publish. Since the broker is not in the database transaction, store an outbox row atomically and dispatch it rather than claiming a cross-resource commit.

SUMMARY

In one minute

Distributed transactions can provide atomicity at the cost of coordination and availability; independent services more often need eventual workflows.
