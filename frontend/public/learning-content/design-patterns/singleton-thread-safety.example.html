APPLY THE IDEA

Worked example

A singleton token cache uses ConcurrentDictionary for independent entries but still coordinates expiration updates that span multiple operations.

  1. Minimize shared mutable state.
  2. Use synchronization around the entire invariant, not isolated field access.
  3. Stress-test concurrent creation, update, and eviction paths.

CODE OR QUERY

Try it

private readonly ConcurrentDictionary<string, Token> _tokens = new();
public Token GetOrAdd(string key, Func<string, Token> create) =>
    _tokens.GetOrAdd(key, create);

TRADE-OFFS

Benefits and limitations

Benefits

  • Safe shared state avoids races and inconsistent cross-request behavior.
  • Thread-safe collections support common concurrent access patterns.

Limitations

  • Locks, concurrent collections, and atomicity can add contention or complexity.
  • A thread-safe collection does not make multi-step business invariants atomic.

DECISION GUIDE

When to use it

Use: Use immutable data or proven synchronization appropriate to the invariant.

Avoid: Avoid mutable singleton state when request-scoped or distributed state is the real requirement.

COMMON MISTAKES

Watch out

  • Avoid mutable singleton state when request-scoped or distributed state is the real requirement.
  • Assuming singleton thread safety guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Document concurrency assumptions and ownership.
  • Choose distributed coordination only when cross-process consistency is required.

SENIOR-LEVEL SCENARIO

Production thinking

Concurrent cache misses create duplicate expensive tokens. Use an appropriate single-flight or lazy-value strategy, then define expiry, failure caching, and memory bounds.

SUMMARY

In one minute

Singleton safety depends on concurrent state access and invariant design, not just registration lifetime.
