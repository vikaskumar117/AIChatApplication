APPLY THE IDEA

Worked example

Add a seasonal discount by registering a new policy rather than modifying a growing switch that calculates every discount type.

  1. Base abstractions on repeated real variation.
  2. Specify eligibility, precedence, and fallback.
  3. Add regression tests for existing implementations.

CODE OR QUERY

Try it

public interface IDiscountPolicy { bool AppliesTo(Cart cart); decimal Calculate(Cart cart); }
public sealed class MemberDiscount : IDiscountPolicy
{
    public bool AppliesTo(Cart cart) => cart.IsMember;
    public decimal Calculate(Cart cart) => cart.Subtotal * 0.05m;
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Protects stable paths when well-understood variants are added.
  • Makes each new behavior independently testable.

Limitations

  • Premature extension points constrain later design and add indirection.
  • Some changes alter the abstraction itself and still require existing code edits.

DECISION GUIDE

When to use it

Use: Use for recurring, expected variation with a stable contract.

Avoid: Avoid designing a plugin framework for one speculative exception.

COMMON MISTAKES

Watch out

  • Avoid designing a plugin framework for one speculative exception.
  • Assuming solid: open/closed principle guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Keep the abstraction smaller than the variation it covers.
  • Revisit extension boundaries when new cases challenge the model.

INTERVIEW PRACTICE

Common questions

  1. Does OCP forbid modifying existing code?
  2. What evidence justifies an extension point?
  3. How can a strategy support OCP for discounts?

SENIOR-LEVEL SCENARIO

Production thinking

New discount types arrive often, but the code edits an increasingly risky switch. Introduce a policy abstraction and explicitly define precedence and overlap behavior.

SUMMARY

In one minute

OCP protects stable behavior by isolating known extension points while accepting that abstractions can evolve.
