APPLY THE IDEA

Worked example

Confirming an order changes order status and writes an audit row in one database transaction, then separately publishes an outbox event.

  1. Scope context and transaction to one operation.
  2. Keep commit ownership explicit and commit once where practical.
  3. Use an outbox for database-plus-message intent.

CODE OR QUERY

Try it

await using var tx = await db.Database.BeginTransactionAsync(ct);
order.Confirm();
db.AuditEntries.Add(AuditEntry.For(order));
db.Outbox.Add(OutboxMessage.For("OrderConfirmed", order.Id));
await db.SaveChangesAsync(ct);
await tx.CommitAsync(ct);

TRADE-OFFS

Benefits and limitations

Benefits

  • Keeps related local changes atomic and provides one explicit commit point.
  • Supports batching and change tracking across a use case.

Limitations

  • A unit of work is store-specific and does not span independent remote services by default.
  • Long-lived tracked contexts retain state and can mix unrelated operations.

DECISION GUIDE

When to use it

Use: Use one short-lived unit of work per business operation requiring a coordinated local commit.

Avoid: Avoid holding a database transaction open across network calls or user interaction.

COMMON MISTAKES

Watch out

  • Avoid holding a database transaction open across network calls or user interaction.
  • Assuming unit of work pattern guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Keep database transactions short.
  • Test both commit and rollback behavior for important invariants.

INTERVIEW PRACTICE

SENIOR-LEVEL SCENARIO

Production thinking

An order is saved before its audit record due to two commits. Stage both under one context/transaction and use an outbox for external publication.

SUMMARY

In one minute

A unit of work protects one local commit boundary; distributed side effects require another pattern.
