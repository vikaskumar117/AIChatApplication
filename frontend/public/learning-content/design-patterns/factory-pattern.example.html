APPLY THE IDEA

Worked example

A document importer creates a CSV or JSON parser based on a validated file format.

  1. Keep product selection deterministic and testable.
  2. Fail clearly for unknown or ambiguous formats.
  3. Use DI for stable application wiring and a factory for runtime choice.

CODE OR QUERY

Try it

public interface IImportParser { Task<ImportResult> ParseAsync(Stream input, CancellationToken ct); }
public sealed class ImportParserFactory(IEnumerable<IImportParser> parsers)
{
    public IImportParser For(string format) =>
        parsers.Single(p => p.Supports(format));
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Encapsulates variable or complex construction.
  • Centralizes validation and product-family consistency.

Limitations

  • Can become a service locator or giant switch with hidden dependencies.
  • Adds little value when the type is known and constructor injection suffices.

DECISION GUIDE

When to use it

Use: Use when creation or product selection is genuinely variable or complex.

Avoid: Avoid a factory that resolves arbitrary services or owns unrelated business behavior.

COMMON MISTAKES

Watch out

  • Avoid a factory that resolves arbitrary services or owns unrelated business behavior.
  • Assuming factory pattern guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Return a useful abstraction and keep creation side-effect expectations clear.
  • Avoid adding a factory for a single obvious new operation.

INTERVIEW PRACTICE

Common questions

  1. What does a factory hide from its client?
  2. How is a factory different from a DI container?
  3. When would direct constructor injection be simpler?

SENIOR-LEVEL SCENARIO

Production thinking

New import formats arrive monthly. Add a parser and register it; reject unsupported formats explicitly instead of silently selecting a default parser.

SUMMARY

In one minute

Factories are useful when creation is a real variability point, not just because an object has a constructor.
