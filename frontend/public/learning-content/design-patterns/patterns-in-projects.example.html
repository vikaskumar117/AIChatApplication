APPLY THE IDEA

Worked example

Order placement uses DI to provide an order repository and payment strategy; a logging decorator adds telemetry without changing payment logic.

  1. Follow an actual request across the layers.
  2. Name the unique responsibility each layer owns.
  3. Make transaction and external side-effect boundaries explicit.
  4. Remove wrappers that merely forward every call.

CODE OR QUERY

Try it

public sealed class OrderService(IOrderRepository orders, IPaymentMethod payment)
{
    public async Task PlaceAsync(Order order, CancellationToken ct)
    {
        await payment.PayAsync(order.Payment, ct);
        await orders.AddAsync(order, ct);
    }
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Responsibilities can be isolated and tested at meaningful boundaries.
  • Cross-cutting behavior can be composed without embedding it in every domain class.

Limitations

  • Too many handlers, interfaces, and wrappers make navigation harder.
  • Patterns composed without explicit transaction/error semantics can create correctness gaps.

DECISION GUIDE

When to use it

Use: Use patterns that answer a concrete need in the use case and document ownership.

Avoid: Avoid layering every CRUD action through a pattern stack by default.

COMMON MISTAKES

Watch out

  • Avoid layering every CRUD action through a pattern stack by default.
  • Assuming patterns used together in projects guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Keep composition at the application boundary.
  • Test policy, orchestration, and infrastructure at their appropriate levels.

INTERVIEW PRACTICE

Common questions

  1. Where are implementations composed in a .NET application?
  2. How can decorators add behavior without changing a service?
  3. Who owns the transaction when several patterns participate?

SENIOR-LEVEL SCENARIO

Production thinking

A payment succeeds but order persistence fails. Trace the flow and redesign the transaction/workflow boundary rather than assuming DI or repositories make the two effects atomic.

SUMMARY

In one minute

Patterns work together when responsibilities remain distinct and the use-case flow stays understandable.
