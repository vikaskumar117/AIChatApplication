APPLY THE IDEA

Worked example

OrderService declares an IOrderRepository dependency; the ASP.NET Core composition root registers the EF implementation for the request scope.

  1. Keep required dependencies constructor-visible.
  2. Register lifetimes that match state ownership.
  3. Use explicit scopes in long-lived workers.

CODE OR QUERY

Try it

services.AddScoped<IOrderRepository, EfOrderRepository>();
services.AddScoped<OrderService>();

public sealed class OrderService(IOrderRepository orders)
{
    public Task<Order?> FindAsync(Guid id, CancellationToken ct) => orders.FindAsync(id, ct);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Dependencies are visible and replaceable for testing or configuration.
  • Composition centralizes implementation choice and lifecycle management.

Limitations

  • Container misconfiguration and lifetime mismatch can fail at runtime.
  • Service locator patterns hide dependencies and weaken compile-time clarity.

DECISION GUIDE

When to use it

Use: Use constructor injection for required collaborators and composition-root registration.

Avoid: Avoid resolving arbitrary services from IServiceProvider inside domain logic.

COMMON MISTAKES

Watch out

  • Avoid resolving arbitrary services from IServiceProvider inside domain logic.
  • Assuming dependency injection pattern guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Keep composition in startup/module boundaries.
  • Validate registrations and test important object graphs.
