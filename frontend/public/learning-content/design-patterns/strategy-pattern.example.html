APPLY THE IDEA

Worked example

A shipping quote chooses an eligible carrier strategy using destination, weight, and service constraints, then returns an estimate with its assumptions.

  1. Keep strategy contracts cohesive and deterministic.
  2. Test boundary conditions and selection ambiguity.
  3. Return rich results when quote assumptions matter.

CODE OR QUERY

Try it

public interface IShippingRate
{
    bool Supports(Shipment shipment);
    decimal Quote(Shipment shipment);
}
var strategy = rates.Single(x => x.Supports(shipment));
var quote = strategy.Quote(shipment);

TRADE-OFFS

Benefits and limitations

Benefits

  • Adds a carrier policy without changing unrelated quote logic.
  • Enables direct tests of each algorithm and supports runtime selection.

Limitations

  • Selection rules can become scattered or ambiguous.
  • Additional types and registrations are unnecessary for stable, tiny behavior.

DECISION GUIDE

When to use it

Use: Use when behavior varies by context and alternatives share a meaningful contract.

Avoid: Avoid strategy when one simple expression is clearer and unlikely to vary.

COMMON MISTAKES

Watch out

  • Avoid strategy when one simple expression is clearer and unlikely to vary.
  • Assuming strategy pattern: shipping rate example guarantees outcomes beyond its stated scope.

BEST PRACTICES

In practice

  • Make no-match and tie behavior explicit.
  • Inject strategies through DI rather than constructing them in the caller.

INTERVIEW PRACTICE

Common questions

  1. How does Strategy differ from a conditional?
  2. Where should strategy selection live?
  3. What should happen if multiple strategies match?

SENIOR-LEVEL SCENARIO

Production thinking

A new carrier supports only some postal codes. Its Supports rule and quote tests define eligibility; the selector detects no match rather than silently choosing the wrong carrier.

SUMMARY

In one minute

Strategy is valuable when meaningful algorithms vary at runtime and share a truthful contract.
