APPLY THE IDEA

Worked example

A StringExtensions method can add a domain-specific normalization helper while remaining an ordinary static method under the hood.

  1. Declare a static class and method.
  2. Mark the first parameter with this and a receiver type.
  3. Import the namespace and call using receiver syntax.

CODE OR QUERY

Try it

public static class TextExtensions
{
    public static bool HasContent(this string? value)
        => !string.IsNullOrWhiteSpace(value);
}

string? name = "Mira";
if (name.HasContent())
    Console.WriteLine(name.Trim());

TRADE-OFFS

Benefits and limitations

Benefits

  • Convenient APIs for types you do not own
  • No inheritance or source modification required

Limitations

  • Namespace collisions and hidden static dispatch
  • Overuse fragments behavior across helpers

DECISION GUIDE

When to use it

Use: Use extensions for cohesive stateless helpers and clear call-site readability.

Avoid: Avoid extension methods that pretend to override behavior or hide important dependencies.

COMMON MISTAKES

Watch out

  • Creating ambiguous extensions with common names.
  • Putting unrelated helpers into one giant extension namespace.

BEST PRACTICES

In practice

  • Use specific names and cohesive namespaces.
  • Keep helpers stateless and predictable.
  • Choose instance APIs for owned or overridable behavior.

SENIOR-LEVEL SCENARIO

Production thinking

A shared validation library offers string checks without changing framework types. Place related extensions in a discoverable namespace and avoid ambiguous names.

SUMMARY

In one minute

Extension methods provide static helper behavior with receiver-style syntax, scoped by namespace and compile-time type.
