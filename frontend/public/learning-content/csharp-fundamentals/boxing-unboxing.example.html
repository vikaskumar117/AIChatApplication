APPLY THE IDEA

Worked example

A value type passed to a method taking object is boxed. Prefer a generic method when the type can remain T.

  1. Pass an int to an object-returning method.
  2. Treat the result as object, then cast it to int.
  3. Compare with Echo<T>, which keeps the type parameter.

CODE OR QUERY

Try it

static object Box(int value) => value;
object boxed = Box(42);       // boxing: object contains a copy
int number = (int)boxed;      // unboxing: exact type required

static T Echo<T>(T value) => value;
int noObjectConversion = Echo(42);

TRADE-OFFS

Benefits and limitations

Benefits

  • Required for object/interface compatibility
  • Generic APIs avoid many boxing conversions

Limitations

  • Boxing may allocate and copy
  • Wrong unbox type throws InvalidCastException

DECISION GUIDE

When to use it

Use: Use generics for type-preserving hot paths and collections.

Avoid: Avoid repeatedly boxing values in high-frequency loops without profiling.

COMMON MISTAKES

Watch out

  • Assuming unboxing accepts numeric conversion between different types.
  • Assuming every interface call boxes every struct in every context.

BEST PRACTICES

In practice

  • Use generic APIs for typed collections and algorithms.
  • Profile allocation hot spots before changing readable code.
  • Keep casts at explicit, validated interop boundaries.

INTERVIEW PRACTICE

Common questions

  1. What is copied during boxing?
  2. Why must unboxing name the exact value type?
  3. How do generics reduce boxing?

SENIOR-LEVEL SCENARIO

Production thinking

A telemetry loop shows allocation spikes from formatting numeric values through object-based APIs. Use typed overloads or generic APIs, then verify allocation reduction with a profiler.

SUMMARY

In one minute

Boxing stores a value copy in an object representation; unboxing validates and extracts the matching value type.
