APPLY THE IDEA

Worked example

A List<int> prevents inserting a string and returns an int without casting; ArrayList accepts both and fails when the caller assumes the wrong type.

  1. Add integers to List<int> and consume them without conversion.
  2. Add mixed values to ArrayList.
  3. Cast each value and observe the runtime risk.

CODE OR QUERY

Try it

var typed = new List<int> { 1, 2 };
int total = typed[0] + typed[1];

var untyped = new System.Collections.ArrayList { 1, "two" };
int first = (int)untyped[0]; // runtime cast required
// int second = (int)untyped[1]; // InvalidCastException

TRADE-OFFS

Benefits and limitations

Benefits

  • Compile-time guarantees
  • No casts at typed call sites

Limitations

  • Object collections can represent mixed data
  • Casts and value boxing add risk and possible overhead

DECISION GUIDE

When to use it

Use: Prefer generic collections and APIs when a collection has a known element type.

Avoid: Avoid object as a shortcut for missing domain modeling.

COMMON MISTAKES

Watch out

  • Casting every object without validating its runtime type.
  • Using object to avoid designing a stable message contract.

BEST PRACTICES

In practice

  • Choose generic collections for homogeneous data.
  • Represent variants explicitly and validate at boundaries.
  • Keep object-based interop isolated.

INTERVIEW PRACTICE

Common questions

  1. What error is detected earlier by List<T>?
  2. Why can object store an int but require a cast?
  3. When is heterogeneity a real requirement?

SENIOR-LEVEL SCENARIO

Production thinking

An event pipeline handles several message types. Prefer a shared message contract or explicit tagged variants rather than object payloads that consumers blindly cast.

SUMMARY

In one minute

Generic APIs preserve element type and catch errors early; object APIs defer correctness to runtime casts.
