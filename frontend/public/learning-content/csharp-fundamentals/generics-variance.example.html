APPLY THE IDEA

Worked example

A repository can return Customer objects directly rather than returning object values that every caller must cast.

  1. Declare the type parameter T.
  2. Add only constraints the implementation actually needs.
  3. Implement and call the closed IRepository<Customer> type.

CODE OR QUERY

Try it

public interface IEntity { Guid Id { get; } }
public interface IRepository<T> where T : IEntity
{
    Task<T?> FindAsync(Guid id, CancellationToken cancellationToken);
}
public interface IProducer<out T> { T Get(); }
public interface IConsumer<in T> { void Accept(T value); }

public sealed record Customer(Guid Id, string Name) : IEntity;
public sealed class CustomerRepository : IRepository<Customer>
{
    public Task<Customer?> FindAsync(Guid id, CancellationToken cancellationToken)
        => Task.FromResult<Customer?>(new Customer(id, "Mira"));
}

public static class Program
{
    public static void Main()
    {
        IEnumerable<string> names = new List<string>();
        IEnumerable<object> objects = names; // covariance
        Action<object> logObject = value => Console.WriteLine(value);
        Action<string> logString = logObject; // contravariance
    }
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Reusable compile-time type safety
  • Constraints document required capabilities

Limitations

  • Complex constraints can obscure APIs
  • Over-generalized frameworks are harder to evolve

DECISION GUIDE

When to use it

Use: Use generics when behavior is genuinely reusable across types and preserve precise type information.

Avoid: Avoid generic abstractions whose type parameters do not affect meaningful behavior.

COMMON MISTAKES

Watch out

  • Using object inside a generic class and losing type safety.
  • Adding constraints that are unrelated to the algorithm.
  • Creating a universal repository that hides domain queries.

BEST PRACTICES

In practice

  • Prefer type-safe inputs and outputs.
  • Constrain to required capabilities, not a particular implementation.
  • Test generic behavior with representative types.

INTERVIEW PRACTICE

Common questions

SENIOR-LEVEL SCENARIO

Production thinking

A persistence library supports several entity types. Keep generic CRUD operations constrained by actual requirements and keep domain-specific queries explicit.

SUMMARY

In one minute

Generics provide reusable APIs that retain concrete type information and enable compiler-checked constraints.
