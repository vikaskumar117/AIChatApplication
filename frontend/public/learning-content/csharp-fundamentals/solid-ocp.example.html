APPLY THE IDEA

Worked example

Discount calculation varies by campaign. A strategy contract lets a new campaign implement its rule without expanding a checkout switch.

  1. Define policy behavior required by checkout.
  2. Implement one discount strategy.
  3. Add another strategy via composition rather than another checkout branch.

CODE OR QUERY

Try it

public interface IDiscountPolicy { decimal Apply(decimal subtotal); }
public sealed class NoDiscount : IDiscountPolicy
{
    public decimal Apply(decimal subtotal) => subtotal;
}
public sealed class PercentageDiscount : IDiscountPolicy
{
    private readonly decimal rate;
    public PercentageDiscount(decimal rate) => this.rate = rate;
    public decimal Apply(decimal subtotal) => subtotal * (1 - rate);
}
public sealed class Checkout
{
    private readonly IDiscountPolicy discount;
    public Checkout(IDiscountPolicy discount) => this.discount = discount;
    public decimal Total(decimal subtotal) => discount.Apply(subtotal);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • New variants have localized implementation
  • Stable client code changes less

Limitations

  • Abstraction has upfront cost
  • Configuration/plugin systems can become opaque

DECISION GUIDE

When to use it

Use: Apply OCP where variation is real and recurring.

Avoid: Avoid building speculative plugin architectures for a single stable branch.

COMMON MISTAKES

Watch out

  • A large type switch that grows with every variant.
  • An abstract framework for variants that do not exist.

BEST PRACTICES

In practice

  • Use observed change pressure to select extension points.
  • Keep invariants and validation explicit.
  • Test each strategy and the composition boundary.

INTERVIEW PRACTICE

Common questions

  1. Does OCP forbid modifying code?
  2. When should a switch become a strategy?
  3. How can extension points become over-engineering?

SENIOR-LEVEL SCENARIO

Production thinking

A promotion platform adds campaign rules monthly. Register validated discount strategies and keep checkout stable; do not make payment invariants pluggable without a requirement.

SUMMARY

In one minute

OCP localizes expected variation behind stable contracts without pretending existing code must never change.
