APPLY THE IDEA

Worked example

A checkout calls IPaymentMethod.PayAsync without depending on card internals; the adapter encapsulates provider details, and a derived provider may specialize implementation only where appropriate.

  1. Validate the checkout invariant before calling collaborators.
  2. Depend on the payment capability rather than a concrete provider.
  3. Substitute an implementation without changing checkout policy.

CODE OR QUERY

Try it

public interface IPaymentMethod
{
    Task PayAsync(decimal amount, CancellationToken cancellationToken);
}
public sealed class Checkout
{
    private readonly IPaymentMethod payment;
    public Checkout(IPaymentMethod payment) => this.payment = payment;
    public Task CompleteAsync(decimal total, CancellationToken token)
    {
        if (total <= 0) throw new ArgumentOutOfRangeException(nameof(total));
        return payment.PayAsync(total, token);
    }
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Protects business invariants
  • Enables implementation substitution

Limitations

  • Inheritance can over-couple designs
  • Excessive abstraction hides simple flows

DECISION GUIDE

When to use it

Use: Use encapsulation to protect invariants, abstraction for meaningful boundaries, and polymorphism for interchangeable behavior.

Avoid: Avoid inheritance solely to share code; prefer composition when behavior is assembled.

COMMON MISTAKES

Watch out

  • Exposing mutable state and relying on callers to preserve invariants.
  • Creating deep class hierarchies for code reuse alone.

BEST PRACTICES

In practice

  • Keep invariants near the state or operation they protect.
  • Design contracts around client needs.
  • Favor composition where behavior varies independently.

INTERVIEW PRACTICE

Common questions

  1. Name the four OOP pillars.
  2. How is abstraction different from encapsulation?
  3. Does polymorphism require inheritance from a class?

SENIOR-LEVEL SCENARIO

Production thinking

A checkout system supports multiple payment methods and must enforce positive totals. Keep validation in the domain-facing service and provider protocol inside replaceable adapters.

SUMMARY

In one minute

OOP principles help protect rules and substitute behavior; they are tools, not reasons to build inheritance-heavy frameworks.
