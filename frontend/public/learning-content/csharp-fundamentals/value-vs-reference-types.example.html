APPLY THE IDEA

Worked example

Copying a struct with a List field copies the list reference, not the list contents; value copying does not make an object graph deeply independent.

  1. Create a struct containing a List reference.
  2. Copy the struct value.
  3. Mutate the list and observe shared referenced state.

CODE OR QUERY

Try it

public struct CartView
{
    public List<string> Items;
}

var original = new CartView { Items = new() { "book" } };
var copy = original;       // struct fields are copied
copy.Items.Add("pen");     // both fields reference the same List
Console.WriteLine(original.Items.Count); // 2

TRADE-OFFS

Benefits and limitations

Benefits

  • Value copies avoid shared top-level state
  • References allow shared object identity

Limitations

  • Aliasing can cause unintended shared mutation
  • Large value copies can be expensive

DECISION GUIDE

When to use it

Use: Explain assignment semantics at API boundaries and prefer immutable values when copy behavior should be simple.

Avoid: Avoid teaching or optimizing with an absolute “value=stack, reference=heap” rule.

COMMON MISTAKES

Watch out

  • Assuming a struct copy recursively duplicates all objects.
  • Assuming every local reference necessarily allocates or stays on the heap.

BEST PRACTICES

In practice

  • Use immutable value types for predictable copying.
  • Make mutable shared ownership explicit.
  • Use memory profiling for layout and allocation questions.

INTERVIEW PRACTICE

Common questions

  1. What does assigning a reference type copy?
  2. Can a value type contain a reference?
  3. Why does a struct copy not imply deep copy?

SENIOR-LEVEL SCENARIO

Production thinking

A cache returns a mutable DTO shared between requests. Decide whether callers need an independent snapshot; copy or expose immutable values rather than relying on class/struct labels.

SUMMARY

In one minute

Value types copy their fields; reference variables copy object references, and either type can participate in more complex memory layouts.
