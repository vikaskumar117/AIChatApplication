APPLY THE IDEA

Worked example

TryParse uses out because there may be no parsed result on entry; ref would misleadingly imply a meaningful initialized value.

  1. Call Increment with ref to update the existing count.
  2. Call TryPercent with out to receive its result.
  3. Pass values with in to the readonly Sum method.

CODE OR QUERY

Try it

static bool TryPercent(string text, out int value)
    => int.TryParse(text, out value);

static void Increment(ref int value) => value++;
static int Sum(in int left, in int right) => left + right;

int count = 3;
Increment(ref count);
if (TryPercent("42", out var parsed))
    Console.WriteLine(Sum(in count, in parsed));

TRADE-OFFS

Benefits and limitations

Benefits

  • Efficient large readonly values
  • Clear Try-pattern output

Limitations

  • Call-site coupling and aliasing
  • Ref-like types impose escape and async restrictions

DECISION GUIDE

When to use it

Use: Use out for a Try-style output and ref only when caller-visible mutation is essential.

Avoid: Avoid ref/out/in for ordinary small values or using ref as an unmeasured optimization.

COMMON MISTAKES

Watch out

  • Using out when input value is meaningful.
  • Assuming in prohibits mutation of an object reached through the reference.

BEST PRACTICES

In practice

  • Use the Try pattern for conditional results.
  • Keep mutation explicit and narrow.
  • Respect ref-like lifetime and async restrictions.

INTERVIEW PRACTICE

Common questions

  1. Why does out not require initialization?
  2. Does in make an object graph immutable?
  3. What is the difference between ref and out?

SENIOR-LEVEL SCENARIO

Production thinking

A numeric API handles large immutable structs. Keep scalar results as returns, use out for parse success, and benchmark in only where avoiding a copy matters.

SUMMARY

In one minute

ref reads and writes an initialized variable, out must assign a result, and in provides readonly by-reference input.
