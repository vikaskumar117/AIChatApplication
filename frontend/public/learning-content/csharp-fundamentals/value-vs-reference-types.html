Value Types vs Reference Types in C#

Learn how C# stores, copies, and passes data. This concept controls predictable method behavior, memory usage, mutation, equality, exception handling, and performance in real .NET applications.

1. What Is the Difference?

A value type stores its data directly in a variable. When it is assigned or passed to a method, C# normally creates a copy of that data.

A reference type stores a reference, or address, to an object on the managed heap. Assigning or passing a reference variable normally copies the reference, not the complete object.

Value variable: holds data
Assignment: copies data
Reference variable: holds address
Assignment: copies address
Interview definition: A value type represents a value and is copied; a reference type represents an object identity and is accessed through a reference. Both categories follow their own copy, mutation, and equality semantics.

2. Why Do We Need to Understand This?

Two methods can receive the same visible value and behave differently: changing a value-typed argument may not change the caller, while changing an object through a reference-typed argument may change shared state.

  • Prevents accidental mutation of shared objects.
  • Explains why method parameters sometimes appear unchanged.
  • Helps choose the correct type for small immutable values.
  • Improves API design and code-review decisions.
  • Reduces confusion about aliases, equality, boxing, and copying.

3. Real-World Analogy

Think of a value type like a printed bank cheque: copying the cheque creates a separate piece of paper. Editing the copy does not change the original.

A reference type is like sharing a house address: two people can hold different copies of the address but both can visit and modify the same house. The address is copied; the house is shared.

5. Simple C# Example

int firstNumber = 10;
int secondNumber = firstNumber;

secondNumber = 20;

Console.WriteLine(firstNumber);   // 10
Console.WriteLine(secondNumber);  // 20

var firstOrder = new Order { Total = 100m };
var secondOrder = firstOrder;

secondOrder.Total = 250m;

Console.WriteLine(firstOrder.Total);   // 250
Console.WriteLine(secondOrder.Total);  // 250

public class Order
{
    public decimal Total { get; set; }
}

The integer assignment copies 10 into a separate variable. The order assignment copies only the reference, so both variables refer to the same Order object.

6. How Copying Works Internally

1. Variable is declared
2. Value or reference is stored
3. Assignment occurs
4. Value or address is copied
5. Variables are read or mutated

The CLR manages object allocation and garbage collection for reference types. A reference variable does not itself contain the complete object. It contains information that lets the runtime locate the object.

A value type can be stored in a stack frame, inline inside another object, in an array, or in a reference-type field. Saying that value types are “always on the stack” is therefore an incomplete interview answer.

7. Method Parameters

By default, C# passes both value types and references by value. The important distinction is what is being passed: a copied value or a copied reference. 

void UpdateInt(int value)
{
    value = 50;
}

void UpdateOrder(Order order)
{
    order.Total = 50m;
}

void ReplaceOrder(Order order)
{
    order = new Order { Total = 75m };
}

var quantity = 10;
var currentOrder = new Order { Total = 100m };

UpdateInt(quantity);
UpdateOrder(currentOrder);
ReplaceOrder(currentOrder);

Console.WriteLine(quantity);       // 10
Console.WriteLine(currentOrder.Total); // 50

UpdateInt changes only its parameter copy. UpdateOrder follows the shared reference and mutates the caller’s object. ReplaceOrder assigns a new object only to the parameter copy of the reference, so the caller’s variable still points to the original object.

8. ref, out, and in

Normal parameter passing copies the argument value or reference. The ref, out, and in modifiers change how the parameter is connected to the caller.

Modifier Caller Variable Method Return Relationship Typical Use
ref Must be initialized Method may read and update the same variable In-place updates and Try-style APIs
out Does not need to be initialized Method must assign it before returning Returning success plus an output value
in Usually initialized by the caller Method cannot reassign or modify the argument Readonly large struct passing 
bool TryParseAmount(string text, out decimal amount)
{
    amount = 0m;
    return decimal.TryParse(text, out amount);
}

void ApplyDiscount(ref decimal total, decimal discount)
{
    total -= discount;
}

decimal total = 500m;
ApplyDiscount(ref total, 50m);

if (TryParseAmount("125.50", out decimal parsedAmount))
{
    Console.WriteLine(parsedAmount);
}

9. Mutable and Immutable Types

The reference-versus-value distinction is not identical to mutable-versus- immutable. A reference type can be immutable, and a value type can contain mutable reference fields. 

public readonly record struct Money(decimal Amount, string Currency);

public sealed class Customer
{
    public required string Name { get; init; }
    public required IReadOnlyList<string> Tags { get; init; }
}

Money is a value type with immutable fields. Customer is a reference type, and changing or sharing its Tags collection can still introduce mutable alias behavior unless the collection itself is safely copied or made read-only.

10. Equality Is a Separate Concept

Value types usually use value-oriented equality. Two values are equal if their meaningful fields have equal values. Reference types usually default to reference equality, meaning the same object instance is required. 

var pointA = new Point(10, 20);
var pointB = new Point(10, 20);

Console.WriteLine(pointA == pointB); // true for a record struct

var firstOrder = new Order { Id = 101 };
var secondOrder = new Order { Id = 101 };

Console.WriteLine(firstOrder == secondOrder); // false for a normal class

public readonly record struct Point(int X, int Y);

public class Order
{
    public int Id { get; init; }
}

11. Enterprise Example: Order Calculation

In an ASP.NET Core service, immutable money values can be passed around without changing caller state. Mutable entities can represent persistence identity and require a clear unit-of-work boundary. 

public readonly record struct Money(decimal Amount, string Currency)
{
    public Money
    {
        if (Amount < 0)
            throw new ArgumentOutOfRangeException(nameof(Amount));
        if (string.IsNullOrWhiteSpace(Currency))
            throw new ArgumentException("Currency is required.", nameof(Currency));
    }
}

public sealed class Order
{
    public Guid Id { get; init; }
    public decimal Total { get; private set; }

    public void ApplyDiscount(decimal discount)
    {
        if (discount < 0 || discount > Total)
            throw new ArgumentOutOfRangeException(nameof(discount));

        Total -= discount;
    }
}

public sealed class OrderCalculator
{
    public Money Calculate(Money subtotal, decimal taxRate)
    {
        var tax = subtotal.Amount * taxRate;
        return new Money(subtotal.Amount + tax, subtotal.Currency);
    }
}

Money is best represented as a small immutable value. Order is a stateful entity and belongs as a reference type because mutations occur over time and the object has identity.

13. Boxing and Unboxing

Boxing converts a value type to an object or interface reference. The CLR creates a heap object containing the value. Unboxing extracts the value and verifies its type. 

object value = 42;        // Boxing
int number = (int)value;  // Unboxing

// May box in some overload resolution paths.
PrintValue(42);

void PrintValue(object? value)
{
    Console.WriteLine(value);
}
Performance note: Repeated boxing in hot paths causes allocations and type checking. Prefer generics, overloads, and value-aware APIs instead of treating object as a general-purpose data container.

14. Common Interview Questions

  1. What is the difference between a value type and a reference type? A value type stores its data directly and is copied by value. A reference type stores a reference to a heap object and normally copies that reference.
  2. Is every value type stored on the stack? No. Storage location depends on context. A struct can be contained inside an object or array and exist in heap-backed storage.
  3. What happens when an object reference is assigned to another variable? Both variables can refer to the same instance. Mutating the object through either reference affects the shared object.
  4. Are method parameters passed by reference? No by default. C# passes parameter values normally, but the parameter value can be a reference to an object.
  5. Why are large structs sometimes passed with in? in communicates that the argument will not be modified and can avoid unnecessary copying for large readonly structs.
  6. What is boxing? It wraps a value type in a heap object or interface reference.
  7. When should you prefer a class over a struct? Prefer a class for identity, mutable lifecycle, inheritance, or objects larger than a few fields.
  8. Can a struct contain reference types? Yes. The struct itself is copied, but its reference fields can still point to shared objects.
  9. How does null apply? Ordinary reference types can be null; ordinary value types cannot without a nullable wrapper such as int?.
  10. What is an alias in C#? An alias is a second variable or property that refers to the same object as another reference.

15. Challenging Senior-Level Scenario

A pricing service exposes a DiscountRequest object and returns a mutable Money struct from a collection. Engineers report inconsistent totals because a method changes a field in the struct copy returned from a dictionary.

Senior solution: Use immutable value objects for Money, return them through complete DTO or record APIs, and keep mutable entities inside an explicit application or unit-of-work boundary. Do not solve aliasing with a defensive copy everywhere unless ownership and mutation requirements justify it.

16. Common Mistakes

Mistake Why It Is Wrong Correction
“All structs are faster than classes.” Copying large structs can cost more than copying references. Measure and prefer small, meaningful immutable structs.
Making every DTO a struct Large or mutable structs create surprising copy behavior. Use classes or records based on identity and mutation needs.
Assuming assignment clones an object Classes copy references, not the complete object. Use explicit clone or copy methods when independent state is required.
Using object for hot-loop values Boxing creates heap allocations. Use generics or typed overloads.
Ignoring reference fields inside structs The struct copy may share mutable arrays or collections. Make the complete value immutable or use a class.

17. When to Use Each

Use a Value Type Use a Reference Type
Small immutable measurements or coordinates. Mutable domain entities with identity.
Business values such as money, range, or postal coordinates. Objects requiring inheritance or polymorphism.
A value has no null lifecycle meaning. Object lifetime or shared state must be represented.
Equality means field values are equal. Equality means object identity unless explicitly customized.

19. 60-Second Interview Answer

In C#, value types store their data directly and assignments normally copy the value, while reference types store references to managed heap objects and assignments copy the reference. Because C# passes parameters by value by default, a reference parameter still copies the reference, allowing methods to mutate the shared object but not replace the caller’s variable. Value types are good for small immutable domain values, while classes are better for identity and mutable lifecycle. Equality, mutability, storage, and boxing are separate decisions. Senior developers should choose types based on domain semantics and avoid assumptions about every struct being faster or every object being a heap allocation detail.

20. Key Takeaways

  • Assignment copies a value or copies a reference.
  • Parameters are normally passed by value, even for reference types.
  • Reference variables can be aliases for the same mutable object.
  • Do not say that all value types are always stored on the stack.
  • Use classes for identity and mutable lifecycles.
  • Use small immutable structs or records for meaningful value concepts.
  • Use ref, out, and in deliberately.
  • Test performance-sensitive code instead of assuming struct or class is faster.
