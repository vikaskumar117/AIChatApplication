APPLY THE IDEA

Worked example

An incident review correlates slow order requests with a database span by trace ID and route template.

  1. Capture safe request context
  2. Run downstream application work
  3. Record status, duration, and correlation

CODE OR QUERY

Try it

var started = Stopwatch.GetTimestamp();
await next(context);
logger.LogInformation("HTTP {Method} {Route} {Status} in {ElapsedMs}ms TraceId={TraceId}",
    context.Request.Method, context.GetEndpoint()?.DisplayName,
    context.Response.StatusCode, Stopwatch.GetElapsedTime(started).TotalMilliseconds,
    context.TraceIdentifier);

TRADE-OFFS

Benefits and limitations

Benefits

  • Consistent request-level operational context
  • Supports latency analysis and cross-service investigation

Limitations

  • High-volume logs and high-cardinality fields raise cost
  • Over-collection can expose secrets or personal data

DECISION GUIDE

When to use it

Use: Use structured framework logging and tracing with reviewed fields, sampling, retention, and access controls.

Avoid: Avoid logging authorization headers, tokens, passwords, full bodies, or raw user identifiers without a documented need and safeguards.

COMMON MISTAKES

Watch out

  • Logging bearer tokens or entire bodies for convenience.
  • Using raw URLs or user input as unbounded metric labels.

BEST PRACTICES

In practice

  • Define redaction, retention, and access policies for telemetry.
  • Prefer standard ASP.NET Core diagnostics and OpenTelemetry instrumentation.

INTERVIEW PRACTICE

Common questions

  1. Why log route templates rather than raw paths?
  2. How do trace IDs help across services?
  3. Why not log every request body?

SENIOR-LEVEL SCENARIO

Production thinking

p95 latency worsens while logs grow; sample noisy low-value routes, correlate traces with dependency spans, and remove sensitive high-cardinality dimensions.

In one minute
