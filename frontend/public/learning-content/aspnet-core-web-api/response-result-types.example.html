APPLY THE IDEA

Worked example

A lookup returns ActionResult<ProductDto> so the success schema is visible while the action can also return 404.

  1. Action selects typed result
  2. MVC executes result and formatter
  3. Status, headers, and body are emitted

CODE OR QUERY

Try it

[HttpGet("{id:int}")]
public async Task<ActionResult<ProductDto>> Get(int id, CancellationToken ct)
{
    var product = await service.FindAsync(id, ct);
    return product is null ? NotFound() : Ok(product);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Typed success contracts clarify API output
  • Action results express status and header behavior

Limitations

  • Broad IActionResult hides response schemas unless documented
  • Implicit conversions can obscure response construction

DECISION GUIDE

When to use it

Use: Use ActionResult<T> for controller endpoints with a primary representation and a few explicit HTTP alternatives.

Avoid: Avoid returning object or IActionResult everywhere without documenting possible status and body contracts.

COMMON MISTAKES

Watch out

  • Returning a DTO with an accidental 200 for a missing resource.
  • Assuming a return type alone documents every error response.

BEST PRACTICES

In practice

  • Declare response metadata for success and relevant errors.
  • Use CreatedAtAction for resource creation and NoContent when no representation is returned.

SENIOR-LEVEL SCENARIO

Production thinking

A generated client cannot determine the success schema because actions return object; replace it with explicit DTO return types and document non-success responses.

SUMMARY

In one minute

Action return types communicate whether an endpoint returns a representation, several HTTP outcomes, or a framework-level result.
