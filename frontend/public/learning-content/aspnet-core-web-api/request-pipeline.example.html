APPLY THE IDEA

Worked example

Exception handling wraps authentication and controller execution; authentication establishes the user before authorization checks access.

  1. Request enters early middleware
  2. Routing, auth, and endpoint execute
  3. Response unwinds toward server

CODE OR QUERY

Try it

app.UseExceptionHandler();
app.UseHttpsRedirection();
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

TRADE-OFFS

Benefits and limitations

Benefits

  • Compositional cross-cutting behavior
  • Explicit ordering makes request lifecycle understandable

Limitations

  • Misordering can bypass policies or prevent exception handling
  • Each component can add latency or alter the response

DECISION GUIDE

When to use it

Use: Use middleware for application-wide behavior and verify ordering against the features each component depends on.

Avoid: Avoid placing authentication after endpoints or placing exception handling so late that earlier failures escape it.

COMMON MISTAKES

Watch out

  • Assuming registration order is irrelevant.
  • Putting endpoint-specific business decisions in global middleware.

BEST PRACTICES

In practice

  • Keep a concise, reviewed pipeline in Program.cs.
  • Add integration tests for middleware order, short-circuiting, and exceptions.

INTERVIEW PRACTICE

Common questions

  1. What does calling next mean?
  2. Why does middleware order matter?
  3. Where should authentication and authorization appear?

SENIOR-LEVEL SCENARIO

Production thinking

A new authorization requirement sees no authenticated user; inspect the actual pipeline and move authentication ahead of authorization while testing both anonymous and authenticated requests.

SUMMARY

In one minute

The ordered middleware pipeline surrounds endpoint execution, so ordering determines which components can observe and affect a request.
