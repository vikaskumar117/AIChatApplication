APPLY THE IDEA

Worked example

Attach a trace identifier to structured logs for every request, including requests that later fail.

  1. Inspect request context
  2. Continue or intentionally short-circuit
  3. Observe or finalize response

CODE OR QUERY

Try it

app.Use(async (context, next) =>
{
    var started = Stopwatch.GetTimestamp();
    await next(context);
    logger.LogInformation("HTTP {Status} took {Elapsed}ms",
        context.Response.StatusCode,
        Stopwatch.GetElapsedTime(started).TotalMilliseconds);
});

TRADE-OFFS

Benefits and limitations

Benefits

  • One implementation covers many endpoints
  • Can operate before and after endpoint execution

Limitations

  • Global scope can make endpoint-specific behavior awkward
  • Incorrect lifetime use or body buffering can cause bugs and cost

DECISION GUIDE

When to use it

Use: Use custom middleware when the same HTTP concern must consistently wrap a broad part of the application.

Avoid: Avoid storing request state in middleware instance fields or reading request bodies without deliberate buffering, limits, and privacy review.

COMMON MISTAKES

Watch out

  • Calling next twice or failing to await downstream processing.
  • Keeping mutable request data in a long-lived middleware field.

BEST PRACTICES

In practice

  • Use framework-provided diagnostics when they already meet the need.
  • Keep middleware stateless and pass cancellation and request context through.

INTERVIEW PRACTICE

Common questions

  1. How does middleware continue the pipeline?
  2. What does short-circuit mean?
  3. Where should request-specific state live?

SENIOR-LEVEL SCENARIO

Production thinking

Add a correlation header even on controlled errors; place middleware before exception and endpoint processing, preserve an existing trace ID only when validated, and test header behavior after response start.

SUMMARY

In one minute

Middleware is an HTTP delegate that can inspect, transform, short-circuit, or delegate request processing.
