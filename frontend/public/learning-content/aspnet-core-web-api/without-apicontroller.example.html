APPLY THE IDEA

Worked example

A legacy action may execute with invalid ModelState unless it checks ModelState.IsValid or adopts the API controller convention.

  1. Request matches controller route
  2. MVC binds parameters and records errors
  3. Action or explicit convention handles outcome

CODE OR QUERY

Try it

if (!ModelState.IsValid)
    return ValidationProblem(ModelState);
var result = await service.CreateAsync(request, ct);

TRADE-OFFS

Benefits and limitations

Benefits

  • Allows explicit legacy or specialized MVC behavior
  • Useful where the API controller conventions are intentionally not desired

Limitations

  • More repeated validation and binding decisions
  • Clients may see inconsistent errors between controllers

DECISION GUIDE

When to use it

Use: Use an unadorned controller when you intentionally own binding and validation response behavior.

Avoid: Avoid assuming that data annotations alone guarantee an automatic 400 response on an ordinary controller.

COMMON MISTAKES

Watch out

  • Equating missing [ApiController] with no model binding.
  • Assuming invalid annotations always stop an ordinary controller action.

BEST PRACTICES

In practice

  • Test malformed JSON, missing values, and annotation failures at the HTTP boundary.
  • Document deliberate exceptions to shared validation conventions.

INTERVIEW PRACTICE

Common questions

  1. Can a controller route work without [ApiController]?
  2. What should the action do with invalid ModelState?
  3. How would you migrate legacy behavior safely?

SENIOR-LEVEL SCENARIO

Production thinking

A service returns 200 for invalid request objects in one legacy controller; add explicit validation handling and integration tests before moving it to shared API conventions.

SUMMARY

In one minute

A controller without [ApiController] can still serve an API, but it does not receive that attribute’s API-specific conventions automatically.
