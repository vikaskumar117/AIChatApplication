APPLY THE IDEA

Worked example

An order service matches two ledger adjustments to a reconciliation total. The problem contract must define whether values can be reused, whether multiple answers exist, and what to return when no pair is found.

  1. Input [3, 7, 4], target 10.
  2. At index 0, complement 7 is absent; store 3 → 0.
  3. At index 1, complement 3 is present; return [0, 1].

CODE OR QUERY

Try it

int[] TwoSum(int[] values, int target)
{
    var indexByValue = new Dictionary<int, int>();

    for (int index = 0; index < values.Length; index++)
    {
        int complement = target - values[index];
        if (indexByValue.TryGetValue(complement, out int otherIndex))
            return [otherIndex, index];

        indexByValue[values[index]] = index;
    }

    return [];
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Expected O(n) time with one pass
  • Returns original indices without sorting the input

Limitations

  • Uses O(n) auxiliary memory
  • Integer overflow and no-solution behavior must match the problem contract

DECISION GUIDE

When to use it

Use: Use when extra memory is acceptable and the input is a one-shot search.

Avoid: Avoid if memory is tightly bounded or sorted input allows a two-pointer approach that fits the required output.

COMMON MISTAKES

Watch out

  • Storing values but not indices when the answer requires positions.
  • Inserting first can allow the same array element to satisfy its own complement.
  • Ignoring integer overflow when target/value ranges are large.

BEST PRACTICES

In practice

  • Specify duplicate, no-answer, and multiple-answer behavior.
  • Use wider arithmetic if the input domain can overflow int.
  • Test negative values, duplicate values, and a single-element input.

INTERVIEW PRACTICE

Common questions

  1. Why check the complement before inserting the current value?
  2. How do duplicate values work?
  3. What are the time and space complexities?
  4. What changes if the input is already sorted?

SENIOR-LEVEL SCENARIO

Production thinking

A reconciliation job processes large, untrusted batches with a 32-bit target. Define overflow behavior (for example, calculate in `long`), cap batch size, and test duplicates and missing matches before production.

SUMMARY

In one minute

A complement lookup turns the nested search into one expected-linear scan by trading extra memory for speed.
