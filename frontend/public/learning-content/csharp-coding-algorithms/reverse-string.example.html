APPLY THE IDEA

Worked example

A log-normalization utility reverses a short ASCII token for a coding exercise. In production, clarify whether “character” means UTF-16 code unit, Unicode scalar value, or user-perceived grapheme cluster.

  1. Start with [c, o, d, e], left = 0, right = 3.
  2. Swap c/e; then swap o/d.
  3. Pointers cross, so stop and return "edoc".

CODE OR QUERY

Try it

string Reverse(string value)
{
    char[] characters = value.ToCharArray();
    int left = 0;
    int right = characters.Length - 1;

    while (left < right)
    {
        (characters[left], characters[right]) = (characters[right], characters[left]);
        left++;
        right--;
    }

    return new string(characters);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Linear time with a straightforward invariant
  • Original string remains unchanged

Limitations

  • The result requires O(n) additional memory
  • char-based reversal can split a surrogate pair or grapheme cluster

DECISION GUIDE

When to use it

Use: Use the two-pointer version when the input contract is ASCII or UTF-16 code-unit based.

Avoid: Avoid claiming this reverses user-perceived Unicode characters; use text-element-aware processing when that is the actual requirement.

COMMON MISTAKES

Watch out

  • Using `left <= right` is valid but can do an unnecessary self-swap.
  • Repeated string concatenation can make a simple reversal quadratic.
  • Treating UTF-16 char units as full visible characters breaks some Unicode text.

BEST PRACTICES

In practice

  • Handle empty and one-character input naturally.
  • Describe O(n) time and O(n) additional buffer space.
  • Use Unicode-aware text elements when product requirements are grapheme-based.

SENIOR-LEVEL SCENARIO

Production thinking

A customer-name feature reverses visible text for a user-facing operation. Confirm Unicode requirements first; a char-array algorithm may corrupt emoji or combining marks, so choose a text-element-aware implementation and test real multilingual samples.
