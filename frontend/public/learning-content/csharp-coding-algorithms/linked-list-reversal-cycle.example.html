APPLY THE IDEA

Worked example

A batch importer accepts a serialized chain of dependency records. Before processing, detect a malformed loop so one corrupt record cannot keep a worker traversing forever; reverse a valid chain only when ownership permits mutation.

  1. Trace A → B → C with previous = null.
  2. Save B.Next, set B.Next = A, then advance.
  3. Repeat until current is null; return C.
  4. For a cycle, stop when the two references are identical.

CODE OR QUERY

Try it

Node? Reverse(Node? head)
{
    Node? previous = null;
    Node? current = head;
    while (current is not null)
    {
        Node? next = current.Next; // Preserve the rest of the chain.
        current.Next = previous;
        previous = current;
        current = next;
    }
    return previous;
}

bool HasCycle(Node? head)
{
    Node? slow = head;
    Node? fast = head;
    while (fast?.Next is not null)
    {
        slow = slow!.Next;
        fast = fast.Next.Next;
        if (ReferenceEquals(slow, fast)) return true;
    }
    return false;
}

TRADE-OFFS

Benefits and limitations

Benefits

  • One pass; constant extra space
  • No node allocation is required

Limitations

  • In-place reversal mutates the chain
  • Pointer ordering and null boundaries are easy to get wrong

DECISION GUIDE

When to use it

Use: Use when nodes are exclusively owned and memory efficiency matters.

Avoid: Avoid mutating shared or immutable structures; copy or use an immutable representation instead.

COMMON MISTAKES

Watch out

  • Overwriting Next before saving it loses the unprocessed suffix.
  • Checking node values instead of references can report a false cycle when values repeat.
  • Reversing a structure still in use can break concurrent readers.

BEST PRACTICES

In practice

  • State the loop invariant: previous is reversed and current begins the untouched suffix.
  • Test null, singleton, two-node, cycle-at-head, and self-loop inputs.
  • Make ownership and mutation expectations explicit at the API boundary.

INTERVIEW PRACTICE

Common questions

  1. Why must `next` be saved before changing `current.Next`?
  2. Why can two pointers detect a cycle without storing visited nodes?
  3. What are the time and space costs of each algorithm?
  4. How would you return the cycle entry rather than only report that a cycle exists?

SENIOR-LEVEL SCENARIO

Production thinking

A worker stops completing imported dependency jobs because a chain loops. Validate for a cycle at the ingestion boundary, record the source record ID for repair, and cover empty, single-node, acyclic, and cyclic cases without silently mutating shared input.

SUMMARY

In one minute

Rewire links carefully for reversal; use two-speed identity comparison to detect loops without extra storage.
