APPLY THE IDEA

Worked example

A catalog service looks up a product ID in an immutable sorted snapshot. If the collection changes frequently or is not sorted, choose a data structure whose update and lookup costs fit the workload.

  1. Start low = 0, high = 6.
  2. Middle index 3 has value 12; move low to 4.
  3. Middle index 5 has value 23; move high to 4.
  4. Index 4 has value 16; return 4.

CODE OR QUERY

Try it

int BinarySearch(int[] sorted, int target)
{
    int low = 0;
    int high = sorted.Length - 1;

    while (low <= high)
    {
        int middle = low + (high - low) / 2;
        if (sorted[middle] == target) return middle;
        if (sorted[middle] < target) low = middle + 1;
        else high = middle - 1;
    }

    return -1;
}

TRADE-OFFS

Benefits and limitations

Benefits

  • O(log n) comparisons
  • O(1) auxiliary space in the iterative form

Limitations

  • Requires sorted data and a consistent ordering
  • Frequent inserts may make maintaining sorted arrays expensive

DECISION GUIDE

When to use it

Use: Use for repeated lookup in data that is already sorted and changes infrequently.

Avoid: Avoid on unsorted data or when a hash-based lookup or database index better matches the update and query workload.

COMMON MISTAKES

Watch out

  • Using the wrong loop condition can skip a one-element range.
  • Updating low/high without excluding the midpoint can create an infinite loop.
  • Applying binary search to data whose ordering is not guaranteed.

BEST PRACTICES

In practice

  • Test empty, singleton, first, last, missing, and duplicate values.
  • Use a safe midpoint expression.
  • For duplicate values, define whether any, first, or last match is required.

INTERVIEW PRACTICE

Common questions

  1. Why is sorted input required?
  2. Why use `low + (high - low) / 2`?
  3. What does low > high mean?
  4. How do you find the first occurrence of duplicates?

SENIOR-LEVEL SCENARIO

Production thinking

A service binary-searches a large in-memory configuration snapshot but production data occasionally arrives unsorted. Validate the sort invariant when building the snapshot and test duplicate keys and boundary values before relying on logarithmic lookup.

SUMMARY

In one minute

Binary search achieves logarithmic lookup by preserving a sorted-range invariant and discarding half the candidates each step.
