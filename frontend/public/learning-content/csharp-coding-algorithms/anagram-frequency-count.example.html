APPLY THE IDEA

Worked example

A deduplication import compares labels independent of character order, ignoring case and spaces. The sample uses UTF-16 chars and should be adapted if grapheme clusters define a character.

  1. Count "aab": a → 2, b → 1.
  2. Consume "aba": a → 1, b → 0, a → 0.
  3. All counts are zero, so the strings match as anagrams.

CODE OR QUERY

Try it

bool AreAnagrams(string first, string second)
{
    var counts = new Dictionary<char, int>();

    foreach (char value in first.ToUpperInvariant())
    {
        if (char.IsWhiteSpace(value)) continue;
        counts[value] = counts.GetValueOrDefault(value) + 1;
    }

    foreach (char value in second.ToUpperInvariant())
    {
        if (char.IsWhiteSpace(value)) continue;
        if (!counts.TryGetValue(value, out int count) || count == 0)
            return false;
        counts[value] = count - 1;
    }

    return counts.Values.All(count => count == 0);
}

TRADE-OFFS

Benefits and limitations

Benefits

  • Expected O(n) time without sorting
  • Makes duplicate character counts explicit

Limitations

  • Dictionary memory grows with distinct characters
  • Correctness depends on matching normalization rules for both inputs

DECISION GUIDE

When to use it

Use: Use for moderate text under a defined character and normalization contract.

Avoid: Avoid assuming char counts are equivalent to human-perceived characters for all Unicode text.

COMMON MISTAKES

Watch out

  • Checking membership alone misses different duplicate counts.
  • Normalizing only one side makes results inconsistent.
  • Forgetting whitespace/case requirements changes expected answers.

BEST PRACTICES

In practice

  • Reject unequal normalized lengths early when normalization is available.
  • Test repeated letters, empty input, casing, and punctuation rules.
  • For strict Unicode behavior, count text elements rather than UTF-16 code units.

INTERVIEW PRACTICE

Common questions

  1. Why must duplicate characters be counted?
  2. Why is checking only that every character exists insufficient?
  3. When would sorting be simpler?
  4. What should normalization include?

SENIOR-LEVEL SCENARIO

Production thinking

A customer-data merge compares names without case or spaces, but the canonical record must preserve the original text. Compare normalized copies only for matching; never overwrite source data with the normalized form.
