THE IDEA

What is it?

A deadlock is a cycle of transactions, each holding a resource needed by another. SQL Server detects the cycle and chooses a victim; error 1205 means that victim transaction was rolled back.

WHY IT MATTERS

What problem does it solve?

Deadlocks differ from ordinary blocking: a wait may resolve when its holder commits, while a deadlock cycle cannot progress without aborting a participant.

UNDER THE HOOD

How does it work?

Capture the deadlock graph (extended events/system_health), identify statements, lock modes, indexes, and access order, then shorten transactions, standardize resource order, and improve selective access. Retry the entire database unit only when safe, bounded, and idempotent.

KEY TAKEAWAYS

Remember

  • 1205 means SQL Server selected and rolled back a deadlock victim.
  • Blocking alone is not a deadlock; a cycle is required.
  • Deadlock graphs are stronger evidence than guessing from application logs.
  • Retries complement, not replace, concurrency design fixes.
