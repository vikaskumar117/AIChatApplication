Employees Above Their Department Average in SQL Server

Learn how to compare each employee's salary against the average salary of their department using multiple T-SQL approaches. Understand correlated subqueries, window functions, NULL handling, execution plans and performance optimization.

1. Problem Statement

Imagine an organization has several departments, and each department has employees with different salaries.

The requirement is to find employees whose salary is greater than the average salary of their own department.

For example:

  • Find employees earning more than the IT department average.
  • Find employees earning more than the HR department average.
  • Find employees earning more than the Finance department average.
  • Compare each employee against the correct department, not the company-wide average.
Important distinction: We are not comparing every employee against one overall company average. Each employee must be compared against the average calculated for their own department.

3. Understand the Department Averages

Before finding employees above average, calculate the average salary for each department. 

SELECT
    Department,
    AVG(Salary) AS AverageSalary
FROM Employees
GROUP BY Department;

Expected output

Department AverageSalary
Finance65,000
HR60,000
IT77,500

How are these averages calculated?

IT:

(90000 + 80000 + 50000 + 90000) / 4
= 77500

HR:

(80000 + 60000 + 40000) / 3
= 60000

Finance:

(70000 + 70000 + 55000) / 3
= 65000
SQL Server's AVG() ignores NULL values. It calculates the average using non-NULL salary values, not the total number of rows when some salaries are NULL.

4. Approach 1 — Using a Correlated Subquery

A correlated subquery refers to a column from the outer query. Here, the inner query uses the current employee's Department to calculate that department's average salary. 

SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary
FROM Employees E
WHERE E.Salary >
(
    SELECT AVG(E2.Salary)
    FROM Employees E2
    WHERE E2.Department = E.Department
)
ORDER BY E.Department, E.Salary DESC;

Expected output

EmployeeId EmployeeName Department Salary Department Average
104DavidFinance70,00065,000
107GraceFinance70,00065,000
102BobHR80,00060,000
101AliceIT90,00077,500
110JackIT90,00077,500
103CarolIT80,00077,500

Understand the query step by step

WHERE E.Salary >
(
    SELECT AVG(E2.Salary)
    FROM Employees E2
    WHERE E2.Department = E.Department
)
  1. The outer query considers an employee row.
  2. The inner query uses that employee's Department.
  3. AVG() calculates the average salary for that department.
  4. The outer query compares the employee's salary with that average.
  5. Only employees with a greater salary are returned.

Example: Alice

Employee: Alice
Department: IT
Salary: 90000

IT Average: 77500

90000 > 77500

Result: Alice is included.
Why is it called correlated? The inner query refers to E.Department from the outer query. The two queries are logically related through that reference. SQL Server may transform and optimize the query rather than literally executing the inner query independently for every row.

5. Approach 2 — Using a CTE and JOIN

We can calculate the department averages once in a CTE and join those results to the Employees table. 

WITH DepartmentAverage AS
(
    SELECT
        Department,
        AVG(Salary) AS AverageSalary
    FROM Employees
    GROUP BY Department
)
SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary,
    D.AverageSalary
FROM Employees E
INNER JOIN DepartmentAverage D
    ON E.Department = D.Department
WHERE E.Salary > D.AverageSalary
ORDER BY E.Department, E.Salary DESC;

How it works

  1. The CTE groups employees by department.
  2. AVG(Salary) calculates the average for each group.
  3. The main query joins every employee to their department average.
  4. The WHERE clause selects salaries greater than the average.
Step 1: Group employees

Separate employee records by department.

Step 2: Calculate averages

Calculate AVG(Salary) for each department.

Step 3: Join averages

Associate each employee with the correct department average.

Step 4: Filter employees

Return only employees earning more than their department average.

6. Approach 3 — Using a Window Function

A window function calculates the department average while retaining every employee row. This is one of the clearest approaches for this problem. 

SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary,
    AVG(Salary) OVER
    (
        PARTITION BY Department
    ) AS DepartmentAverage
FROM Employees;

Expected intermediate output

Employee Department Salary DepartmentAverage
AliceIT90,00077,500
BobHR80,00060,000
CarolIT80,00077,500
DavidFinance70,00065,000
EmmaHR60,00060,000
FrankIT50,00077,500
GraceFinance70,00065,000
HenryHR40,00060,000
IvyFinance55,00065,000
JackIT90,00077,500

Understand PARTITION BY

AVG(Salary) OVER
(
    PARTITION BY Department
)
  • PARTITION BY Department divides rows into department groups.
  • AVG(Salary) calculates an average for each group.
  • The average is repeated on each employee row in that department.
  • Unlike GROUP BY, the window function does not collapse the employee rows into one row per department.

Filter employees above their average

SQL Server does not allow a window function to be used directly in the WHERE clause of the same SELECT query block. Use a CTE or derived table. 

WITH EmployeeAverage AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        AVG(Salary) OVER
        (
            PARTITION BY Department
        ) AS DepartmentAverage
    FROM Employees
)
SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary,
    DepartmentAverage
FROM EmployeeAverage
WHERE Salary > DepartmentAverage
ORDER BY Department, Salary DESC;

7. Approach 4 — Using a Derived Table

A derived table is a subquery placed in the FROM clause. It can calculate the department average and expose it to the outer query. 

SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary,
    D.AverageSalary
FROM Employees E
INNER JOIN
(
    SELECT
        Department,
        AVG(Salary) AS AverageSalary
    FROM Employees
    GROUP BY Department
) D
    ON E.Department = D.Department
WHERE E.Salary > D.AverageSalary;

This has the same general logic as the CTE approach. The derived table calculates one average per department, and the outer query compares employee salaries against it.

8. Approach 5 — Using CROSS APPLY

CROSS APPLY can calculate a department average for each employee's department. 

SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary,
    A.AverageSalary
FROM Employees E
CROSS APPLY
(
    SELECT AVG(E2.Salary) AS AverageSalary
    FROM Employees E2
    WHERE E2.Department = E.Department
) A
WHERE E.Salary > A.AverageSalary
ORDER BY E.Department, E.Salary DESC;

The APPLY expression is correlated to the current outer employee through E.Department.

Since AVG() returns one row even when no non-NULL values exist, CROSS APPLY does not remove the employee in that situation. The calculated average will be NULL.

9. Compare the Different Approaches

Approach Best use Key concept
Correlated subquery Direct comparison against a related group average Outer query reference
CTE + JOIN Readable multi-step query Aggregate first, then join
Window function Keep employee details alongside group statistics PARTITION BY
Derived table Inline aggregation Subquery in FROM
CROSS APPLY Correlated calculations and per-row logic APPLY operator

These query forms can produce similar results, and SQL Server may transform them into similar execution plans. Do not assume one form is automatically faster. Measure with realistic data.

10. Company Average vs Department Average

A common mistake is comparing employees against the overall company average instead of their own department average.

Company-wide average

SELECT AVG(Salary) AS CompanyAverage
FROM Employees;

The company-wide average in this sample is 68,500.

Employees above the company average

SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary
FROM Employees
WHERE Salary >
(
    SELECT AVG(Salary)
    FROM Employees
);

This is a different business question. It compares every employee against one company-wide number.

Employees above their department average

SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary
FROM Employees E
WHERE Salary >
(
    SELECT AVG(Salary)
    FROM Employees E2
    WHERE E2.Department = E.Department
);

This second query compares employees against the average calculated for their own department.

11. Handling NULL Salaries

SQL Server's AVG() ignores NULL values. Consider this data:

Employee Department Salary
Employee ASupport50,000
Employee BSupport70,000
Employee CSupportNULL

SQL Server calculates:

AVG(Salary)
= (50000 + 70000) / 2
= 60000

Employee B is above average. Employee A is below average. Employee C has a NULL salary, so the comparison evaluates to UNKNOWN and that employee is not returned.

What if all salaries in a department are NULL?

AVG(Salary) returns NULL. A comparison such as Salary > NULL does not evaluate to TRUE. Therefore, no employees in that department are returned by the above-average query.

Do not automatically replace NULL with zero using ISNULL() or COALESCE(). A missing salary and a salary of zero may represent different business meanings.

12. Find Employees at or Above Their Department Average

If the requirement includes employees whose salaries equal their department average, change the greater-than operator to greater-than-or-equal. 

WITH EmployeeAverage AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        AVG(Salary) OVER
        (
            PARTITION BY Department
        ) AS DepartmentAverage
    FROM Employees
)
SELECT *
FROM EmployeeAverage
WHERE Salary >= DepartmentAverage;

In the sample data, Emma's salary is exactly equal to the HR department average, so she is included in this version.

13. Find Employees Below Their Department Average

The same logic can be reversed to find employees whose salary is less than their department average. 

WITH EmployeeAverage AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        AVG(Salary) OVER
        (
            PARTITION BY Department
        ) AS DepartmentAverage
    FROM Employees
)
SELECT *
FROM EmployeeAverage
WHERE Salary < DepartmentAverage;

In the sample data, this returns employees earning below their department average, including Frank, Emma, Henry and Ivy.

14. Find Departments Where the Average Salary Is Above a Threshold

Sometimes the requirement is not about individual employees. Instead, the organization wants departments whose average salary exceeds a specific amount. 

SELECT
    Department,
    AVG(Salary) AS AverageSalary
FROM Employees
GROUP BY Department
HAVING AVG(Salary) > 65000;

Expected output

Department AverageSalary
IT77,500

HAVING filters groups after aggregation. WHERE filters individual rows before grouping.

15. SQL Server Internal Processing

SQL Server's optimizer determines how to execute the query. The logical requirement is to calculate a department average and compare employee salaries against it.

Conceptual execution flow for the CTE and JOIN approach

1. Read employee data

Access the necessary table or index rows.

2. Group by department

Build department groups for aggregation.

3. Calculate AVG(Salary)

Calculate one average value per department.

4. Join average values

Associate the average with the matching employees.

5. Apply the salary filter

Return rows where salary exceeds the department average.

Possible execution plan operators

Operator Purpose
Index ScanReads rows from an index.
Table ScanReads rows from a heap table.
Hash Match (Aggregate)Groups rows and calculates aggregates.
Stream AggregateAggregates rows that arrive in suitable grouping order.
Hash Match (Join)Joins the department averages to employee rows.
Nested LoopsMay be used for joins when the estimated input sizes and access paths make it appropriate.
FilterApplies the salary comparison.
Window AggregateMay participate in a plan for the window-function approach.

The exact operators and their order are selected by the optimizer. A correlated subquery does not necessarily mean the inner query physically executes once for every employee.

16. Performance Optimization

1. Consider an index on Department and Salary

CREATE NONCLUSTERED INDEX IX_Employees_Department_Salary
ON Employees
(
    Department,
    Salary
)
INCLUDE
(
    EmployeeId,
    EmployeeName
);

This index may help when queries group or filter by department and need salary and employee details. Its benefit depends on the table size, selectivity, workload and chosen execution plan.

2. Avoid unnecessary repeated calculations

A window-function or aggregate-and-join approach can make the calculation easier to express when the query needs department averages and multiple employee columns.

3. Measure the actual workload

SET STATISTICS IO ON;
SET STATISTICS TIME ON;

-- Execute the query being tested.

SET STATISTICS IO OFF;
SET STATISTICS TIME OFF;

Inspect logical reads, CPU time, elapsed time and the actual execution plan. Compare alternative query forms using the same representative data and conditions.

An index is not automatically beneficial. Extra indexes require storage and can increase the cost of INSERT, UPDATE and DELETE operations.

18. Common Mistakes

  1. Comparing against the company average. The requirement is department-specific, so use the department correlation or PARTITION BY.
  2. Using GROUP BY when employee details are required. GROUP BY returns one row per group. Use a JOIN or window function to retain employee rows.
  3. Using a window function directly in WHERE. Calculate it in a CTE or derived table, then filter.
  4. Forgetting the department condition. A correlated subquery must match the employee's department.
  5. Ignoring NULL salary values. AVG() ignores NULL, and comparisons with NULL do not evaluate to TRUE.
  6. Assuming a CTE is materialized. A CTE is a query expression; it does not automatically create a stored intermediate table.

20. Knowledge Check

Question 1

Which clause divides employees into department groups for a window function?

  • A. ORDER BY
  • B. PARTITION BY
  • C. GROUP BY
  • D. HAVING

Answer: B. PARTITION BY.

Question 2

What does AVG(Salary) OVER (PARTITION BY Department) return?

  • A. One row for the entire company
  • B. One row per department only
  • C. The department average alongside each employee row
  • D. The maximum salary in each department

Answer: C. The department average alongside each employee row.

Question 3

Why is a correlated subquery called correlated?

  • A. It always uses a JOIN
  • B. It references a column from the outer query
  • C. It cannot use aggregate functions
  • D. It returns only one row in total

Answer: B. It references a column from the outer query.

Question 4

What does AVG() do with NULL values?

  • A. Treats them as zero
  • B. Ignores them
  • C. Returns an error
  • D. Counts them as one

Answer: B. Ignores them.
