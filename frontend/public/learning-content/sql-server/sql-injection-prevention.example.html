APPLY THE IDEA

Worked example

A search term is passed as a parameter; the chosen sort column is selected from a fixed server-side mapping.

  1. Use parameterized APIs/ORM interpolation for all scalar values.
  2. For identifiers or sort directions, map a finite enum to known SQL fragments.
  3. Give the application DB identity only required permissions.
  4. Test inputs containing quotes, comments, encodings, and unexpected sort keys; log safely.

CODE OR QUERY

Try it

using var command = new SqlCommand(
    "SELECT UserId, DisplayName FROM dbo.Users WHERE Email = @email",
    connection);
command.Parameters.Add("@email", SqlDbType.NVarChar, 320).Value = email;

// For an identifier (not a value), select only from a server-side allowlist:
var sortColumn = sortKey switch
{
    "name" => "[DisplayName]",
    "created" => "[CreatedAt]",
    _ => "[UserId]"
};
var sql = $"SELECT UserId, DisplayName FROM dbo.Users ORDER BY {sortColumn}";

TRADE-OFFS

Benefits and limitations

Benefits

  • Parameters separate data values from SQL code.
  • Allowlisting provides a safe finite vocabulary for dynamic identifiers.

Limitations

  • Identifiers and SQL structure cannot generally be supplied as ordinary value parameters.
  • Dynamic query shapes need careful plan and authorization review.

DECISION GUIDE

When to use it

Use: Use typed parameters for every untrusted value and strict allowlists for unavoidable structural choices.

Avoid: Avoid string concatenation for values, blacklists, “escaping” as a substitute for parameters, and excessive database privileges.

COMMON MISTAKES

Watch out

  • Interpolating user values into raw SQL strings.
  • Assuming an ORM makes manually constructed raw SQL safe.
  • Allowing user-provided table or column names without strict mapping.

BEST PRACTICES

In practice

  • Use typed parameters and ORM parameter APIs.
  • Keep dynamic query structure finite and allowlisted.
  • Use least-privilege database credentials and avoid leaking error details.
  • Review raw SQL and test injection boundaries.

INTERVIEW PRACTICE

Common questions

  1. Why can a parameter represent a value but not a table name?
  2. How should a dynamic ORDER BY column be selected?
  3. Why is least privilege part of injection defense?

SENIOR-LEVEL SCENARIO

Production thinking

A search endpoint accepts free text and a sort option. Bind search text, map sort options to fixed identifiers, restrict database principal permissions, and test adversarial inputs without exposing SQL or credentials.

SUMMARY

In one minute

SQL injection occurs when untrusted input is concatenated into SQL syntax, allowing input to alter the intended command or predicate. Injection can bypass authorization filters, expose or modify data, and execute unintended statements. Escaping ad hoc is fragile, especially for encoding, quoting, and multiple SQL dialect details.
