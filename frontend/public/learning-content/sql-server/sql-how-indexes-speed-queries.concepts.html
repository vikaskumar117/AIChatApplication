THE IDEA

What is it?

A B-tree index narrows the rows that must be visited for selective predicates and can provide ordered rows or cover all columns needed by a query.

WHY IT MATTERS

What problem does it solve?

Reading fewer pages can reduce I/O and CPU, but an index seek can still return many rows, perform many lookups, or feed an expensive join or sort.

UNDER THE HOOD

How does it work?

Align leading key columns with useful equality/range predicates and ordering; keep predicates sargable (search-argument-able), maintain statistics, and check actual rows, logical reads, lookups, and spills. The optimizer chooses indexes using estimated costs and available statistics.

KEY TAKEAWAYS

Remember

  • Indexes reduce data access only when query shape and selectivity benefit.
  • A seek can still read many rows or trigger expensive lookups.
  • Sargable predicates and accurate statistics support better access choices.
  • Optimize the whole plan and measured workload, not a single operator label.
