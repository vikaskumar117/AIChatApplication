Find the Second-Highest Salary in SQL Server

Learn different ways to find the second-highest salary using MAX(), subqueries, DISTINCT, TOP, and window functions. Understand duplicate salaries, NULL handling, department-wise ranking, and production considerations.

1. Understand the Problem

Consider an Employee table containing employee names, departments, and salaries.

The business requirement is to find the second-highest salary paid by the company.

Sample employee data

101AliceIT90000
102BobHR80000
103CarolIT80000
104DavidFinance70000
105EmmaHR60000
106FrankIT50000
107GraceFinance50000
108HenryHR40000

What is the expected answer?

First, arrange the distinct salary values in descending order.

Position Salary
1st highest90000
2nd highest80000
3rd highest70000
4th highest60000
5th highest50000
6th highest40000
Expected answer: 80000 Notice that 80000 occurs twice. It is still the second-highest distinct salary, not the third-highest.

3. Approach 1 — Using MAX() with a Subquery

This is one of the simplest ways to find the second-highest distinct salary.

Step 1: Find the highest salary


SELECT MAX(Salary) AS HighestSalary
FROM Employees;

Output

HighestSalary
90000.00

MAX() returns the largest non-NULL salary.

Step 2: Find the maximum salary below the highest salary


SELECT MAX(Salary) AS SecondHighestSalary
FROM Employees
WHERE Salary < (
    SELECT MAX(Salary)
    FROM Employees
);

How does this query work?

  1. The inner query finds the highest salary, which is 90000.
  2. The outer WHERE condition excludes salaries greater than or equal to 90000.
  3. The remaining salaries are 80000, 80000, 70000, 60000, 50000, 50000 and 40000.
  4. MAX() selects the largest remaining salary, which is 80000.

Output

SecondHighestSalary
80000.00
This approach automatically handles duplicate highest salaries because the condition excludes every row equal to the maximum salary.

4. Approach 2 — Using DISTINCT and TOP

SQL Server supports TOP to return a specified number of rows.

We can combine TOP with DISTINCT and ORDER BY to retrieve the second-highest distinct salary. 


SELECT TOP (1)
    Salary AS SecondHighestSalary
FROM
(
    SELECT DISTINCT Salary
    FROM Employees
    WHERE Salary IS NOT NULL
) AS SalaryList
ORDER BY Salary DESC
OFFSET 1 ROWS;

Understand each part

  • SELECT DISTINCT removes repeated salary values.
  • WHERE Salary IS NOT NULL excludes missing salaries.
  • ORDER BY Salary DESC sorts salaries from highest to lowest.
  • OFFSET 1 ROWS skips the first salary.
  • TOP (1) returns the next available row.

Intermediate result

Position Distinct Salary
190000
280000
370000
460000
550000
640000

The first row is skipped, and the next row is returned.

OFFSET requires ORDER BY in SQL Server. The DISTINCT operation is important here because we want the second distinct salary, not simply the second employee row.

5. Approach 3 — Using DENSE_RANK()

DENSE_RANK() is a window function that assigns ranking numbers to rows based on an ordering expression.

Rows with the same salary receive the same rank. The next distinct salary receives the next consecutive rank.

Query


WITH SalaryRanking AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Salary,
        DENSE_RANK() OVER
        (
            ORDER BY Salary DESC
        ) AS SalaryRank
    FROM Employees
    WHERE Salary IS NOT NULL
)
SELECT
    EmployeeId,
    EmployeeName,
    Salary,
    SalaryRank
FROM SalaryRanking
WHERE SalaryRank = 2;

How DENSE_RANK() works

EmployeeName Salary SalaryRank
Alice900001
Bob800002
Carol800002
David700003
Emma600004
Frank500005
Grace500005
Henry400006

Final output

EmployeeId EmployeeName Salary SalaryRank
102Bob800002
103Carol800002
DENSE_RANK() returns both employees because both employees have the second-highest distinct salary.

6. Approach 4 — Using a Correlated Subquery

Another way is to count how many distinct salary values are greater than each employee's salary.

The second-highest distinct salary has exactly one distinct salary value greater than it.

Query


SELECT DISTINCT
    e1.Salary AS SecondHighestSalary
FROM Employees AS e1
WHERE e1.Salary IS NOT NULL
  AND
  (
      SELECT COUNT(DISTINCT e2.Salary)
      FROM Employees AS e2
      WHERE e2.Salary > e1.Salary
  ) = 1;

How does it work?

SQL Server evaluates the subquery for each candidate salary in the outer query.

Candidate Salary Distinct Salaries Greater Than It Count
90000None0
80000900001
7000090000, 800002
6000090000, 80000, 700003

The salary whose count equals one is the second-highest distinct salary.

This is useful for understanding correlated subqueries, but it may require more work on large tables than a suitable ranking or aggregation approach. Always compare actual execution plans and performance.

7. Second-Highest Distinct Salary vs Second Employee Salary

This distinction is extremely important.

Consider this data:

EmployeeName Salary
Alice90000
Bob80000
Carol80000
David70000

Requirement A: Second-highest distinct salary

Distinct salary values are 90000, 80000 and 70000.

The answer is 80000.

Requirement B: Second employee when sorted by salary

Sort all employee rows by salary descending.

Alice is first. Bob and Carol tie for the next position. Without an additional tie-breaker, their relative order is not guaranteed. 


SELECT TOP (2)
    EmployeeId,
    EmployeeName,
    Salary
FROM Employees
ORDER BY Salary DESC, EmployeeId ASC;

This returns two employee rows, not the second-highest distinct salary.

Always clarify whether the requirement means the second distinct salary or the second employee row. These are different business requirements.

8. What If There Is No Second-Highest Salary?

Consider a company with only one distinct salary value.

EmployeeName Salary
Alice90000
Bob90000
Carol90000

There is no second distinct salary. 


SELECT MAX(Salary) AS SecondHighestSalary
FROM Employees
WHERE Salary < (
    SELECT MAX(Salary)
    FROM Employees
);

MAX() returns NULL because the outer query has no qualifying salary rows.

Return a message when the value does not exist


DECLARE @SecondHighestSalary DECIMAL(12, 2);

SELECT @SecondHighestSalary = MAX(Salary)
FROM Employees
WHERE Salary < (
    SELECT MAX(Salary)
    FROM Employees
);

SELECT
    CASE
        WHEN @SecondHighestSalary IS NULL
            THEN 'Second highest salary does not exist'
        ELSE CAST(@SecondHighestSalary AS VARCHAR(30))
    END AS Result;

The result is returned as a message if no second distinct salary exists.

9. How NULL Salaries Affect the Result

NULL means that a salary value is missing or unknown. SQL Server aggregate functions such as MAX() ignore NULL.

For example:

EmployeeName Salary
Alice90000
Bob80000
CarolNULL

The second-highest distinct salary remains 80000.

In the DENSE_RANK() approach, we explicitly used WHERE Salary IS NOT NULL to make the intended behavior clear.

Do not replace NULL salaries with zero unless the business requirement explicitly defines missing salary as zero. Missing and zero are different values.

10. Find the Second-Highest Salary Per Department

Now consider a different business requirement: find the second-highest distinct salary in every department.

We can use DENSE_RANK() with PARTITION BY.

Query


WITH DepartmentSalaryRanking AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        DENSE_RANK() OVER
        (
            PARTITION BY Department
            ORDER BY Salary DESC
        ) AS SalaryRank
    FROM Employees
    WHERE Salary IS NOT NULL
)
SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary
FROM DepartmentSalaryRanking
WHERE SalaryRank = 2
ORDER BY Department;

How PARTITION BY works

PARTITION BY divides the rows into separate department groups. DENSE_RANK() starts ranking independently inside each department.

Example ranking

Department Employee Salary Rank
FinanceDavid700001
FinanceGrace500002
HRBob800001
HREmma600002
HRHenry400003
ITAlice900001
ITCarol800002
ITFrank500003

Final output

EmployeeName Department SecondHighestSalary
GraceFinance50000
EmmaHR60000
CarolIT80000

This query returns the employee or employees earning the second-highest distinct salary within each department.

11. Why DENSE_RANK() Instead of RANK()?

Both functions assign the same rank to tied values, but they differ in how the next rank is calculated.

Consider the following salaries:

Employee Salary
Alice90000
Bob80000
Carol80000
David70000
 

SELECT
    EmployeeName,
    Salary,

    ROW_NUMBER() OVER
    (
        ORDER BY Salary DESC
    ) AS RowNumber,

    RANK() OVER
    (
        ORDER BY Salary DESC
    ) AS SalaryRank,

    DENSE_RANK() OVER
    (
        ORDER BY Salary DESC
    ) AS DenseSalaryRank

FROM Employees;

Result

Employee Salary ROW_NUMBER RANK DENSE_RANK
Alice90000111
Bob80000222
Carol80000322
David70000443

ROW_NUMBER assigns a unique sequential number to each row. RANK leaves gaps after tied ranks. DENSE_RANK does not leave gaps.

For the second-highest distinct salary, DENSE_RANK() is usually the most natural window function.

12. How SQL Server Executes These Queries

Different SQL statements can produce the same result, but SQL Server may choose different execution plans.

MAX() approach

SQL Server may use an aggregate operator to calculate the maximum salary. The inner query and outer query may be optimized together.

DENSE_RANK() approach

A window ranking query may use operators such as:

  • Scan or Seek to read employee rows.
  • Sort to arrange salaries in descending order, if needed.
  • Segment and Sequence Project or other window-related operators to calculate ranking.
  • Filter to return only rank 2.

Execution flow — conceptual

Employee table

Read salary data

Sort

Order salaries descending

Ranking

Calculate DENSE_RANK

Filter

Keep rank 2

This is a conceptual flow, not a guaranteed physical execution plan. The actual operators depend on SQL Server's optimizer, indexes, statistics and data distribution.

Inspect the actual execution plan

SET STATISTICS TIME ON;

WITH SalaryRanking AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Salary,
        DENSE_RANK() OVER
        (
            ORDER BY Salary DESC
        ) AS SalaryRank
    FROM Employees
    WHERE Salary IS NOT NULL
)
SELECT *
FROM SalaryRanking
WHERE SalaryRank = 2;

Examine the actual number of rows, sort operations, memory usage, logical reads and execution time.

13. Performance Considerations

On a small employee table, the difference between these approaches may be negligible.

On a large employee table, examine the following:

  • Number of rows in the employee table.
  • Whether the query needs all employee columns or only salary.
  • Whether a useful salary index exists.
  • Whether the query requires sorting.
  • Actual versus estimated row counts.
  • Logical reads and memory grants.

Example index


CREATE NONCLUSTERED INDEX IX_Employees_Salary
ON Employees(Salary);

This index can help queries that access salary values. Whether it improves a particular query depends on the execution plan and workload.

Do not create an index for every query automatically. Indexes consume storage and add maintenance overhead during INSERT, UPDATE and DELETE operations.

14. Common Mistakes

  • Using TOP (2) without DISTINCT when the requirement is the second-highest distinct salary.
  • Using ROW_NUMBER() when tied salaries should share the same rank.
  • Forgetting that multiple employees can earn the second-highest salary.
  • Assuming a second-highest salary always exists.
  • Forgetting to consider NULL salaries.
  • Confusing the second-highest salary across the company with the second-highest salary per department.
  • Assuming one query-writing approach is always faster than the others.

15. Real-World Production Scenarios

Scenario 1: Payroll reporting

The finance team wants to know the second-highest distinct salary in the organization for salary benchmarking.

Use MAX() with a subquery or DENSE_RANK(), depending on whether the report needs only the salary or the employee details as well.

Scenario 2: Department compensation analysis

HR wants to compare the second-highest salary in each department.

Use DENSE_RANK() with PARTITION BY Department.

Scenario 3: Salary approval workflow

A manager wants to review employees whose salaries are the second-highest in the company.

Return all employees with DENSE_RANK() equal to 2 rather than returning only one employee.

Scenario 4: Salary analytics API

A backend API needs to return the second-highest salary for a dashboard.

The application should define what happens if there is no second-highest salary and should return a predictable result to the frontend.
