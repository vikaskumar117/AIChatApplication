THE IDEA

What is it?

A clustered index is the table’s rowstore B-tree whose leaf level contains the data rows; a table has at most one. A nonclustered index is a separate B-tree with key columns and a row locator (clustered key or RID), and a table may have many.

WHY IT MATTERS

What problem does it solve?

Indexes provide ordered access paths, support constraints, and can avoid scans or lookups. Each index also adds storage, write work, and maintenance.

UNDER THE HOOD

How does it work?

Choose a clustered key that fits access patterns and key stability; design nonclustered keys for predicates, joins, ordering, and grouping. INCLUDE non-key columns for coverage without making them ordering keys. Validate with actual plans and workload evidence.

KEY TAKEAWAYS

Remember

  • A table has at most one clustered index; its leaf level is the table data.
  • A nonclustered index stores key values and a row locator.
  • INCLUDE can cover output without expanding the index key.
  • Indexes trade read efficiency for storage and write maintenance.
