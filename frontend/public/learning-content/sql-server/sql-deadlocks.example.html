APPLY THE IDEA

Worked example

Transaction A locks Order then Inventory while B locks Inventory then Order; standardize both to Order then Inventory.

  1. Capture the deadlock graph and correlate transaction IDs to application operations.
  2. Inspect resource types, lock modes, access order, and plan/index support.
  3. Make access order consistent and reduce lock duration.
  4. Retry only a safe, idempotent transaction with bounded backoff; verify external effects are outside or deduplicated.

Try it

-- Pseudocode: retry the complete database operation with bounded backoff.
// Retry only a known transient deadlock and only an idempotent DB unit.
await retryPolicy.ExecuteAsync(async () =>
{
    await using var tx = await connection.BeginTransactionAsync(ct);
    await UpdateOrderThenInventoryAsync(tx, orderId, ct);
    await tx.CommitAsync(ct);
});

TRADE-OFFS

Benefits and limitations

Benefits

  • Deadlock graphs expose involved resources and statements.
  • A bounded retry can recover a transient victim rollback.

Limitations

  • Retries add latency and can amplify load during contention.
  • Blind retries can duplicate external effects or mask a systemic lock-order flaw.

DECISION GUIDE

When to use it

Use: Use retries for a narrowly classified transient failure when the transaction can safely be replayed.

Avoid: Avoid retrying non-idempotent external side effects inside the retry boundary or swallowing 1205 without diagnosis.

COMMON MISTAKES

Watch out

  • Treating every timeout or blocking wait as a deadlock.
  • Retrying unboundedly or retrying operations with already-issued external side effects.
  • Changing isolation or adding indexes without graph and plan evidence.

BEST PRACTICES

In practice

  • Use Extended Events/system_health to capture deadlock XML.
  • Keep transactions short and acquire shared resources in a consistent order.
  • Use bounded jittered retries only for safe transient transaction failures.
  • Log operation correlation IDs and retry counts without sensitive SQL parameter values.

SENIOR-LEVEL SCENARIO

Production thinking

Checkout intermittently fails with 1205. Capture graphs during the incident, map locks to statements and indexes, standardize entity update order, shorten transaction scope, and add a bounded database-only retry with idempotency keys for external payment actions.

SUMMARY

In one minute

A deadlock is a cycle of transactions, each holding a resource needed by another. SQL Server detects the cycle and chooses a victim; error 1205 means that victim transaction was rolled back. Deadlocks differ from ordinary blocking: a wait may resolve when its holder commits, while a deadlock cycle cannot progress without aborting a participant.
