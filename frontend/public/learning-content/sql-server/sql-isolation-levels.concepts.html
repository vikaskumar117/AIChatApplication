THE IDEA

What is it?

Isolation defines what changes a transaction can observe and which concurrent anomalies are prevented. SQL Server offers READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE, and SNAPSHOT; READ COMMITTED SNAPSHOT (RCSI) is a database option that provides statement-level versioned reads.

WHY IT MATTERS

What problem does it solve?

Isolation is a correctness and concurrency decision: stronger guarantees can increase locking, blocking, or row-version storage. Snapshot and RCSI use row versions rather than making readers wait for many writers.

UNDER THE HOOD

How does it work?

READ UNCOMMITTED permits dirty reads; READ COMMITTED avoids dirty reads; REPEATABLE READ retains locks on read rows; SERIALIZABLE protects qualifying key ranges against phantoms; SNAPSHOT gives a transactionally consistent versioned view and can raise update conflicts. Select the weakest level that maintains invariants and test under real concurrency.

KEY TAKEAWAYS

Remember

  • READ UNCOMMITTED can expose uncommitted changes.
  • SERIALIZABLE protects qualifying ranges but can increase blocking.
  • RCSI gives statement-level versioned reads; SNAPSHOT gives transaction-level view.
  • Isolation cannot replace constraints or atomic operations for core invariants.
