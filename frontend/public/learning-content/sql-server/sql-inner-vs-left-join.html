INNER JOIN vs LEFT JOIN in SQL Server

1. Why Do We Need JOINs?

In a relational database, information is usually divided into multiple tables to avoid unnecessary duplication.

For example, an employee table stores employee information, while a department table stores department information. Instead of storing the department name repeatedly for every employee, we store a DepartmentId in the Employees table.

A JOIN allows us to retrieve related information from both tables in a single query.

Example business requirement

Business scenario: The HR team wants to display employee names along with their department names.

We need to connect Employees.DepartmentId with Departments.DepartmentId.

Notice that Finance has no employees. David also has no department assigned. These two situations will help us understand the difference between INNER JOIN and LEFT JOIN.

3. What Is INNER JOIN?

INNER JOIN returns only the rows where the join condition matches in both tables.

Query


SELECT
    e.EmployeeId,
    e.EmployeeName,
    d.DepartmentName
FROM Employees AS e
INNER JOIN Departments AS d
    ON e.DepartmentId = d.DepartmentId;

How does it work?

SQL Server compares Employees.DepartmentId with Departments.DepartmentId.

  • Alice has DepartmentId 1. A matching Engineering row exists.
  • Bob has DepartmentId 1. A matching Engineering row exists.
  • Carol has DepartmentId 2. A matching HR row exists.
  • David has NULL. The equality condition does not match.

Result

EmployeeId EmployeeName DepartmentName
101 Alice Engineering
102 Bob Engineering
103 Carol HR
Important: David is excluded because his DepartmentId does not match a department. Finance is also absent because INNER JOIN does not return departments without matching employees.

4. What Is LEFT JOIN?

LEFT JOIN returns every row from the left table and matching rows from the right table.

If no matching row exists in the right table, SQL Server returns NULL for the right table's columns.

Query


SELECT
    e.EmployeeId,
    e.EmployeeName,
    d.DepartmentName
FROM Employees AS e
LEFT JOIN Departments AS d
    ON e.DepartmentId = d.DepartmentId;

Result

EmployeeId EmployeeName DepartmentName
101 Alice Engineering
102 Bob Engineering
103 Carol HR
104 David NULL

David is included because Employees is the left table. Since no matching department exists, DepartmentName is NULL.

5. What If We Reverse the Tables?

The position of the tables matters in a LEFT JOIN. The table written immediately after FROM is the left table.

Business requirement

The HR team wants to see every department, including departments that currently have no employees. 


SELECT
    d.DepartmentId,
    d.DepartmentName,
    e.EmployeeName
FROM Departments AS d
LEFT JOIN Employees AS e
    ON d.DepartmentId = e.DepartmentId;

Result

DepartmentId DepartmentName EmployeeName
1 Engineering Alice
1 Engineering Bob
2 HR Carol
3 Finance NULL
Finance is now included because Departments is the left table. This is the key to understanding LEFT JOIN.

6. INNER JOIN vs LEFT JOIN

Feature INNER JOIN LEFT JOIN
Matching rows Included Included
Unmatched left rows Excluded Included
Unmatched right rows Excluded Excluded
Missing right-side values Not returned Returned as NULL
Common use Only related records All left-side records

7. Real-World Business Scenarios

Scenario 1: Employees with valid departments

Requirement: Display only employees assigned to a department. 


SELECT
    e.EmployeeName,
    d.DepartmentName
FROM Employees e
INNER JOIN Departments d
    ON e.DepartmentId = d.DepartmentId;

Scenario 2: All employees, even without a department

Requirement: HR wants to identify every employee and see whether a department has been assigned. 


SELECT
    e.EmployeeName,
    d.DepartmentName
FROM Employees e
LEFT JOIN Departments d
    ON e.DepartmentId = d.DepartmentId;

Scenario 3: Find departments with no employees

Requirement: Identify departments that have no employees. 


SELECT
    d.DepartmentId,
    d.DepartmentName
FROM Departments d
LEFT JOIN Employees e
    ON d.DepartmentId = e.DepartmentId
WHERE e.EmployeeId IS NULL;

Result

DepartmentId DepartmentName
3 Finance

This pattern is called an anti-join: it finds rows in one table that have no matching row in another table.

8. Important: ON vs WHERE with LEFT JOIN

One of the most common SQL mistakes is placing a condition in WHERE when it was intended to be part of the JOIN.

Example A: Filter in ON


SELECT
    e.EmployeeName,
    d.DepartmentName
FROM Employees e
LEFT JOIN Departments d
    ON e.DepartmentId = d.DepartmentId
    AND d.DepartmentName = 'Engineering';

All employees are preserved. Only Engineering is allowed to match on the department side. Employees in other departments appear with a NULL department name.

Example B: Filter in WHERE


SELECT
    e.EmployeeName,
    d.DepartmentName
FROM Employees e
LEFT JOIN Departments d
    ON e.DepartmentId = d.DepartmentId
WHERE d.DepartmentName = 'Engineering';

The WHERE condition removes rows where DepartmentName is NULL or is not Engineering. The result contains only employees matched to Engineering.

Remember: A WHERE condition on the nullable side of a LEFT JOIN can eliminate unmatched rows. This can make the result behave like an INNER JOIN for that condition.

9. How SQL Server Executes a JOIN Internally

SQL Server does not necessarily execute a JOIN using the exact row-by-row process imagined from the SQL syntax. The optimizer chooses a physical execution strategy.

Nested Loops Join

SQL Server reads rows from one input and searches the other input for matching rows. This can be effective when one input is small and the other has a useful index.

Hash Join

SQL Server builds a hash structure from one input and probes it using rows from the other input. This is commonly useful for larger equality joins when a suitable ordered access path is not available.

Merge Join

SQL Server reads inputs ordered by the join keys and combines matching values. It can be efficient when both inputs are already suitably ordered.

INNER JOIN and LEFT JOIN are logical join types. Nested Loops, Hash Match and Merge Join are physical execution operators. Do not confuse these two concepts.

Inspect the execution plan


SET STATISTICS IO ON;
SET STATISTICS TIME ON;

SELECT
    e.EmployeeName,
    d.DepartmentName
FROM Employees e
LEFT JOIN Departments d
    ON e.DepartmentId = d.DepartmentId;

SET STATISTICS TIME OFF;
SET STATISTICS IO OFF;

In SQL Server Management Studio, enable the Actual Execution Plan and execute the query. Inspect the selected join operator, estimated rows, actual rows, and access methods.

10. Common Mistakes

  • Assuming LEFT JOIN always returns all rows from both tables. It preserves only the left table's rows.
  • Forgetting that table order matters in a LEFT JOIN.
  • Using WHERE on right-side columns without considering how it affects unmatched rows.
  • Assuming NULL equals NULL. In SQL Server, an equality comparison with NULL evaluates to UNKNOWN.
  • Assuming INNER JOIN always performs faster than LEFT JOIN. Performance depends on the query, data, indexes and plan.
  • Forgetting that one left row can match multiple right rows, producing multiple output rows.
