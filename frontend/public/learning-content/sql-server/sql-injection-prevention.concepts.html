THE IDEA

What is it?

SQL injection occurs when untrusted input is concatenated into SQL syntax, allowing input to alter the intended command or predicate.

WHY IT MATTERS

What problem does it solve?

Injection can bypass authorization filters, expose or modify data, and execute unintended statements. Escaping ad hoc is fragile, especially for encoding, quoting, and multiple SQL dialect details.

UNDER THE HOOD

How does it work?

Use parameterized commands so values are data, not executable syntax. For dynamic identifiers or sort directions that cannot be parameters, map input to a strict allowlist and quote validated identifiers. Apply least privilege and avoid returning raw database errors.

KEY TAKEAWAYS

Remember

  • Parameterized values are data, not SQL syntax.
  • Identifiers and keywords need server-side allowlists, not ordinary value parameters.
  • Escaping and input filtering are not substitutes for parameterization.
  • Least privilege and safe error handling reduce impact.
