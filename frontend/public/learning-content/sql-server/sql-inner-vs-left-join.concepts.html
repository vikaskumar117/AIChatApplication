THE IDEA

What is it?

INNER JOIN returns rows with matching join keys on both sides. LEFT JOIN preserves every left-side row and returns NULLs for right-side columns when no match exists.

WHY IT MATTERS

What problem does it solve?

Join type encodes whether unmatched left entities matter. A predicate on the nullable right side in WHERE can remove unmatched rows and make a LEFT JOIN behave like an inner join for that predicate.

UNDER THE HOOD

How does it work?

Put relationship matching in ON. Put right-side filters in ON when unmatched left rows must remain; put them in WHERE only when the result should exclude rows without a qualifying right match. Use COUNT(right.PrimaryKey), not COUNT(*), to count actual matches after an outer join.

KEY TAKEAWAYS

Remember

  • INNER JOIN drops rows without a match.
  • LEFT JOIN preserves left rows and supplies NULL right-side values.
  • A right-side WHERE condition can remove NULL-extended rows.
  • COUNT(*) counts the preserved row; COUNT(non-null right key) counts matches.
