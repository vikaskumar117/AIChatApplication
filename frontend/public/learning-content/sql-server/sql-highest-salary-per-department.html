Find the Highest Salary Per Department in SQL Server

Learn how to retrieve the highest salary in every department, identify the employee earning that salary, handle multiple employees with the same highest salary, and understand the performance of different T-SQL approaches.

1. Problem Statement

Imagine an organization has multiple departments, and each department has several employees. We need to identify the highest salary in each department.

For example:

  • Which employee has the highest salary in IT?
  • Which employee has the highest salary in HR?
  • Which employee has the highest salary in Finance?
  • What if two employees have the same highest salary?
  • What if a department has no employees?
Important distinction: Finding the maximum salary per department and finding the employee who earns that salary are two different tasks. MAX() finds the salary value. Additional logic is needed to retrieve the employee details.

3. Approach 1 — GROUP BY with MAX()

The simplest approach is to group employees by department and calculate the maximum salary in each group. 

SELECT
    Department,
    MAX(Salary) AS HighestSalary
FROM Employees
GROUP BY Department;

Output

Department HighestSalary
Finance70,000
HR80,000
IT90,000

How it works

  1. GROUP BY Department divides rows into department groups.
  2. MAX(Salary) calculates the maximum salary in each group.
  3. SQL Server returns one row for each department.
Limitation: This query returns only the department and salary. It does not return the employee name or EmployeeId.

4. Approach 2 — GROUP BY with JOIN

If we need the complete employee details, first calculate the maximum salary for each department. Then join that result back to the Employees table. 

SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary
FROM Employees E
INNER JOIN
(
    SELECT
        Department,
        MAX(Salary) AS HighestSalary
    FROM Employees
    GROUP BY Department
) M
    ON E.Department = M.Department
   AND E.Salary = M.HighestSalary
ORDER BY E.Department, E.EmployeeName;

Output

EmployeeId EmployeeName Department Salary
104DavidFinance70,000
107GraceFinance70,000
102BobHR80,000
101AliceIT90,000
110JackIT90,000

Execution flow

Step 1: Group employees

Divide the Employees table by Department.

Step 2: Calculate MAX(Salary)

Find the highest salary in every department.

Step 3: Join with Employees

Match department and salary against the original rows.

Step 4: Return employee details

Return every employee whose salary matches the department maximum.

Why do we join using two conditions?

ON E.Department = M.Department
AND E.Salary = M.HighestSalary
  • The first condition matches the department.
  • The second condition matches the maximum salary.

Both conditions are necessary. Matching only the department would return all employees in that department.

Handling ties: This query returns all employees tied for the highest salary. That is often the correct business behavior.

5. Approach 3 — Using a CTE

A Common Table Expression makes the query easier to read by separating the maximum salary calculation from the final query. 

WITH DepartmentMaxSalary AS
(
    SELECT
        Department,
        MAX(Salary) AS HighestSalary
    FROM Employees
    GROUP BY Department
)
SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary
FROM Employees E
INNER JOIN DepartmentMaxSalary M
    ON E.Department = M.Department
   AND E.Salary = M.HighestSalary
ORDER BY E.Department, E.EmployeeName;

How the CTE works

  1. The CTE calculates the highest salary per department.
  2. The main query joins the CTE to Employees.
  3. The matching employee records are returned.

A CTE is a named query expression, not automatically a materialized temporary result. SQL Server can optimize the overall statement as a single query.

6. Approach 4 — Using DENSE_RANK()

Window functions are especially useful for ranking employees within each department. 

WITH RankedEmployees AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        DENSE_RANK() OVER
        (
            PARTITION BY Department
            ORDER BY Salary DESC
        ) AS SalaryRank
    FROM Employees
)
SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary
FROM RankedEmployees
WHERE SalaryRank = 1
ORDER BY Department, EmployeeName;

Understanding the window function

DENSE_RANK() OVER
(
    PARTITION BY Department
    ORDER BY Salary DESC
)
  • PARTITION BY Department creates a separate ranking group for each department.
  • ORDER BY Salary DESC places the highest salary first.
  • DENSE_RANK() assigns the same rank to employees with equal salaries.
  • WHERE SalaryRank = 1 selects all employees ranked first.

Why DENSE_RANK()? It assigns rank 1 to every employee tied at the highest salary. Therefore, filtering rank 1 returns all top-paid employees.

7. Approach 5 — Using ROW_NUMBER()

Sometimes the requirement is to return exactly one employee per department, even when multiple employees have the same highest salary.

In that case, use ROW_NUMBER() with a deterministic tie-breaking column. 

WITH RankedEmployees AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        ROW_NUMBER() OVER
        (
            PARTITION BY Department
            ORDER BY Salary DESC, EmployeeId ASC
        ) AS RowNum
    FROM Employees
)
SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary
FROM RankedEmployees
WHERE RowNum = 1
ORDER BY Department;

How it works

  • Highest salary receives row number 1.
  • If salaries are tied, the smaller EmployeeId comes first.
  • Only the row numbered 1 is returned for each department.
Important: Without a unique tie-breaker such as EmployeeId, the chosen employee among tied salaries may be nondeterministic.

8. DENSE_RANK vs RANK vs ROW_NUMBER

These functions can all be used to rank employees, but they behave differently when salaries are tied.

Consider this salary data from one department:

Employee Salary
Alice90,000
Jack90,000
Carol80,000
Frank70,000
Employee Salary ROW_NUMBER RANK DENSE_RANK
Alice90,000111
Jack90,000211
Carol80,000332
Frank70,000443
  • ROW_NUMBER(): Gives each row a unique sequential number.
  • RANK(): Gives tied rows the same rank and leaves gaps afterward.
  • DENSE_RANK(): Gives tied rows the same rank without gaps afterward.

For finding all employees with the highest salary, both RANK() and DENSE_RANK() work when filtering rank 1. ROW_NUMBER() returns only one row.

9. Approach 6 — Using CROSS APPLY

SQL Server also supports CROSS APPLY, which can be useful when selecting the top employee or employees for each department.

First, create a separate Departments table so departments exist independently of employee records. 

CREATE TABLE Departments
(
    DepartmentId INT PRIMARY KEY,
    DepartmentName VARCHAR(50)
);

INSERT INTO Departments
    (DepartmentId, DepartmentName)
VALUES
    (1, 'IT'),
    (2, 'HR'),
    (3, 'Finance'),
    (4, 'Marketing');

Return all employees tied for the highest salary

SELECT
    D.DepartmentName,
    T.EmployeeId,
    T.EmployeeName,
    T.Salary
FROM Departments D
CROSS APPLY
(
    SELECT TOP (1) WITH TIES
        E.EmployeeId,
        E.EmployeeName,
        E.Salary
    FROM Employees E
    WHERE E.Department = D.DepartmentName
    ORDER BY E.Salary DESC
) T
ORDER BY D.DepartmentName, T.EmployeeName;

TOP (1) WITH TIES returns the first salary row and all other rows tied on the ORDER BY expression.

Because this is CROSS APPLY, departments without matching employees are excluded.

Include departments without employees

Replace CROSS APPLY with OUTER APPLY to preserve every department, including those without employees. 

SELECT
    D.DepartmentName,
    T.EmployeeId,
    T.EmployeeName,
    T.Salary
FROM Departments D
OUTER APPLY
(
    SELECT TOP (1) WITH TIES
        E.EmployeeId,
        E.EmployeeName,
        E.Salary
    FROM Employees E
    WHERE E.Department = D.DepartmentName
    ORDER BY E.Salary DESC
) T
ORDER BY D.DepartmentName, T.EmployeeName;

Marketing will appear with NULL employee columns because it currently has no employees.

10. Handling NULL Salaries

SQL Server's MAX() ignores NULL values. If a department has salaries 80,000, 60,000 and NULL, the maximum is 80,000.

If every salary in a department is NULL, MAX(Salary) returns NULL. A join using equality will not match NULL to NULL. 

-- NULL does not equal NULL in SQL comparisons.
SELECT
    NULL = NULL AS ComparisonResult;

The result is NULL (UNKNOWN), not TRUE.

If the business rule says employees with NULL salary should be considered only when no non-NULL salary exists, explicitly handle that condition. 

WITH DepartmentMax AS
(
    SELECT
        Department,
        MAX(Salary) AS HighestSalary
    FROM Employees
    GROUP BY Department
)
SELECT
    E.EmployeeId,
    E.EmployeeName,
    E.Department,
    E.Salary
FROM Employees E
INNER JOIN DepartmentMax M
    ON E.Department = M.Department
   AND
   (
       E.Salary = M.HighestSalary
       OR
       (
           E.Salary IS NULL
           AND M.HighestSalary IS NULL
       )
   );
Decide the NULL salary rule with the business team. Treating NULL as the highest salary is usually not appropriate unless the business requirement explicitly says so.

11. SQL Server Internal Processing

The query is declarative: you describe the result you want, and SQL Server's optimizer chooses an execution strategy.

Conceptual processing for the GROUP BY and JOIN approach

1. Read employee rows

SQL Server accesses the required table or index pages.

2. Group by Department

A possible plan operator is Hash Match (Aggregate) or Stream Aggregate.

3. Calculate MAX(Salary)

The aggregate computes one maximum value per department.

4. Join the results

The optimizer may select Nested Loops, Hash Match, or Merge Join.

5. Return matching rows

Rows matching the department and maximum salary are returned.

Possible execution plan operators

Operator Purpose
Index Scan Reads index rows to obtain required data.
Table Scan Reads rows from a heap table.
Stream Aggregate Aggregates rows that arrive in suitable grouping order.
Hash Match (Aggregate) Uses a hash structure to group and aggregate rows.
Hash Match (Join) Joins two inputs using a hash-based strategy.
Sort Orders rows when the required ordering is not already available.
Window Aggregate May be used in plans involving window functions.

These are possible operators, not a guaranteed sequence. The actual plan depends on table size, indexes, statistics, data distribution, query shape and SQL Server's cost estimates.

12. Performance Optimization

1. Create an index for department and salary

CREATE NONCLUSTERED INDEX IX_Employees_Department_Salary
ON Employees
(
    Department,
    Salary DESC
)
INCLUDE
(
    EmployeeId,
    EmployeeName
);

This index can help queries that group or filter by department and need salary information. Included columns may help cover the query and reduce lookups.

2. Consider the query workload

  • Check how frequently the query executes.
  • Check the number of employees and departments.
  • Check whether department values are evenly distributed.
  • Check whether the index is used by the actual execution plan.
  • Consider the write overhead and storage cost of additional indexes.

3. Measure the query

SET STATISTICS IO ON;
SET STATISTICS TIME ON;

-- Run your highest salary query here.

SET STATISTICS IO OFF;
SET STATISTICS TIME OFF;

Review logical reads, CPU time and elapsed time. Also inspect the actual execution plan for expensive operators, spills, unexpected scans, inaccurate row estimates and key lookups.

An index does not guarantee that a query will be faster. Test with representative production-sized data and compare actual plans and measurements.

13. Real-World Scenarios

Scenario 1: Highest-paid employee in every department

An HR dashboard needs to show the highest-paid employee or employees in every department. Use DENSE_RANK() or GROUP BY with JOIN when all tied employees should appear.

Scenario 2: Department salary benchmarking

Finance needs to compare the highest salary across departments. Use GROUP BY with MAX() when only department-level salary values are required.

Scenario 3: One representative employee per department

A report requires exactly one employee per department. Use ROW_NUMBER() with a deterministic tie-breaker, such as EmployeeId.

Scenario 4: Departments without employees

A management report must include every department even when no employees are assigned. Start with the Departments table and use OUTER APPLY or a LEFT JOIN.

14. Common Mistakes

  1. Using MAX() while selecting EmployeeName directly. An aggregate query cannot select an ungrouped employee name without additional logic.
  2. Using ROW_NUMBER() when all ties are required. ROW_NUMBER() returns only one row for rank 1.
  3. Forgetting PARTITION BY. Without partitioning by department, the ranking applies across the whole result set.
  4. Using an incomplete JOIN condition. Match both department and maximum salary.
  5. Ignoring NULL behavior. MAX() ignores NULL values, and equality does not match NULL.
  6. Assuming one execution plan is always best. Different data sizes and distributions can produce different optimal plans.

16. Knowledge Check

Question 1

Which function returns all employees tied for the highest salary per department?

  • A. ROW_NUMBER()
  • B. DENSE_RANK()
  • C. COUNT()
  • D. SUM()

Answer: B. DENSE_RANK()

Question 2

What does PARTITION BY Department do in a window function?

  • A. Sorts all departments alphabetically
  • B. Creates separate ranking groups for each department
  • C. Removes duplicate departments
  • D. Calculates the department count

Answer: B. Creates separate ranking groups for each department.

Question 3

Which query returns exactly one row per department when salaries are tied?

  • A. GROUP BY Department
  • B. DENSE_RANK() = 1
  • C. ROW_NUMBER() = 1 with a tie-breaker
  • D. MAX() without GROUP BY

Answer: C. ROW_NUMBER() = 1 with a tie-breaker.

Question 4

What happens when every salary in a department is NULL?

  • A. MAX() returns 0
  • B. MAX() returns NULL
  • C. MAX() returns an error
  • D. MAX() returns the first row

Answer: B. MAX() returns NULL.

  • Calculate the highest salary in each department using MAX().
  • Retrieve complete employee details using JOIN.
  • Use CTEs to structure aggregate queries.
  • Use DENSE_RANK() to return all tied highest-paid employees.
  • Use ROW_NUMBER() to return exactly one employee per department.
  • Understand the differences between ranking functions.
