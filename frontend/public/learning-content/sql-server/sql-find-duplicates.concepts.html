THE IDEA

What is it?

A duplicate is a repeated business key, not necessarily a byte-for-byte identical database row. The key might be a normalized email, external reference, or composite of several columns.

WHY IT MATTERS

What problem does it solve?

Reliable duplicate detection requires agreeing on equality rules, including case, whitespace, collation, NULL behavior, and which columns define one logical entity.

UNDER THE HOOD

How does it work?

GROUP BY the business key and use HAVING COUNT(*) > 1 to find duplicate key groups. Join those keys back to the source to inspect all candidate rows before any cleanup.

KEY TAKEAWAYS

Remember

  • Duplicate detection starts with domain identity, not SQL syntax.
  • GROUP BY with HAVING COUNT(*) > 1 finds repeated key groups.
  • Inspect candidate rows and foreign-key dependencies before cleanup.
  • Prevent recurrence with an appropriate unique constraint or index after remediation.
