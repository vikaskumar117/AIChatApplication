APPLY THE IDEA

Worked example

Stage a filtered customer set used by several statements and add an index when its cardinality makes reuse valuable.

  1. Estimate row count, lifetime, number of references, and required indexes.
  2. Start with a CTE for a one-statement readable expression.
  3. Materialize to #temp if reuse or statistics/indexes improve measured plans.
  4. Test table variables only for bounded inputs on the deployed SQL Server version.

CODE OR QUERY

Try it

-- CTE: readable expression scoped to the next statement.
;WITH Active AS (
  SELECT CustomerId, RegionId FROM dbo.Customer WHERE IsActive = 1
)
SELECT RegionId, COUNT_BIG(*) FROM Active GROUP BY RegionId;

-- #temp: materialized, reusable intermediate result; evaluate indexing.
SELECT CustomerId, RegionId INTO #Active
FROM dbo.Customer WHERE IsActive = 1;
CREATE INDEX IX_Active_Region ON #Active(RegionId);
SELECT RegionId, COUNT_BIG(*) FROM #Active GROUP BY RegionId;
DROP TABLE #Active;

TRADE-OFFS

Benefits and limitations

Benefits

  • CTEs make a single relational expression readable.
  • #temp tables enable reuse and statistics/index choices for complex workflows.

Limitations

  • CTEs may be inlined/re-evaluated in a plan and do not imply storage.
  • Temp tables use tempdb and add writes, lifecycle, and compilation considerations; table-variable estimates can be poor for some workloads.

DECISION GUIDE

When to use it

Use: Use CTE for one-statement decomposition; #temp for measured multi-step reuse or cardinality-sensitive work; table variables for small predictable scoped sets.

Avoid: Avoid assuming a CTE caches rows or a table variable is always faster or memory-only. Do not choose based on folklore without representative plans.

COMMON MISTAKES

Watch out

  • Expecting a repeated CTE reference to run once and cache results.
  • Assuming table variables are always in memory or always outperform temp tables.
  • Ignoring tempdb and compilation costs when materializing.

BEST PRACTICES

In practice

  • Choose the narrowest lifetime and scope that fits the workflow.
  • Compare actual versus estimated rows and spills.
  • Include data volume and SQL Server version in performance tests.

INTERVIEW PRACTICE

Common questions

SENIOR-LEVEL SCENARIO

Production thinking

A report reuses an intermediate million-row customer set and spills repeatedly. Compare a CTE, #temp table with an appropriate index, and the original plan using actual rows, tempdb activity, and end-to-end latency.

SUMMARY

In one minute

A CTE names a query expression for one following statement; #temp tables are session-scoped tempdb tables; table variables are variables backed by tempdb with table-like structure and narrower scope. Choice affects reuse, statistics, indexes, compilation, scope, and plan quality. A CTE is not inherently a materialized cache, and a table variable is not guaranteed to stay in memory.
