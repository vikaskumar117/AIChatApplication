ROW_NUMBER() vs RANK() vs DENSE_RANK() in SQL Server

Learn how SQL Server assigns rankings to rows, handles duplicate values, partitions data, and uses window functions to solve practical business problems such as Top-N reports, employee rankings, and salary analysis.

1. What Are Ranking Functions?

Ranking functions are SQL Server window functions that assign a numerical position to rows based on an ORDER BY expression. They can rank rows across an entire result set or independently within groups using PARTITION BY.

SQL Server provides four ranking functions:

  • ROW_NUMBER(): Assigns a unique sequential number to every row.
  • RANK(): Assigns the same rank to tied rows and leaves gaps after ties.
  • DENSE_RANK(): Assigns the same rank to tied rows without leaving gaps.
  • NTILE(): Divides rows into approximately equal groups.
Important: Ranking functions do not physically sort or permanently change the underlying table. They calculate ranking values in the query result according to the window's ORDER BY clause.

3. ROW_NUMBER() — Unique Sequential Number

ROW_NUMBER() assigns a different sequential number to every row, even when multiple rows have the same salary. 

SELECT
    EmployeeId,
    EmployeeName,
    Salary,
    ROW_NUMBER() OVER
    (
        ORDER BY Salary DESC, EmployeeId
    ) AS RowNum
FROM Employees
WHERE Department = 'IT';

Expected result

EmployeeSalaryRowNum
Alice90,0001
Bob80,0002
Carol80,0003
David70,0004
Emma60,0005

Bob and Carol have the same salary, but they receive different row numbers. EmployeeId is included as a tie-breaker so the ordering is deterministic for this data.

Use ROW_NUMBER() when: You need exactly one row per position, deduplication, pagination, or a fixed number of records from an ordered result.

4. RANK() — Same Rank for Ties, With Gaps

RANK() gives the same rank to rows with equal values. The next rank accounts for the number of tied rows, so gaps appear. 

SELECT
    EmployeeId,
    EmployeeName,
    Salary,
    RANK() OVER
    (
        ORDER BY Salary DESC
    ) AS SalaryRank
FROM Employees
WHERE Department = 'IT';

Expected result

EmployeeSalaryRank
Alice90,0001
Bob80,0002
Carol80,0002
David70,0004
Emma60,0005

Bob and Carol both receive rank 2. David receives rank 4 because two employees occupy the second position.

Use RANK() when: You want competition-style ranking, where tied participants share a position and subsequent positions are skipped.

5. DENSE_RANK() — Same Rank for Ties, Without Gaps

DENSE_RANK() also assigns the same rank to tied rows, but the next distinct value receives the next consecutive rank. 

SELECT
    EmployeeId,
    EmployeeName,
    Salary,
    DENSE_RANK() OVER
    (
        ORDER BY Salary DESC
    ) AS DenseSalaryRank
FROM Employees
WHERE Department = 'IT';

Expected result

EmployeeSalaryDense Rank
Alice90,0001
Bob80,0002
Carol80,0002
David70,0003
Emma60,0004
Use DENSE_RANK() when: You want to rank distinct values without gaps, such as finding the second-highest distinct salary or the top three salary levels.

7. PARTITION BY — Rank Independently Within Each Department

PARTITION BY divides the result set into groups. The ranking function starts again from 1 for every department. 

SELECT
    EmployeeName,
    Department,
    Salary,

    ROW_NUMBER() OVER
    (
        PARTITION BY Department
        ORDER BY Salary DESC, EmployeeId
    ) AS DepartmentRowNumber,

    RANK() OVER
    (
        PARTITION BY Department
        ORDER BY Salary DESC
    ) AS DepartmentRank,

    DENSE_RANK() OVER
    (
        PARTITION BY Department
        ORDER BY Salary DESC
    ) AS DepartmentDenseRank

FROM Employees
ORDER BY Department, Salary DESC, EmployeeId;

Notice that the ranking restarts for Finance, HR, and IT. In HR, Frank and Grace tie at rank 1. Henry receives rank 3 with RANK(), but rank 2 with DENSE_RANK().

8. NTILE() — Divide Rows Into Groups

NTILE(n) distributes ordered rows into n groups, with group sizes differing by at most one row when possible. It is useful for quartiles, performance bands, and segmentation. 

SELECT
    EmployeeName,
    Salary,
    NTILE(4) OVER
    (
        ORDER BY Salary DESC, EmployeeId
    ) AS SalaryQuartile
FROM Employees;

With ten rows and four groups, SQL Server distributes the rows into group sizes of 3, 3, 2, and 2, in that order. NTILE() assigns groups based on row positions, not distinct salary values. Employees with tied salaries can therefore be placed in different groups.

9. Real-World Example — Find the Top Three Employees Per Department

Requirement: Return the three highest-paid employees from every department, including employees tied at the third position.

Option A: Include ties at the third position

WITH RankedEmployees AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        RANK() OVER
        (
            PARTITION BY Department
            ORDER BY Salary DESC
        ) AS SalaryRank
    FROM Employees
)
SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary,
    SalaryRank
FROM RankedEmployees
WHERE SalaryRank <= 3
ORDER BY Department, Salary DESC;

RANK() includes all employees tied at a rank of 3 or better. However, because RANK() leaves gaps, it does not mean the first three distinct salary levels.

Option B: Top three distinct salary levels

WITH RankedEmployees AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        DENSE_RANK() OVER
        (
            PARTITION BY Department
            ORDER BY Salary DESC
        ) AS SalaryLevel
    FROM Employees
)
SELECT *
FROM RankedEmployees
WHERE SalaryLevel <= 3
ORDER BY Department, Salary DESC;

DENSE_RANK() returns every employee whose salary belongs to one of the top three distinct salary levels in that department.

Option C: Exactly three employees per department

WITH RankedEmployees AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        ROW_NUMBER() OVER
        (
            PARTITION BY Department
            ORDER BY Salary DESC, EmployeeId
        ) AS RowNum
    FROM Employees
)
SELECT *
FROM RankedEmployees
WHERE RowNum <= 3
ORDER BY Department, Salary DESC;

ROW_NUMBER() returns no more than three rows per department. When salaries tie, EmployeeId provides a consistent tie-breaker.

10. Find the Second-Highest Distinct Salary

DENSE_RANK() is a natural choice when the requirement is the second-highest distinct salary. 

WITH SalaryRanking AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Salary,
        DENSE_RANK() OVER
        (
            ORDER BY Salary DESC
        ) AS SalaryRank
    FROM Employees
)
SELECT
    EmployeeId,
    EmployeeName,
    Salary
FROM SalaryRanking
WHERE SalaryRank = 2;

All employees who earn the second-highest distinct salary are returned. If the business requirement instead asks for the second employee row, ROW_NUMBER() may be more appropriate.

11. Remove Duplicate Rows Using ROW_NUMBER()

A common production use case is identifying duplicate business keys and retaining one preferred record. 

WITH DuplicateCheck AS
(
    SELECT
        EmployeeId,
        EmployeeName,
        Department,
        Salary,
        ROW_NUMBER() OVER
        (
            PARTITION BY EmployeeName, Department
            ORDER BY EmployeeId
        ) AS DuplicateNumber
    FROM Employees
)
SELECT *
FROM DuplicateCheck
WHERE DuplicateNumber > 1;

The query identifies rows after the first occurrence for each EmployeeName and Department combination. The ORDER BY clause determines which record is retained.

Production warning: Preview the rows before deleting them. Confirm the business key, retention rule, foreign-key dependencies, and transaction strategy before running a DELETE.

12. Logical Processing and Important SQL Rules

Ranking functions are evaluated as part of the SELECT processing stage, after the rows to be ranked have been filtered by the FROM, JOIN, and WHERE operations.

FROM and JOIN — build the input row set
WHERE — filter input rows
GROUP BY and HAVING — aggregate and filter groups, when present
SELECT — calculate ranking window functions
ORDER BY — arrange final output

Why can't you filter a ranking alias in WHERE?

This query is invalid:

SELECT
    EmployeeName,
    Salary,
    ROW_NUMBER() OVER
    (
        ORDER BY Salary DESC
    ) AS RowNum
FROM Employees
WHERE RowNum <= 3;

WHERE is logically processed before SELECT calculates the RowNum alias. Use a CTE or derived table instead. 

WITH Ranked AS
(
    SELECT
        EmployeeName,
        Salary,
        ROW_NUMBER() OVER
        (
            ORDER BY Salary DESC
        ) AS RowNum
    FROM Employees
)
SELECT *
FROM Ranked
WHERE RowNum <= 3;

13. SQL Server Internals — How Ranking Is Executed

Ranking functions are logical expressions. SQL Server's optimizer chooses physical operators to produce the required ordering and calculate the window values.

1. Access input rows

SQL Server may read a table or use an index through an Index Scan, Index Seek, or another access operator.

2. Establish required ordering

If the input is not already in a suitable order, the execution plan may use a Sort operator.

3. Calculate window values

Depending on the plan and SQL Server version, operators such as Segment, Sequence Project, or Window Aggregate may be used to calculate ranking values.

4. Apply outer filtering

When the ranking is calculated in a CTE or derived table, a Filter operator can retain only the required ranks.

5. Return final output

A final Sort may be required if the outer ORDER BY requests an order not already guaranteed by the plan.

The exact physical operators depend on the SQL Server version, query shape, available indexes, estimated costs, cardinality estimates, and execution plan choices. No single operator sequence is guaranteed for every ranking query.

14. Execution Plan and Performance Testing

Test ranking queries with actual execution plans and runtime measurements rather than assuming that one ranking function is always faster than another. 

SET STATISTICS IO ON;
SET STATISTICS TIME ON;

SELECT
    EmployeeId,
    EmployeeName,
    Department,
    Salary,
    ROW_NUMBER() OVER
    (
        PARTITION BY Department
        ORDER BY Salary DESC, EmployeeId
    ) AS RowNum
FROM Employees;

SET STATISTICS IO OFF;
SET STATISTICS TIME OFF;

Execution plan areas to inspect

  • Sort: Check whether SQL Server sorts a large input and whether the sort spills to tempdb.
  • Index Scan or Seek: Understand how the rows are accessed.
  • Memory grant: Review memory requested and used by sort or other operators.
  • Spills: Investigate sort or window-related spills when present.
  • Estimated vs actual rows: Large differences can indicate cardinality-estimation problems.
  • Parallelism: Check whether parallel operators help or introduce additional exchanges and sorting.

15. Indexing for Ranking Queries

If a query frequently ranks employees by department and salary, an index aligned with the partition and ordering columns may reduce sorting work. 

CREATE NONCLUSTERED INDEX IX_Employees_Department_Salary
ON Employees
(
    Department,
    Salary DESC,
    EmployeeId
)
INCLUDE
(
    EmployeeName
);

This index may help queries that partition by Department and order by Salary and EmployeeId. It can also cover the selected columns in this example.

Do not create an index automatically for every ranking query. Consider write overhead, storage, index maintenance, existing indexes, data distribution, and the wider workload. Validate improvements using actual execution plans and measurements.

16. Common Mistakes

  • Using ROW_NUMBER() when ties must be included: It gives every row a unique number, so tied rows may be separated.
  • Using RANK() for the top three distinct values: Gaps can mean the third distinct value has a rank greater than 3. Use DENSE_RANK().
  • Forgetting PARTITION BY: Without it, ranking is calculated across the entire input set.
  • Using a non-deterministic tie order: Add a unique tie-breaker when exactly repeatable row numbering is required.
  • Filtering the ranking alias in the same WHERE clause: Use a CTE or derived table.
  • Confusing window ORDER BY with final ORDER BY: The window ORDER BY defines ranking; the outer ORDER BY defines display order.
  • Assuming NTILE keeps equal values together: It divides rows by position, so ties may be split across groups.

19. Knowledge Check

Question 1

Which function assigns a unique number to every row?

A. RANK()   B. DENSE_RANK()   C. ROW_NUMBER()   D. NTILE()

Answer: C. ROW_NUMBER()

Question 2

Two employees tie at rank 2. What rank does the next employee receive with RANK()?

A. 2   B. 3   C. 4   D. 5

Answer: C. 4

Question 3

Which function ranks distinct salary values without gaps?

A. ROW_NUMBER()   B. RANK()   C. DENSE_RANK()   D. NTILE()

Answer: C. DENSE_RANK()

Question 4

What does PARTITION BY Department do?

A. Sorts the table permanently

B. Restarts ranking for each department

C. Removes duplicate departments

D. Groups rows into one aggregate row

Answer: B. Restarts ranking for each department

Question 5

Why is a CTE commonly used when filtering ROW_NUMBER()?

A. Ranking functions can only run inside CTEs

B. A CTE makes the ranking permanently stored

C. It allows the outer query to filter the calculated ranking value

D. It automatically creates an index

Answer: C. It allows the outer query to filter the calculated ranking value
