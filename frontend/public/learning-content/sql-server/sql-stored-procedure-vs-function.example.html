APPLY THE IDEA

Worked example

A transfer command belongs in a stored procedure; a reusable filtered customer rowset may be an inline table-valued function.

  1. Determine whether the caller needs a command or a composable value.
  2. Choose result contract and side-effect requirements.
  3. Account for SQL Server function restrictions and inline versus multi-statement form.
  4. Benchmark the calling query and document database code ownership.

CODE OR QUERY

Try it

CREATE OR ALTER PROCEDURE dbo.GetDepartmentEmployees
  @DepartmentId int
AS
BEGIN
  SET NOCOUNT ON;
  SELECT EmployeeId, Name
  FROM dbo.Employee
  WHERE DepartmentId = @DepartmentId;
END;

-- Inline TVF is composable as a table expression.
CREATE OR ALTER FUNCTION dbo.EmployeesInDepartment(@DepartmentId int)
RETURNS TABLE
AS
RETURN (
  SELECT EmployeeId, Name
  FROM dbo.Employee
  WHERE DepartmentId = @DepartmentId
);

TRADE-OFFS

Benefits and limitations

Benefits

  • Procedures expose command-oriented behavior and multiple output channels.
  • Inline TVFs can compose relational logic into a caller query.

Limitations

  • Database routines introduce deployment/versioning and ownership boundaries.
  • Function restrictions and scalar/multi-statement function performance vary by form and engine version.

DECISION GUIDE

When to use it

Use: Use procedures for database commands and explicit operational APIs; use inline TVFs when composable set logic is useful and measured.

Avoid: Avoid placing all business logic in opaque database code or assuming every function is inlined and equally performant.

COMMON MISTAKES

Watch out

  • Trying to call a procedure as if it were a scalar expression.
  • Assuming every function can modify arbitrary database state.
  • Assuming stored procedures are inherently faster than parameterized queries.

BEST PRACTICES

In practice

  • Use parameterized calls and explicit contracts.
  • Keep database routines versioned with the application schema.
  • Inspect actual plans for functions in real calling queries.
  • Grant least privilege and avoid dynamic SQL unless identifiers are safely validated.

SENIOR-LEVEL SCENARIO

Production thinking

Several reports duplicate a department filter while a write workflow needs atomic multi-step behavior. Expose read logic through a measured inline TVF if composition helps, and keep the write workflow in a procedure or application transaction with clear ownership.

SUMMARY

In one minute

A stored procedure is an executable database routine that can accept parameters, return result sets/output parameters, and perform data modifications. A function returns a scalar or table value and is designed to participate in expressions or FROM clauses, subject to SQL Server function restrictions. The choice affects composability, side effects, result shape, permissions, and optimizer visibility. It is not simply “procedure is faster” or “function is reusable.”
