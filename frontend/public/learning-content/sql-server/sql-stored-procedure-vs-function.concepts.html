THE IDEA

What is it?

A stored procedure is an executable database routine that can accept parameters, return result sets/output parameters, and perform data modifications. A function returns a scalar or table value and is designed to participate in expressions or FROM clauses, subject to SQL Server function restrictions.

WHY IT MATTERS

What problem does it solve?

The choice affects composability, side effects, result shape, permissions, and optimizer visibility. It is not simply “procedure is faster” or “function is reusable.”

UNDER THE HOOD

How does it work?

Use procedures for command/workflow boundaries, transactional operations, and multiple result sets. Use inline table-valued functions for composable relational logic where appropriate; scalar and multi-statement functions have distinct optimizer/performance characteristics that require version-aware measurement.

KEY TAKEAWAYS

Remember

  • Procedures are command routines; functions return values usable in expressions or table contexts.
  • Procedures can return multiple result sets; functions have stricter side-effect rules.
  • Inline and multi-statement table-valued functions have different optimization behavior.
  • Choose based on composition, transaction boundary, ownership, and measured performance.
