APPLY THE IDEA

Worked example

A link service handles 100 writes/second and 10,000 redirects/second. Keep the mapping store authoritative, cache hot codes, reserve keys transactionally, and decouple click analytics so an analytics outage does not block redirects.

  1. Normalize and validate the submitted URL before storing it.
  2. Insert the code under a unique constraint; generate another code on conflict.
  3. Resolve redirect from cache or the indexed mapping table.
  4. Publish click analytics asynchronously and tolerate duplicate events.

CODE OR QUERY

Try it

POST /links { "url": "https://example.com/article" }
  -> validate scheme/domain policy
  -> generate unique code; retry on unique-key conflict
  -> persist(code, destination, owner, expiresAt)
  -> return https://sho.rt/{code}

GET /{code}
  -> cache lookup -> store on miss -> apply expiry/safety
  -> redirect; emit click event asynchronously

TRADE-OFFS

Benefits and limitations

Benefits

  • Read path can be fast with cache and compact indexed key lookup
  • Analytics and creation can scale independently

Limitations

  • Hot links create cache/key hotspots
  • Redirect safety, privacy, abuse, and analytics retention add operational complexity

DECISION GUIDE

When to use it

Use: Use when durable links, ownership, expiry, and measurable redirect behavior are clear requirements.

Avoid: Avoid inventing a globally distributed design before traffic, availability, and data residency needs justify it.

COMMON MISTAKES

Watch out

  • Assuming random code generation cannot collide.
  • Allowing arbitrary untrusted destinations without abuse controls.
  • Making analytics synchronous and turning its outage into redirect failure.

BEST PRACTICES

In practice

  • Use idempotent creation where clients may retry.
  • Protect hot keys and bound analytics backlog.
  • Choose redirect status and caching policy from product semantics.

INTERVIEW PRACTICE

Common questions

  1. How do you prevent short-code collisions?
  2. What is the difference between 301 and 302 redirects?
  3. What should happen if analytics is unavailable?
  4. How do you prevent the service from becoming a malicious redirector?

SENIOR-LEVEL SCENARIO

Production thinking

A marketing campaign creates a hot link and millions of redirect requests while a user submits a phishing destination. Apply URL policy and reputation controls at creation, rate-limit abusive clients, cache the hot mapping safely, and send analytics through a bounded queue.

SUMMARY

In one minute

A URL shortener is a read-heavy key-to-URL system; unique persistence, safe destinations, caching, and decoupled analytics are its core decisions.
