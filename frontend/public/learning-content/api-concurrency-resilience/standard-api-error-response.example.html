APPLY THE IDEA

Worked example

A validation response provides field-level errors and a trace ID; the client displays corrections while support can find the correlated log entry.

  1. Failure is classified
  2. Problem document is constructed safely
  3. Client acts on type, status, and trace context

CODE OR QUERY

Try it

return Results.Problem(
    type: "https://api.example/problems/order-conflict",
    title: "Order cannot be updated",
    statusCode: StatusCodes.Status409Conflict,
    extensions: new Dictionary<string, object?>
    {
        ["traceId"] = Activity.Current?.TraceId.ToString()
    });

TRADE-OFFS

Benefits and limitations

Benefits

  • Consistent client parsing across endpoints
  • Safe trace correlation improves supportability

Limitations

  • Clients can become coupled to unstable prose or implementation codes
  • Overly detailed errors can leak sensitive state

DECISION GUIDE

When to use it

Use: Use stable problem types and validation extensions with well-defined client recovery semantics.

Avoid: Avoid returning raw exceptions, SQL messages, stack traces, access tokens, or arbitrary database fields.

COMMON MISTAKES

Watch out

  • Exposing exception.Message or stack traces as detail.
  • Changing a stable error code while keeping the same prose and expecting clients to recover.

BEST PRACTICES

In practice

  • Use RFC 9457 Problem Details and a documented validation shape.
  • Localize user-facing prose in clients while treating server problem types as stable identifiers.

INTERVIEW PRACTICE

Common questions

  1. Which fields are defined by Problem Details?
  2. Why should clients rely on problem type/code rather than title prose?
  3. How can a trace ID help without leaking internals?

SENIOR-LEVEL SCENARIO

Production thinking

An SDK parses inconsistent ad hoc error JSON; standardize on Problem Details, preserve status semantics, and add contract tests for validation, conflict, and server failures.

SUMMARY

In one minute

A standard error body gives clients stable machine-readable classification without exposing internal implementation details.
