APPLY THE IDEA

Worked example

Use optimistic tokens for product-description edits; use a short database transaction for a scarce inventory allocation when atomic conditional decrement is not sufficient.

  1. Select concurrency strategy
  2. Perform conditional write or acquire lock
  3. Commit, detect conflict, or release lock

CODE OR QUERY

Try it

// Optimistic EF Core token:
modelBuilder.Entity<Product>()
    .Property(p => p.Version)
    .IsRowVersion();

TRADE-OFFS

Benefits and limitations

Benefits

  • Optimistic updates offer high concurrency with little blocking
  • Pessimistic locking can serialize truly exclusive short operations

Limitations

  • Optimistic conflicts require merge or retry policy
  • Locks can block, reduce throughput, and deadlock

DECISION GUIDE

When to use it

Use: Prefer optimistic checks for typical web edits and use short, explicit locks only when contention and invariant analysis justify them.

Avoid: Avoid holding database locks while waiting for users, networks, or external payment providers.

COMMON MISTAKES

Watch out

  • Retrying non-idempotent external effects after a database conflict.
  • Assuming higher isolation always improves correctness without throughput cost.

BEST PRACTICES

In practice

  • Instrument conflicts, wait time, and deadlocks before tuning.
  • Keep external calls outside locked transactions and use an outbox where needed.

INTERVIEW PRACTICE

Common questions

  1. How does optimistic concurrency detect conflict?

SENIOR-LEVEL SCENARIO

Production thinking

A shipment allocation workflow has high contention; compare atomic conditional updates, optimistic retries, and short transactions under representative load before choosing a locking policy.

SUMMARY

In one minute

Optimistic concurrency detects a conflict when committing; pessimistic concurrency acquires a lock to exclude competing work.
