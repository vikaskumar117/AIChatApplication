APPLY THE IDEA

Worked example

Two support agents edit a customer address; the second save reports a conflict rather than silently erasing the first agent’s changes.

  1. Editor A and B load same version
  2. A commits a change
  3. B submits stale version and conflict is detected

CODE OR QUERY

Try it

// Update only if the submitted version is still current.
var affected = await db.Customers
    .Where(c => c.Id == id && c.Version == request.Version)
    .ExecuteUpdateAsync(setters => setters
        .SetProperty(c => c.Address, request.Address), ct);
return affected == 0 ? Conflict() : NoContent();

TRADE-OFFS

Benefits and limitations

Benefits

  • Protects user intent and exposes stale work
  • Allows deliberate reload, merge, or conflict resolution

Limitations

  • Users may need to resolve conflicts
  • Version tokens and client contracts require coordination

DECISION GUIDE

When to use it

Use: Use conflict detection for collaborative or long-lived edits where overwriting another user’s work is unacceptable.

Avoid: Avoid last-write-wins unless the data and product explicitly accept discarded updates.

COMMON MISTAKES

Watch out

  • Checking a version in application memory and saving later without a conditional write.
  • Automatically merging fields without understanding business meaning.

BEST PRACTICES

In practice

  • Include an opaque version or ETag in editable representations.
  • Test simultaneous updates and verify that no successful write is silently lost.

INTERVIEW PRACTICE

Common questions

SENIOR-LEVEL SCENARIO

Production thinking

An editor submits a form open for twenty minutes while another agent changed the record; return the current representation/version safely and offer a user-reviewed merge.

SUMMARY

In one minute

A lost update occurs when a later save overwrites changes made after the editor loaded its original copy.
