APPLY THE IDEA

Worked example

Two shoppers read stock quantity 1; each tries to reserve the final item, so a conditional update must ensure only one reservation succeeds.

  1. Actors read shared state
  2. Operations overlap in time
  3. Persistence policy preserves invariant or detects conflict

CODE OR QUERY

Try it

var changed = await db.Products
    .Where(p => p.Id == id && p.AvailableQuantity > 0)
    .ExecuteUpdateAsync(setters => setters
        .SetProperty(p => p.AvailableQuantity, p => p.AvailableQuantity - 1), ct);
if (changed == 0) return Conflict();

TRADE-OFFS

Benefits and limitations

Benefits

  • Explicit concurrency policy preserves business invariants
  • Conflict detection gives clients a safe recovery path

Limitations

  • Coordination adds storage and application complexity
  • Overly broad locking can reduce throughput and cause deadlocks

DECISION GUIDE

When to use it

Use: Identify the invariant at risk and choose the narrowest database-supported mechanism that protects it.

Avoid: Avoid assuming that a request-scoped DbContext or transaction automatically prevents every lost update.

COMMON MISTAKES

Watch out

  • Assuming application-level validation remains true at write time.
  • Using locks across network calls or long user interactions.

BEST PRACTICES

In practice

  • Document invariants and identify race windows explicitly.
  • Use constraints, atomic operations, or version checks and test simultaneous requests.

INTERVIEW PRACTICE

Common questions

  1. What is a lost update?
  2. Why is a read followed by a write unsafe under concurrency?

SENIOR-LEVEL SCENARIO

Production thinking

Flash-sale requests oversell the last items; encode inventory availability in an atomic conditional database operation and observe contention under load.

SUMMARY

In one minute

Data concurrency is the behavior of overlapping operations that read or change shared state.
